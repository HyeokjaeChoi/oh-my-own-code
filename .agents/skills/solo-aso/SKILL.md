# App store optimization

Use the supplied run ID and read its plan, product brief, implemented capabilities, analytics evidence, and prior listing results. Check run status; do not begin or finish a run. Screenshot capture and visual export belong to `solo-store-launch`.

Read [references/aso-evidence.md](references/aso-evidence.md) for metadata and evidence requirements. Establish the store, country/locale, app version, audience, user problem, primary benefit, and current listing. Verify current official field limits and experiment capabilities before finalizing provider-specific output.

Write clear benefit-led copy supported by the working product. Distinguish search-intent and keyword hypotheses from measured rank, volume, conversion, or experiment evidence. Localize meaning and store vocabulary instead of translating word for word. Prefer Apple and Google native listing experiments before recommending another subscription.

When writing a durable ASO brief or metadata file, use `docs/growth/aso.md` or the project's convention and return its path to the coordinator for harness registration. Return copy by exact field, keyword evidence and uncertainty, localization notes, experiment proposal, and missing product proof to the planner.
