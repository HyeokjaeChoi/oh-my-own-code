# Store launch assets

Use the supplied run ID, its plan, the implemented product, approved design direction, and approved ASO copy. Check run status; do not begin or finish the run. Keyword research and store metadata belong to `solo-aso`.

Read [references/store-assets.md](references/store-assets.md) before capture, composition, localization, or export. Establish the store, locale, app version/build, target device classes, exact current store requirements, and source captures.

Use real captures with intentional demo data for product screenshots. Generated or reconstructed product UI may illustrate a concept but must be labelled as a mockup and cannot prove shipped behavior. AppLaunchFlow may compose and export assets when a working connection exists; otherwise use available project-native tools and produce an exact storyboard and manifest. Verify generated files rather than treating an issued export command as success.

When writing assets or manifests, return each durable artifact and applicable dimension/content checks to the coordinator for harness registration. Return ready asset paths, locale/device/order manifest, source build and capture provenance, licenses for external materials, and specific missing or unverified items to the planner.
