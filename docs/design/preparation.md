# 디자인 준비 상태

2026-09-26 · oh-my-own-code · 신규 시스템 제작

통합 스펙 v0.1과 **로컬 브라우저 앱** 방향은 승인되었다. 정확한 대상은 [승인 기록](../runs/technical-feasibility/spec-approval.json)에 고정했다. 기존 스펙 파일의 “사용자 승인 전” 표기는 승인 당시의 스냅샷이며, 이 기록이 그 상태를 갱신한다. 승인된 원문과 해시는 수정하지 않는다.

## 확인한 것

- Figma 인증, 전용 프로젝트 폴더 내 배치, 실제 파일 읽기·편집과 컴포넌트 렌더를 확인했다. Library 게시와 실제 앱 런타임 검증은 별도다.
- 신규 [디자인 시스템](system.md)에 3계층 토큰 163개, Light/Dark, 한글·코드 글꼴과 6개 계열의 44개 상태를 정의하고 Figma에 반영했다.
- 제품은 개인이 실제 프로젝트를 운영하면서 에이전트·도구·권한·검증 흐름을 이해하는 작업대다. 대화는 assistant-ui, 구조화된 도구 표현은 tool-ui를 사용한다.
- 화면 동작의 기준은 승인된 [UX 스펙](specs/workbench-ux.md)이다. 이전 MealTicket의 디자인 방향은 이 제품에 자동 적용하지 않는다.

## 확정된 디자인 작업

사용자가 “새 디자인 시스템 & 파일로 진행. 별도 프로젝트로 진행”을 선택했다. 전용 [oh-my-own-code 프로젝트 폴더](https://www.figma.com/files/team/1682045324479940459/folder/660860312)와 [새 디자인 시스템 파일](https://www.figma.com/design/e6QYqEsmA3FHB6A2ohNr2o)을 생성했고, 폴더 내 파일 표시와 실제 파일 읽기를 확인했다. 접근 범위는 초대된 사용자로 제한했으며 다른 사람을 초대하지 않았다. 라이브러리 게시·공개 공유·유료 변경은 수행하지 않았다.

토큰 값은 저장소를 원본으로 삼고 Figma 변수와 CSS에 반영한다. 한글용 Noto Sans KR과 코드용 IBM Plex Mono의 실제 제공 스타일을 확인했다. 변수·타입 스타일·컴포넌트와 안내 페이지를 제작했다. [캡처와 검증 범위](../runs/design-foundation/visual-evidence.json), [실행 기록](../runs/design-foundation/plan.md), [파일 연결 정보](figma-source.json)를 보관한다. 최종 독립 리뷰와 완료 상태는 실행 장부를 따른다.

## 다음 디자인 작업에 넘길 범위

다음 항목은 새 스펙이나 확정된 시각 디자인이 아니라, 기존 UX 계약을 제작할 때 사용할 작업 묶음이다.

1. **기본 작업대:** 프로젝트/작업 목록, 중앙 대화, 우측 프리뷰·파일·변경 내용·터미널.
2. **실행 이해:** 계획과 승인 버전, 자식 에이전트, 도구 호출, 요청/유효/관측 상태, 근거가 연결된 타임라인.
3. **사용자 개입:** 권한 요청·변경, 작업 중단, 오류·누락·복구, 삭제 대상 확인.
4. **설정과 반복 사용:** 명령 검색, 구성요소 검사·편집 상태, 키보드 이동, 알림과 로컬 예약 실행 상태.

신규 시스템은 primitive → semantic → component 토큰, 한글 타이포그래피, 레이아웃, 상호작용 상태, 모션/감소 모션, 포커스와 대비를 정의했다. 저장소에서 Figma/CSS로 단방향 반영한다. 디자인 계약의 독립 검토를 통과한 원본을 사용하며, Figma 화면 검토와 실제 실행 화면 검수는 별개다.

## 병행 가능한 기술 작업

[기술 검증 계획](../runs/technical-feasibility/plan.md)의 S-01/S-07 패키지 타입과 합성 렌더 조사는 완료했다. 실제 host·인증·권한·스트림 연결 검증은 남아 있다. 패키지 타입/렌더 통과는 제품 UI의 사용성·접근성·E2E 통과를 의미하지 않는다.
