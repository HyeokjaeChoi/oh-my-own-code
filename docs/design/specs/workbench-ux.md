# 개인 에이전트 워크벤치 UX 계약

**v0.6 · 2026-09-28 · Electron macOS/Windows + app-owned sidecar · review required**

기준: 승인된 PRD의 기능·상호작용 계약과 PRD v0.6 Electron desktop amendment(독립 검토 대기), [desktop bootstrap 계획 revision 18](../../workplans/desktop-app-bootstrap/plan.md); domain-specs 계획은 역사적 입력이며 현재 승인 근거가 아님
[승인 대상 해시](../../engineering/spec-index.md)는 통합 스펙 인덱스와 현재 실행 계약이 소유한다. [기술 문서 조사](../../research/workbench-expansion.md). 이 문서는 F-01~18의 화면·상호작용 계약이다. SDK 작동, 화면 구현, Figma 파일
확인 또는 접근성 검증 결과를 주장하지 않는다.

## 제품 경험의 중심

사용자는 실제 프로젝트를 작업하면서 **무엇을 요청했는지, 어떤 경로와 권한에서 누가 실행했는지, 실제로 무엇이 확인되었는지**를 한 흐름에서 이해한다. 평상시에는 작업을 빠르게 이어가고, 경로 변경·외부 전송·권한 확대·삭제처럼 영향이 큰 순간에는 대상과 효과를 분명히 본다. 학습용 관찰은 실제 작업을 가리지 않는다.
합성 학습 모드는 같은 실행 기록의 설명 방식이며 제품을 데모 뷰어로 줄이지 않는다.

한 명이 쓰는 한국어 로컬 제품을 기준으로 하되 경로, 명령, API 이름, 코드, 모델 이름은 원문을 보존한다. 화면은 설치형 데스크톱 앱의 기본 창 안에서 동작한다. OS 메뉴·알림·파일 선택기는 데스크톱 플랫폼 계약을 따른다. 로컬 사용은 원격 모델·MCP 통신이 없다는 뜻이
아니므로 실행 전에 전송 범위를 확인할 수 있어야 한다.

## 정보 구조와 화면 영역

| 영역 | 기본 역할 | 이동·상태 계약 |
| --- | --- | --- |
| 왼쪽 탐색 | 프로젝트, 일반 폴더/저장소/워크트리 구분, 작업 검색·고정·보관, 읽지 않음, 새 작업·가져오기 | 표시 이름과 절대 경로를 분리한다. 작업을 바꿔도 미완성 입력·실행·승인 소속이 섞이지 않는다. 경로 누락은 재연결 또는 읽기 전용 기록 열기로 안내한다. |
| 중앙 작업 | assistant-ui 대화, 작성기, 모델·에이전트·권한 요약, 실행 진행, tool-ui 결과와 승인 요청 | 현재 프로젝트→경로→세션을 상단에 고정해 확인 가능하게 한다. 진행·대기·실패·완료는 실행 계층에서 확인된 상태를 반영한다. |
| 오른쪽 작업 패널 | 브라우저, 파일, diff, 터미널, 계획, 자식, 실행 기록 탭 | 탭별 선택과 크기·접힘을 작업별로 기억한다. 탭이 닫혀도 실행 중 터미널·서버·자식의 종료를 뜻하지 않는다. |
| 전역 진입점 | 커맨드 팔레트, 설정·하네스 구성, 알림함, 도움말 | 팔레트는 현재 작업의 실행 대상과 명령 출처를 표시한다. 전역 알림에서 해당 프로젝트·작업·요청으로 이동한다. |

프로젝트, 작업 경로(일반 폴더 또는 워크트리), 작업/세션, 실행 기록, 부모·자식 실행, 도구 호출, 권한 요청, 산출물, 명령을 화면에서 다른 개념으로 부른다.
앱이 유지하는 식별자와 SDK 식별자·매핑, API, 이벤트, 저장 구조는 [엔지니어링 계약](../../engineering/workbench-architecture.md)의 소유다. 이 문서의 화면 명칭은 해당 매핑을 대체하지 않는다.

처음 열면 작업 루트가 없을 때 루트 선택을 먼저 보여준다. 루트는 자동 생성 위치의 부모이며 프로젝트 import 위치를 제한하지 않는다. 루트를 선택하지 않은 채 자동 생성은 시작되지 않는다. 최근 작업을 열 때는 저장된 대상이 지금도 존재하고 쓸 수 있는지 확인해 상태를 표시한다.

넓은 화면은 세 영역을 함께 제공한다. 좁은 화면은 탐색·대화·세부 내용을 각각 전환하는 단일 활성 영역으로 바꾸고, 현재 작업명·실행 상태·대기 승인을 항상 되찾을 수 있게 한다. 오른쪽 패널에서만 가능한 작업은 만들지 않는다. 화면 폭이나 터치 여부가 권한 확인 내용을 축약하지 않는다.

## 주요 흐름

### 1. 프로젝트 연결과 새 경로 만들기 · F-01, F-02

1. 사용자가 `프로젝트 연결`에서 폴더 선택 또는 경로 입력을 고른다. 검토 단계에서 정규화된 절대 경로, 폴더/저장소/기존 워크트리 유형, 원본 저장소·브랜치, 접근·쓰기 상태를 보여준다.
2. 루트 밖 경로와 이미 등록된 동일 실제 경로는 각각 명시적으로 설명한다. 중복은 기존 항목 열기로 안내한다. 없는 경로·깨진 워크트리·접근 거절은 문제 경로와 수정 동작을 제공한다.
3. 연결 확인은 등록만 한다. 파일 이동, Git 초기화, 프로젝트 plugin/setup 실행은 후속 별도 동작으로 둔다. 탐색에 실행 부작용이 필요하면 먼저 그 내용을 보여주고 명시적 허용을 받는다.
4. `새 폴더`와 `새 워크트리`를 다른 선택으로 제공한다. 이름·경로를 비우면 선택한 작업 루트와 사용할 이름 규칙을 확인 화면에서 제시한다. SDK 이름은 실제 검증된 규칙만 표현하고, 일반 폴더 대체 규칙은 현지 날짜와 UUIDv7 전체를 사용한다.
5. 워크트리는 원본 저장소, 시작 ref(미선택 시 HEAD 제안), 새 브랜치 여부, 예상 목적지, 복사되지 않는 미커밋·ignored 자료를 확인한다. setup 명령은 실행 전에 내용·대상을 보여주고 별도 확인한다.
6. 성공 화면은 실제 생성 경로와 브랜치, 준비 상태를 보여준다. 생성 성공 뒤 setup 실패는 `경로 생성됨 · 준비 실패`로 구분하고 다시 시도·수동 해결을 제공한다. 충돌·권한·경로 제약 실패 시 다른 전략으로 조용히 재시도하지 않는다.

### 2. 작업·대화·실행 시작 · F-04, F-05, F-06

1. `새 작업`은 선택 경로를 명시한다. 같은 경로에 다른 활성 작업이 있으면 충돌 가능성을 표시하고 다른 워크트리를 선택할 수 있게 한다. `기록에서 분기`는 원본 작업·분기 지점·복사되는 대화 범위를 보여주며 빈 작업과 구분한다.
2. 작성기는 선택 모델/agent/추론 옵션의 요청값, 런타임 기본값, 실제 관측값을 구분해 보여준다. 미지원 옵션은 전송 전 이유를 설명하고 수정 경로를 준다. 실행 중 변경은 적용될 다음 요청 또는 자식 생성 경계를 표시한다.
3. 첨부·파일 참조·선택 영역은 전송 전 이름, 출처 경로, 내용 범위, 크기·형식, 원격 모델 전송 가능성을 검토할 수 있다. 접근 불가·모델 미지원 입력은 제거 또는 수정 전에는 전송하지 않는다. 비밀 원문을 미리보기·기록에 복제하지 않는다.
4. 보내면 해당 세션에 메시지와 스트리밍 진행이 붙는다. 추가 지시는 현재 실행에 끼어드는지 다음 요청으로 대기하는지 명시한다. `중단 요청`과 `종료 확인`은 다른 상태다. 재시도는 대상 메시지·분기 결과를 확인하며 이전 도구 부작용을 자동 재실행하지 않는다.
5. 작업 이름 변경·검색·고정·보관·복원·읽지 않음·삭제는 작업 목록의 동일한 대상에 적용된다. 보관은 디스크 삭제가 아니다. 다시 열 때 입력 초안, 선택 탭, 경로와 아직 실행 중인 항목의 실제 상태를 복원한다.

### 3. 위임과 도구 · F-07, F-08

1. 부모가 위임하거나 사용자가 직접 위임할 때 역할, 목표, 필요한 참조, 소유 경로, 성공·검증 조건, 모델/권한과 실제 컨텍스트 전달 방식을 확인한다. 기본 `새 컨텍스트`와 대화 기록 복사 `history fork`를 분명히 구분한다.
2. 자식 트리는 실행·대기열·승인 대기·실패·완료를 부모와 연결한다. 최소 두 자식을 독립적으로 보며 개별·전체 중단 대상과 미종료 항목을 확인한다. 한 자식 실패는 다른 자식의 성공으로 덮지 않는다. 결과 회수는 출처 자식·산출물·검증 근거를 부모 대화에 연결한다.
3. 도구 카드는 도구명, 호출자, 세션/자식, 입력 요약, 대상 경로·도메인, 권한 상태, 진행, 결과·오류를 표시한다. 구조화된 diff/코드/표/미디어는 tool-ui 등록 렌더러를 쓴다. schema를 확인할 수 없는 결과는 원문을 마스킹한 일반 카드로 제공하고 임의 동작 버튼을 만들지 않는다.
4. 직접 도구 실행은 노출·검증된 schema의 인자를 편집·확인한 뒤 제출한다. agent 호출과 동일한 권한·취소·기록 규칙을 따른다. 카드의 선택·질문 응답은 권한 허용과 시각적으로·문구상 구분한다.

### 4. 권한 요청과 실행 중 모드 변경 · F-09

1. 현재 모드의 실제 적용 규칙을 파일 읽기·쓰기, 셸, 네트워크/MCP, 허용 경로와 확인 조건으로 펼쳐 볼 수 있다. `요청마다 확인`, `범위 내 편집 허용`, `읽기/계획`, `사용자 정의`는 규칙 묶음으로 표현한다. 실행 계층이 강제하지 못하는 모드는 사용 가능하다고 표시하지 않는다.
2. 권한 카드는 호출자·작업·자식, 대상, 정확한 명령/인자, 요청 시각과 이번 허용 범위를 먼저 보여준다. 기본 선택은 `이번 요청만`. 기억 범위는 실제 지원·적용되는 단위만 제공하고 저장 규칙 조회·취소를 연결한다. 시스템 정책의 거절에는 허용 버튼을 제공하지 않는다.
3. 허용·거절 뒤에는 `결정 전송 중` → `적용 확인` 또는 `실패`를 표시한다. 중복 클릭, 오래된 요청, 종료된 요청은 다시 실행하지 않고 상태 재조회와 이유를 보여준다. 여러 요청을 함께 처리할 때는 고정된 대상 목록·각 범위를 다시 확인하고 뒤늦게 생긴 요청을 포함하지 않는다.
   권한 상태는 backend 상태·영수증·원인과 다음 동작을 아래처럼 대응한다. `결정 적용 확인`은 실행 완료가 아니다.

   | Backend state / evidence | Visible state | Available action |
   | --- | --- | --- |
   | `pending` + current revision | 승인 대기 | 이번 요청 허용 / 사용자 거절; 시스템 정책 차단이면 허용 없음 |
   | `decision_sending` | 결정 전송 중 | 허용·거절을 비활성화하고 중복 전송 금지 |
   | `applied` + applied receipt | 선택한 결정 적용 확인 | 결정 버튼 없음. 실행 상태는 별도로 추적 |
   | `denied` + `USER_DENY` | 사용자가 거절함 | 결정 버튼 없음 |
   | `denied` + `POLICY_DENY` | 정책에서 차단함 | 허용 버튼 없음; 정책·권한 상태 보기 |
   | `expired` | 요청 만료됨 | 최신 상태 확인만 가능; 과거 요청 재응답 불가 |
   | `cancelled` | 요청 취소됨 | 취소 주체를 표시하고 최신 상태 확인만 가능 |
   | `unknown`, 전송 결과 불명, 오래된 revision | 결정 상태 확인 필요 | 읽기 전용 재조회·대조; 새 현재 `pending` 확인 전 재응답 금지 |

   전송 오류가 `effectState=none`이라고 확인돼도 같은 revision의 `pending`을 새로 조회한 뒤에만 다시 허용/거절할 수 있다. `dispatched` 이후 효과가 불확실하면 `unknown`으로 남기며 같은 요청을 재전송하지 않는다. `202` 또는 전송 접수는 적용 영수증이 아니다.
4. 모드 변경은 새 규칙·영향받는 세션/자식/대기 요청을 검토하고 `변경 요청` → `신규 호출 보류·기존 호출 처리` → `적용 확인` → `다음 실행부터 적용` 순서로 표시한다. 축소 중 즉시 끊을 수 없는 호출은 아직 실행 중이라고 말한다. 실패 시 이전 유효 모드를 유지한다.
5. 권한 확대는 범위와 향후 적용 시점을 명시적으로 확인한다. 부모의 확대가 기존 자식에게 자동 적용된다고 말하지 않는다. 축소는 활성 자식별 보류·중단·적용 결과를 보여주며 이전 대기 승인으로 우회하지 않게 한다. 이미 발생한 쓰기는 되돌렸다고 표현하지 않는다.

### 5. 결과 검토·개발 도구 · F-10, F-11, F-12, F-15

1. 오른쪽 프리뷰는 연결된 로컬 dev server·URL·HTML/Markdown·이미지/PDF의 주소, 로딩, 실패, 새로고침, 앞뒤 이동, 크기 조절을 제공한다. 임베드 불가 이유와 외부 브라우저 열기 선택을 보여준다. 외부 열기는 앱 내 프리뷰 성공으로 기록하지 않는다. 프리뷰 콘텐츠에는 로컬 실행 권한을
   전달하지 않는다.
2. 서버 시작·중단은 작업, 경로, 포트, 로그, 실제 프로세스 상태에 붙인다. 탭 닫기와 서버 중단을 분리한다. 실패한 서버는 실행 성공이나 활성 프리뷰로 표현하지 않는다.
3. 파일 트리/검색, 텍스트 열기·수정·저장, 외부 변경 충돌 해결, 변경 목록, staged/unstaged/기준 브랜치 diff를 한 경로 문맥에 둔다. 줄 단위 피드백에는 파일·버전·줄을 남긴다. stage/unstage, 변경 복원, commit, branch 선택/생성은 각각 대상과 예상 효과를 확인한다. 손실
   가능 복원은 변경 파일·경로를 다시 확인한다.
4. 터미널 탭은 실제 작업 경로, 사용자 또는 agent 주체, 연결·실행·종료 요청·종료 코드 상태를 표시한다. 닫기와 프로세스 종료를 별도 선택으로 둔다. build/lint/test/dev 액션은 출처 스크립트·실행 경로·최근 결과를 보여준다. 고아 프로세스는 확인·종료 경로를 제공한다.
5. 계획은 대화 옆 또는 오른쪽 패널에서 편집·승인 버전·진행 상태를 보여준다. 구현자 결과와 독립 리뷰어 결과를 구분하고 미해결 지적·수정 후 재검증을 연결한다. 에이전트 완료 발화와 실제 lint/test/review 통과 표시는 다르다.

### 6. 명령·구성·기록·일상 사용 · F-13, F-14, F-16, F-17, F-18

1. 작성기의 `/`와 전역 팔레트는 런타임 내장/프로젝트 명령·스킬, 앱 명령을 출처별로 검색한다. new/open/worktree/model/permissions/plan/review/compact/status/mcp/help에 해당하는 앱 조작으로 이어진다. 인자 도움말·실행 대상·불가 이유를 보여주며 충돌한 이름은
   출처를 고르게 한다. 임의 문자열을 셸 명령으로 해석하지 않는다.
2. 하네스 설정은 instructions/AGENTS, skills, agents, hooks, tools, MCP, plugin의 위치·출처·활성 상태·적용 범위와 요청값/실제 활성값을 보여준다. 편집은 초안→검증→변경 미리보기→적용/재로딩→실제 확인 순서다. MCP 연결/해제·설치·업데이트·프로세스 실행은 영향과
   대상이 보이는 사용자 동작으로만 시작한다. 외부 인증이 필요하면 기존 설정 경로를 안내한다.
3. 시간순 기록은 세션/자식/도구/권한/검증 필터와 원본 결과로 돌아가는 링크를 제공한다. 제공되지 않은 token·usage는 `정보 없음`, 추정치는 `추정`으로 표시한다. 원격 청구액처럼 보이게 하지 않는다. 설정 비교는 요청·기본·관측의 차이를 설명한다.
4. 합성 학습 화면과 실제 작업 기록에서 사용자가 실행 전 예상, 실행 뒤 답·근거·오답을 기록할 수 있다. 숨겨진 사고 과정이나 미측정 cache·성능은 복원했다고 주장하지 않는다. 개인 활용 기록은 로컬에 두고 사용자가 내보내기·삭제 범위를 관리한다.
5. 연결 끊김·프로세스 종료·앱 재시작 뒤에는 저장 상태 재조회 중임을 보여주고 확인된 세션·결과를 복구한다. 실시간 이벤트 누락 구간은 `확인할 수 없는 구간`으로 남긴다. 중단 요청을 종료로 표시하거나 이미 실행한 도구를 자동 재실행하지 않는다. export/import 전에는 포함 데이터·마스킹·대상 파일을, 삭제
   전에는 로컬 삭제 범위와 외부 보존 한계를 확인한다.
6. 테마·글자 크기/밀도·레이아웃·단축키 도움말은 설정에서 조절한다. 완료·오류·승인 알림은 작업과 연결하되 민감 본문을 숨긴다. OS 알림을 쓸 수 없으면 앱 안의 대기 상태를 유지한다. 반복 작업은 대상·주기·권한·마지막 실행을 보여주고 일시정지·재개한다. 앱/서비스가 꺼져 놓친 일정은 미실행으로 표시하며 소급
   실행하지 않는다.

## 파괴적 동작과 복구 계약 · F-03 중심

`목록에서 제거`, `대화 기록 삭제`, `워크트리/폴더 실제 삭제`는 다른 메뉴·확인 제목·결과 설명을 쓴다. 목록 제거와 보관은 디스크에 영향이 없다. 기록 삭제는 작업 경로 삭제가 아니다. 실제 삭제는 절대 경로, import 여부, 원본/워크트리 관계, 미커밋·untracked 파일, 영향을 받는
세션·자식·터미널·서버, branch 유지 여부를 보여준다.

원본 저장소 루트, 홈·파일시스템 루트·상위 작업 루트, 중첩된 다른 프로젝트, 다른 세션이 사용 중인 경로는 삭제 선택을 막고 이유·해결 경로를 표시한다. 활성 실행은 중단 요청 뒤 실제 종료를 확인해야 한다. 경로·dirty 상태는 최종 실행 직전에 다시 확인해야 하므로 UI에서 이전 점검만을 근거로 확정 성공을
예고하지 않는다.

기본은 비강제 삭제다. dirty/untracked를 버리는 별도 선택에는 손실 대상과 절대 경로 재확인을 요구한다. import한 일반 폴더의 물리 삭제에는 import 사실을 강조한다. 취소하면 아무것도 지우지 않는다. 전략 실패는 실패로 남기고 임의의 다른 삭제 방식으로 넘어가지 않는다. 실제 삭제 뒤 기록을 남기면
경로 없음·읽기 전용으로 표시한다. 검증된 복원 수단이 없으면 `되돌리기`를 제공하지 않는다.

정책상 거절, 사용자 거절, 접근 권한 부족, 인증 실패, 네트워크 단절을 하나의 `오류`로 합치지 않는다.

계정·구독·결제 UI는 PRD 범위 밖이다. 기존 런타임 자격 증명이 없거나 만료되면 `외부 설정 필요` 또는 `인증 실패`로 표현하고 벤더 로그인·결제 흐름을 만들지 않는다.

## 키보드·스크린리더·반응형·동작

모든 핵심 흐름은 키보드만으로 가능해야 한다. 논리적 탭 순서는 전역 탐색→현재 작업 헤더→대화/작성기→활성 세부 패널이다. 팔레트와 모달은 열릴 때 제목 또는 첫 의미 있는 입력으로 초점을 옮기고, 닫을 때 호출 요소로 되돌린다. 닫힌 요소가 사라졌으면 현재 작업의 대응 동작으로 이동한다. 권한 카드·삭제 확인은
모달로 표시될 때만 포커스를 가두며 배경 실행 상태 안내를 끊지 않는다. 대화 안의 inline 권한 카드는 일반 탭 순서에 두고 다른 작업으로 이동할 수 있게 한다. `Esc`는 초안·선택 팝오버만 닫고 실행 취소나 권한 거절을 몰래 수행하지 않는다.

프로젝트/작업 목록과 자식 트리는 화살표 탐색·선택·확장을 표준 역할에 맞게 지원하고, 검색·고정·보관은 메뉴에 문자 이름을 제공한다. 탭은 활성 탭, 패널은 제목, 진행은 상태 문구를 스크린리더에 노출한다. 스트리밍 문장 전체를 토큰마다 읽지 않는다. 승인 대기, 중단 확인, 완료, 실패, 연결 복구처럼 의미가 바뀌는
순간만 간결하게 알린다. 병렬 실행 중에는 어느 작업·자식의 알림인지 포함한다.

모든 조작은 보이는 focus 표시와 충분한 터치 대상·명확한 레이블을 갖는다. 상태는 색만으로 전달하지 않고 텍스트·형태·아이콘을 함께 쓴다. 긴 절대 경로·명령·diff는 잘림 여부와 전체 값 열기를 제공한다. 축소된 화면에서도 권한 범위·삭제 경로·외부 전송 대상이 잘리지 않는다. 오버레이가 열려도 현재 작업과 승인
대상이 보인다. 호버 전용 조작은 쓰지 않는다.

움직임은 패널 전환, 새 결과 도착, 상태 변화의 위치 파악을 돕는 용도에 한정한다. 진행 표시가 실제 실행을 암시해야 하며 확인되지 않은 자동 완료 애니메이션을 쓰지 않는다. 사용자 환경의 reduced motion 설정에서는 변위·반복 효과를 제거하고 상태 텍스트를 유지한다. 지속 시간은 승인된 디자인 시스템의 fast 120ms, standard 180ms, panel 240ms를 따르며, 반응형 너비는 320–599px, 600–899px, 900px 이상 구간을 따른다. easing만 구현 선택으로 남으며, 새 easing을 시각 기준으로 승격하기 전 일관성·접근성을 검증한다.

의미·레이블·접근성 계약은 공통으로 유지한다. Native 메뉴, OS dialog, notification, window close/reopen, bridge lifetime and background automation behavior follow the desktop runtime decision and require lifecycle verification. Closing a window must not silently claim that a running bridge operation stopped.

## 토큰·컴포넌트 계약과 보류

승인된 시각 기반은 저장소가 소유하는 [디자인 시스템](../system.md), [토큰 manifest](../tokens/manifest.json), 생성된 [CSS](../tokens/tokens.css), [컴포넌트 계약](../components.json)이다. manifest는 primitive → semantic → component 계층과 Light/Dark 별칭을 정의한다. 현재 시스템에는 타이포그래피, 간격, 반응형 너비, 포커스, 상태, 모션 결정을 포함한 토큰 163개와 정밀 variant 44개, 컴포넌트 계열 6개가 있다. 빈 scaffold이 아니다. Figma는 산출 대상이며, 계정 연결이나 과거 캡처가 있다고 해서 제품 라이브러리 동기화·게시까지 확인된 것은 아니다.

현재 기반 계열은 Button, Input, StatusBadge, NavigationItem, ToolCall, PermissionRequest 여섯 가지다. 작업 공간/세션 탐색, 작성기, 탭, 대화상자, 트리, diff, 터미널, 알림, 프리뷰 같은 제품 구성요소는 이 기반을 조합하는 구현 계약으로 남아 있다. 구현과 검토가 끝나기 전에는 완성된 컴포넌트라고 표시하지 않는다. 아래 의미·접근성 제약은 유지하고, 시각 값을 바꿀 때는 검토된 디자인 시스템 변경으로 처리한다.

PermissionRequest의 backend 상태·원인·receipt 대 UI 문구·행동 매핑은 `components.json`의 `componentContracts.PermissionRequest.runtimeStateMap`을 필수 단일 기준으로 쓴다. 다섯 visual variant의 sample label은 정적 미리보기 전용이며 런타임 표시값으로 사용할 수 없다. 런타임 레이블과 행동은 상태·선택 결정·거절 원인·현재 revision·적용 receipt에 맞춰 이 맵에서 정한다.

| 계층 | 현재 원본과 계약 |
| --- | --- |
| Primitive | `docs/design/tokens/manifest.json`; 기본 값, 타입, 간격, 모서리, 경계, 깊이, 모션 입력 |
| Semantic | 같은 manifest; Light/Dark 면·문자·경계·포커스·행동·상태 역할 |
| Component | `docs/design/components.json`; 정확한 variant, 컴포넌트 바인딩, 콘텐츠 규칙, 조합 상태 |
| CSS 산출물 | `docs/design/tokens/tokens.css`; manifest와 대조 검증하는 결정적 출력 |

정책 차단, 사용자 거절, 전송 오류, 검증 실패는 문구와 의미를 서로 구분한다. 성공 색상은 성공이 확인된 경우에만 사용한다. 코드·diff·터미널처럼 정보 밀도가 높은 콘텐츠는 별도의 읽기 역할을 가지며, 제품 팔레트를 구문 강조색에서 가져오지 않는다. 구현된 UI에서 한국어 본문과 영문 경로·코드가 섞인 표본의 대비, 확대, 줄바꿈, 선택, 좁은 화면, 두 테마를 검토한다.

승인된 시각 방향은 실행 근거가 분명한 조용한 대화 캔버스, 중립적인 Light/Dark 면, 필요한 곳에만 쓰는 기능적 경계다. 장식용 줄무늬와 반복되는 카드 테두리를 쓰지 않는다. 공개 ChatGPT 페이지는 큰 위계의 참고일 뿐, 독점 토큰이나 로그인 화면을 재현했다는 뜻이 아니다. 별도 검토된 디자인 변경으로 실제 제품 필요가 확인되기 전까지 토큰 163개와 variant 44개 계약을 유지한다.
