# assistant-ui and OpenCode: integration evidence

Checked 2026-09-26 KST. Fresh factual researcher: /root/own_code_ui_research. Read-only primary-source investigation; no packages installed, server started, compatibility test executed, or product behavior validated. The coordinator additionally opened the adapter overview, ExternalStoreRuntime and new-v2 client pages.

- **Native integration exists:** @assistant-ui/react-opencode maps OpenCode sessions/events into assistant-ui threads, including streaming, tool/terminal output, permissions and questions. The page labels the adapter experimental v0.0.3 and installs @opencode-ai/sdk. Nested task conversations are eagerly loaded and displayed read-only. This is not evidence that it supports the newly named @opencode/sdk or @opencode/client. [Official adapter](https://www.assistant-ui.com/docs/runtimes/opencode/overview)
- **UI wiring:** the quickstart uses AssistantRuntimeProvider and useOpenCodeRuntime with conversation primitives. Session lists can be server-managed without Assistant Cloud. No hosted service is required by that example. [Quickstart](https://www.assistant-ui.com/docs/runtimes/opencode/quickstart)
- **Custom backend state:** ExternalStoreRuntime consumes application-owned messages and callbacks. Persistence, synchronization and cancellation/branch behavior depend on the supplied implementation. It documents an integration mechanism, not a working new-v2 adapter or a component/flow-learning UI. [ExternalStoreRuntime](https://www.assistant-ui.com/docs/runtimes/custom/external-store)
- **New-v2 client:** @opencode/client uses OpenCode.make. Its events are live-only with neither replay nor automatic reconnect; subscribers share a connection and slow consumers can affect delivery. Disconnection must not silently become a completed trace. [Client documentation](https://opencode.ai/v2/docs/build/client/)
- **Observable evidence:** the API describes configuration discovery, session messages, model/agent changes, skill/tool states and permission requests. These are evidence for external behavior; a reasoning field is not proof of complete hidden model reasoning. Routes retain experimental labels. [API reference](https://opencode.ai/v2/docs/api)
- **Existing alternative:** the CLI already offers interactive and noninteractive execution over the shared server. Whether a learning interface improves this user's understanding is an untested hypothesis, not a market fact. [CLI documentation](https://opencode.ai/v2/docs/cli)

The earlier [SDK-generation discovery](opencode-sdk-initial.md) remains dated context. Current new-v2 packages and the older /v2 export must not be conflated. Exact published versions, end-to-end integration, fresh-session context boundaries, trace recovery and educational benefit remain unverified. Future checks should pin the chosen generation and test the smallest thread/tool/permission/cancellation flow before expanding the interface.
