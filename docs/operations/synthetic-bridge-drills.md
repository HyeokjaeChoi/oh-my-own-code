# Synthetic bridge operations drill

Status: Local fixture exercise. Owner: local workbench operator; unresolved recovery decisions go to the build coordinator.

Run `pnpm nx run local-bridge:operations-drill --skip-nx-cache` from the repository root. The target builds the fixture bridge, then uses an ephemeral loopback listener and a temporary directory containing only generated synthetic records. It deletes that directory on exit. It has no external telemetry, provider calls, user project access, or persistent output. A passing exit means the bounded exercises below passed; it does **not** certify production recovery or complete AC-6.

| Exercise                    | Detection and evidence                                                                                                                                                             | Safe response shown                                                            | Coverage limit                                                                                                 |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Secret canaries             | Six generated token, environment, path, prompt, HTML, and tool-result markers are absent from serialized allowlisted log and diagnostic records                                    | Keep only operation ID, source/error code, and effect state                    | The fixture bridge has no production event store, notification, PTY log, or diagnostic export to inspect       |
| Bridge loss                 | `/health` answers, a closed loopback bridge fails, then a new listener returns `/api/snapshot` with the expected revision                                                          | Show `unavailable` during loss and require a fresh snapshot after reconnect    | This is an in-process fixture restart; no UI reconnect or host/SDK reconciliation exists                       |
| Effect then crash           | A child writes `dispatched`, increments a synthetic effect counter, then exits before confirmation; recovery sees counter 1 and returns `unknown` without replay                   | Hold mutation admission and inspect the actual effect before any new operation | The bridge has no durable operation journal or real tool/OS effect reconciliation                              |
| Backup, migration, rollback | A checksum-protected synthetic JSON backup survives an interrupted candidate; recovery reads schema 1 in a read-only model; schema 2 blocks in-place rollback to a schema 1 reader | Preserve backup, stop writes, pair an older build with its compatible backup   | No application DB, versioned migration, export/import, build pairing, or file/process side effect is exercised |
| Missed schedule             | A pure slot model marks offline due as missed, does not catch it up, skips paused due, and blocks a duplicate dispatched slot                                                      | Resume at a future slot after policy/credential checks                         | No bridge scheduler, clock/DST test, OS background lifecycle, or notification exists                           |

For a real incident, first stop new mutations, record the build and affected operation IDs without raw inputs, and check bridge health plus a fresh snapshot. Treat `dispatched` without a confirmation receipt as `unknown`, inspect file/Git/process/native evidence, and never infer success from an accepted request. For migration failure, preserve the pre-update backup and keep recovery read-only until schema/build compatibility and external effects are checked. If the bridge was down at a due time, mark the slot missed and require a separately authorized new execution; do not silently backfill.

The local status panel, diagnostic exporter, durable operation journal, data store, and scheduler remain implementation work. Their absence is an unavailable signal, not a passing production drill. The unresolved user-data location and retention policy are deliberately outside this fixture. See [local release monitoring](local-release-monitoring.md) for the intended full release checks and recovery contract.
