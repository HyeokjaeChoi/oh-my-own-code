# Git review observation design
Version: 7. Date: 2026-10-08. Initial PLAN revision2, DESIGN_SPECv3 and exact-version compatibilityv4 passed. This bounded implementation compatibility correction replaces the unavailable Darwin root-FD path with checked private worktree copies. Dependent reader implementation waits for the matching changed-concern DESIGN_SPEC pass. Public API/UI remain unchanged.

## 1. Decision and sufficient boundary
Use app-host controlled inert temporary Git metadata with a trusted fixed-command Git executor. No new dependency, durable store or repository writer. SDK2.0.18 is unsuitable for this increment because it drops XY and working diff combines index/worktree against HEAD; actual staged source inherits config/env and patch lacks no-textconv. Original-repo commands with per-filter overrides retain config-change races. Historical sandbox investigation is NO-RUN and gives no enforcement proof. A separate OS sandbox is not claimed or required by this boundary: Git receives no original config/includes/objects metadata, and only fixed read commands. Same-UID malicious memory/temp changes or root compromise are out of the app threat boundary, as existing filesystem design states. Original workspace content remains untrusted data.

Git never follows original object alternates. The helper descriptor-copies the bounded complete supported common objects store, plus detached supported HEAD/index/refs, into one fresh mode0700 private namespace. Original objects are read only by the helper through checked ancestry; Git object reads use copied bytes only. Reject symlink/hardlink/nonregular entries, alternates, promisor/shallow/grafts, split/sparse index, reftable or unknown mandatory extensions. Reject object-store info/alternates and any unrecognized redirection; copy only validated loose-object fanout files and paired pack/idx files, optionally inert known rev metadata. Do not copy original config, config.worktree, hooks, replace refs, logs or executable templates. No symlink/hardlink copy, original GIT_OBJECT_DIRECTORY, GIT_ALTERNATE_OBJECT_DIRECTORIES or original GIT_INDEX_FILE. Root/common/git-dir/object/metadata ancestry identity is checked before and after each bounded descriptor copy; any change refuses the whole observation. Object copy total128MiB/16384files, file count/depth bounded; exceeding it is unavailable too_large. This is deliberately a bounded first read increment, not full large-repository acceptance.

Worktree file reads by Git use only a checked private worktree copy in the same owned mode0700 request namespace. Actual Darwin prerequisites showed that an inherited directory FD can be fstat/opened but /dev/fd/3/child lookup fails; root-FD cwd fails ENOTDIR, and Git status exits128. Do not retry this path or fall back to any original absolute path, symlink, launcher, shim or unproved CWD anchor. The app helper walks the original registered canonical worktree through its existing checked descriptor/ancestry reader, excludes only the selected top-level .git marker/directory, and creates the matching relative directory/file tree privately. Any descendant .git marker/directory refuses the whole observation as unsupported_repository: do not flatten a nested repository into ordinary untracked descendants and do not copy nested Git metadata. After checked canonical discovery of original gitDirectory/commonDirectory and BEFORE worktree copying, validate tree disjointness: metadata inside the selected worktree is allowed ONLY inside the excluded top-level .git subtree. If either gitDirectory or commonDirectory overlaps any copied worktree subtree outside that exclusion, or is an ancestor of the selected worktree, refuse the WHOLE observation as unsupported_repository. In particular a top-level .git file pointing to .meta inside the worktree must refuse before any .meta/config can be persisted. Do not silently omit that directory and claim complete status. External disjoint metadata for supported linked worktrees remains allowed through the existing checked copy. No original config/config.worktree bytes enter this tree: Git metadata config remains bounded memory/stdin-only and only the generated minimal config is persisted. Copy regular files only, preserving the executable-mode semantics needed by core.filemode; reject symlink, hardlink, special file, ambiguous/unsupported relative path or changed ancestry for the whole observation, without following or fabricating its state. Copying ordinary worktree bytes does not authorize displaying protected/binary/oversize content: existing selected-detail guards still apply. Git receives absolute --git-dir and --work-tree paths BOTH inside the owned namespace and cwd there; it has no original worktree path, descriptor path, object directory, config or external attribute path. Original paths may exist only in the host metadata manifest/public path labels, never Git command arguments/environment. Count all copied regular files, including ignored/untracked/protected current source, in the combined object plus worktree copy bound128MiB/16384files. Bound the complete worktree walk at4096entries INCLUDING directories and files (empty directories count), plus separate Git ls-files candidates4096, depth32, chunk1MiB and the same whole8000ms deadline; exceeding any bound is unavailable, including large ignored trees. No partial usable result. Copied index stat identities may differ: Git must rehash copied files and actual tests must prove clean/staged/unstaged, executable mode, supported CRLF/attributes/ignore semantics. Require the complete worktree manifest and stability check before any repository Git command and after all commands. Recheck root and every original metadata/config/attribute/worktree identity before/after command. Changes discard the whole observation. Selected diff current bytes come from the same validated copy, and original source must be rechecked before result publication. Two linked worktrees must copy their own current tree and index, with common objects/refs copied independently. Whole-worktree status remains a last observation, not a transaction or mutation token; same-UID change-and-restore absence is not claimed.

## 2. Executable, environment, lifecycle and alternatives
Darwin initial executable is the direct /Library/Developer/CommandLineTools/usr/bin/git, not /usr/bin shim or PATH lookup. Every component and file must be root-owned and not group/world writable, no symlink alias. Record device/inode/mode/size/SHA256/version and recheck immediately before spawn and after exit. Supported versions are exact2.50.1 (Apple Git-155) or2.54.x, each only with successful exact fixed-command capability preflight; changed/unsupported/missing executable gives git_unavailable, never PATH fallback/download. Root/admin compromise is excluded explicitly. Windows lacks this verified executor/private-copy acceptance and returns platform_unavailable in this increment; no Windows pass or completed whole product claim.

Choose bounded detached-memory config interpretation via this same trusted Git. Read exact checked config/config.worktree bytes into bounded memory only, then invoke the fixed builtin git config --file - --no-includes --null --list with those bytes through its stdin pipe in an empty inherited environment and private cwd. Never create a raw config scratch file, named pipe, command argument, log, report or retained evidence copy. Do not use create-then-unlink as a crash guarantee. Upstream Git2.50.1 and2.54 builtin/config.c treat --file - as stdin; exact installed binary support and no-includes behavior still require actual acceptance. Explicit --no-includes is mandatory even for stdin. This builtin read does not attach original repository or includes, has no shell or repo-selected executable, and writes no config. Bound raw parser stdout/stderr in memory only, extract allowed semantic values, discard raw buffers after settlement without claiming secure heap erasure. Only the whitelist-generated minimal config may be written to scratch. Config includes/unsupported extensions cause unsupported_configuration, not ignored semantic truth. Controlled command config contains only explicit validated supported booleans/normalization settings, no executable drivers; core.hooksPath=/dev/null, fsmonitor=false, gc.auto=0, maintenance.auto=false, core.attributesFile=/dev/null. HOME/config/cache/temp point to owned namespace; clear every inherited variable; set literal locale/no pager/no optional locks/no replace/no lazy fetch/global+system config disabled. Known Git executable directory may be literal PATH for runtime internal resolution, but command names are always absolute and no driver/helper definition exists. --no-ext-diff/--no-textconv/--no-renames/--ignore-submodules=all and literal pathspecs are mandatory where applicable. No remote, shell, checkout/add/commit/reset/restore/branch mutation command is callable.

One request owns one namespace and exact child handles. Max2active requests total and1perworkspace, otherwise READ_BUSY. Whole read budget8000ms (including copies); each child at most2000ms and operation output budget below. Caller cancel/timeout/sender close stops new work, signals only exact owned child SIGTERM, after250ms SIGKILL, and waits at most1500ms for actual exit/close. Release internal IO slot only after settlement. Delete only checked owned private namespace after all actual owned exits; never recursive cleanup of original root/common tree. On failure/cancel with proved exit, preserve bounded report and optionally synthetic evidence as probe requires, clean ordinary production scratch. If exit cannot be proved, retain namespace and mark that workspace Git reader unavailable until service shutdown/reconciliation; do not claim cleanup. No new original write/replay/durable mutation exists. App crash/orphan cleanup and power loss are not claimed fully solved by this read feature; no auto-adopt/kill of foreign PID on restart.

Comparison: SDK cheapest but wrong split/no-helper boundary; original override cheapest custom code but config race; controlled metadata has bounded copy cost and explicit unsupported large/complex repos but retains normal index semantics without repo config execution; OS sandbox would add platform/dependency audit and unverified assumptions. Select controlled metadata as reversible app read module. Actual canaries must establish fixed-command helper refusal, original preservation and copy/descriptor boundaries; hashes alone do not prove isolation.

## 3. Supported interpretation and diff meaning
| Setting/data | Decision | Result |
|---|---|---|
| core.bare | false only | Bare repository unsupported |
| repository format/objectFormat | conventional0/1 with SHA1/SHA256 | Other mandatory extension/ref storage unsupported |
| core.filemode/ignorecase/precomposeunicode/symlinks | validated booleans copied, platform defaults explicit if absent | Preserve known semantics; invalid value unsupported |
| core.autocrlf | absent/false only | true/input unsupported_configuration in this bounded increment |
| core.eol | absent/native/lf supported | crlf unsupported_configuration until separately proven |
| core.worktree | identify exact selected original root, never forward | Mismatch not_repository_root/path_changed |
| core.excludesFile/attributesFile and include/includeIf | external/custom values unsupported | Do not ignore a custom config and label it canonical clean |
| .gitignore and original info/exclude | bounded inert bytes, native Git pattern semantics | Copy info/exclude into private metadata; actual CRLF/ignore fixtures |
| .gitattributes and original info/attributes | builtin text(auto/set/unset), eol=lf, ident supported | Check actual attributes for every tracked/untracked candidate; unsupported custom encoding/conversion refuses observation |
| filter attribute or filter.* driver definitions | any active custom driver unsupported | No clean/process/smudge executable definition forwarded |
| working-tree-encoding/custom named diff driver/textconv | unsupported | Binary/-diff is metadata-supported but selected patch unavailable binary |
| merge driver attributes/config | never execute merge; custom semantic definition unsupported for simplicity | No speculative helper execution |
| replace refs/alternates/partial/shallow/split/sparse/reftable/gitlinks | unsupported_repository | No recursion or false completeness |

A private status command returns separate raw index and worktree codes. Public normalization maps each side separately; conflicts and untracked are distinct. Staged diff is observed HEAD tree -> copied index, unborn uses empty tree. Unstaged is copied index -> current held worktree. Base diff is the explicitly chosen observed local branch TIP OID -> current held worktree including index/worktree changes; it is DIRECT tip comparison, never merge-base, and UI says so. No base selected means no base diff call. Detached HEAD allowed and labeled; unborn base diff requires a real selected branch OID. Conflicts return metadata and selected unavailable conflict, not a resolved patch. Untracked behavior is mode-specific:

| Untracked current path | Comparison/result |
|---|---|
| staged | unavailable not_staged |
| unstaged | empty -> actual observed guarded current file |
| base | exact selected baseOid's path blob -> current guarded file; use empty only when that path is actually absent from that base tree |

Thus a current untracked file equal to the selected base blob yields an empty successful base patch; different bytes yield the exact base-to-current change, never a fabricated full addition. Disabled rename detection produces added+deleted rows and UI explains it. No user rev expression, option or pathspec magic is passed; only validated observed OIDs and literal guarded relative path. Raw binary, protected/configuration/secret, symlink/hardlink, >64KiB old/new/worktree source or non-UTF8/control content has a closed detail refusal.

## 4. Public read contract and bounds
Normalv2 current epoch, authenticated sender, no sessionId. Add both read types to actual host/frontend readTypes/files lane; preserve transport10000ms. Main wraps atomic runtimeEpoch/revision only after host scope recheck. No mutation type, journal event or executable retained payload.

Requests exact:
- git.review.read {type,workspaceId}
- git.diff.read {type,workspaceId,observationId,mode:'staged'|'unstaged'|'base',path,baseRef?}; baseRef REQUIRED only modebase, otherwise forbidden.

Observation common exact {runtimeEpoch,revision,workspaceId,workspacePath,status}. available adds {observationId,repository,branches,files}; repository exact {worktreePath,gitDirectory,commonDirectory,objectFormat:'sha1'|'sha256',head:OID|null,branch:string|null}; branches [{name,oid}]; files [{path,index,worktree,kind}]. index/worktree closed values none|added|modified|deleted|type_changed|unmerged, kind tracked|untracked|conflict. Untracked uses both none, kinduntracked. Protected paths can appear as names, never content. Unavailable adds reason only and no repository/files/patch. No truncated usable observation. Codes/reasons are closed, getter/extras/malformed clock rejected by shared browser-safe validator. observationId64hex binds original sender/current epoch/workspace/root, executable identity and exact copied source metadata/config/attributes; host keeps max4metadata-only observations perworkspace, max256total, expiry30000ms. Refresh replaces current observation; detail requires exact held original observation and matching fresh recreated metadata identity. No snapshot bytes retained between calls.

Detail common exact {runtimeEpoch,revision,workspaceId,workspacePath,observationId,mode,path,status}; modebase adds baseRef and observed baseOid. available adds {patch,sourceDigest}; sourceDigest64hex binds exact compared source bytes/OIDs/modes and original observation. unavailable adds reason only. Both sides and current file bounded before patch generation. No partial patch as successful output. Main returns existing WorkbenchResult wrapper; errors such as malformed/sender/stale epoch/READ_BUSY use existing transport errors, ordinary read inability is valid unavailable DTO. Observation reasons: not_repository|not_repository_root|platform_unavailable|git_unavailable|unsupported_repository|unsupported_configuration|path_denied|path_changed|metadata_changed|too_large|read_failed|process_unverified. Detail adds protected_source|binary|missing_file|conflict|not_staged|expired_observation|stale_observation. No raw config/command/stderr returned.

Numeric bounds: root and relative path reuse current workspace-file grammar4096/2048UTF8,32components/255component. index16MiB, other metadata aggregate1MiB, refs4096entries/depth32, objects128MiB/16384files, all copies read chunks<=1MiB. Max4096tracked+untracked candidates, max512changed rows and128local branches; exceed -> unavailable too_large, never drop rows as clean. Branch name<=512UTF8, oid40/64hex matching format. Every relevant old/index/base/current blob<=65536UTF8 bytes, patch<=65536UTF8 and2048lines/128hunks. Git stdout aggregate16MiB across fixed internal commands, per child at most8MiB, stderr aggregate8192bytes (not exported). Patch capture cap65537bytes permits exact overflow refusal. Public JSON DTO<=196608encodedUTF8 bytes and full serialized WorkbenchResult/envelope<=262144bytes existing cap; check aggregate after JSON escaping, not only raw strings. All arrays/counts/bytes/depth/time/wire limits have negative+boundary tests.

Reads require known ready exclusive host owner and registered current canonical workspace; global/matching recovery or active app mutation lock blocks IO. Native session running alone does not grant mutation or block inert status; read is labeled last observation. Inert metadata/diff read may operate in an untrusted registered workspace because no project code/config executable is loaded; bind trustRevision and trusted flag so changes retire it. This is not execution trust or file-save authority. Tests explicitly exercise malicious untrusted repos through actual no-helper path. Unknown or invalid registry/root authority refuses.

## 5. Renderer lifecycle and actual checks
Sole window owner has Git observation and selected detail, no duplicate server/durable state. Each status/detail request binds epoch/workspace/root/trust/floor and separate generation; detail also exact observationId/mode/path/baseRef. No automatic status/diff on mount/poll/selection/refocus/resize. Explicit refresh retires current detail; old observation may remain visibly last/stale until accepted current result. Workspace/root/epoch/trust change invalidates all IO authority and cancels read, late results inert. Selection ABA/new refresh/base/mode/path rejects old detail. Independent preview remount never changes Git own identity. READ_BUSY offers explicit retry after400ms readiness without auto Git query. Cancel only reads, never claims mutation cancellation. Clipboard/feedback/stage/commit/restore not included or implied.

Existing files context contains explicit Git review surface with full selectable worktree/source/base labels, index and worktree columns, conflict/untracked/unsupported states, empty local base initially and direct-tip explanation, plain readable selected patch. Keyboard and760px200% must work; error/truncated/expired/held state gives explicit re-observe path. Existing file editor remains usable. No fake write controls.

Contract files tests cover DTO/wire/closed limits/scope/ABA/late read and unsupported states. Actual git-probe uses production helper+verified directGit on contained ordinary repos and two linked worktrees; independent expected index/HEAD/worktree/base bytes, diverged base branch distinguishes direct-tip vs merge-base, and a path present only in base while currently untracked has equal/different content cases. CRLF text attribute/ignore/filemode supported cases, custom conversions refusal, helper canary path attempts, original bytes unchanged, metadata/object/root substitutions, copy size cap, child cancellation/deadline/exact exit/namespace retention are required. Synthetic config URL and HTTP-header credential canaries must be absent from every scratch/retained report in normal, parse-failure, timeout, cancel, unproved-exit and controlled host-crash paths; raw config must never reach the filesystem. Distinguish injected unproved-exit tests from actual exit/crash evidence. This config-memory correction does not claim to solve copied object-store crash retention, OS swap/core dumps, all sensitive material lifetime, or secure memory erasure. Build/type/boundary/bundle/lint/format and appended hidden UI matrix bind one coherent candidate. Fresh CODE and RENDER after checks. Darwin only actual evidence; no current Windows, root-malware, power-loss, provider/private-store or productionMain claim.

Version5 resolves the actual Darwin root-FD incompatibility by extending the existing detached-copy read strategy, without a new runtime/helper/dependency/store or original Git command. Private copies include ordinary current source bytes as copied objects already include historical source; they may contain sensitive project data. Production namespaces are private0700 and are removed only after all exact owned children settle; after unproved exit or host crash copies may remain. Do not export copied source/config/raw output in logs or reports, auto-adopt/kill foreign children, claim secure erasure/encryption/OS isolation, or claim crash cleanup. Synthetic probe namespaces may be retained as explicitly synthetic evidence only; raw credential Git configs never go to disk even in those namespaces. Canary normal/error/cancel/timeout/unproved-exit/controlled-crash cases must recursively verify no raw config credential copy. This limitation is visible in final evidence; no private/user repository is invoked in verification.

Version6 clarifies the same draft private-copy boundary before its review completes: nested .git is whole-observation unsupported; only selected top-level .git is excluded. All current ignored/untracked/protected source copies count toward budgets and may remain after crash/unproved exit; no content export or omission-as-clean. Directory walk entries include empty directories, independently of returned/candidate file count. Owner executable mode is preserved and copied stat identity never authorizes a clean shortcut: actual Git rehash proof is required. Full original-source manifest is checked before repository commands and after the complete command sequence. No public API/UI change.
