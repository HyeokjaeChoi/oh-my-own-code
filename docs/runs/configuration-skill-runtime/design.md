# Explicit Native Skills — runtime and UI design
Version: 1. Initial major runtime/security/data/UI boundary. Implementation held for initial reviews.

## Architecture decision
Select a fixed trusted built-in local DIRECTORY plugin, loaded by pinned config.plugins and registered through actual Context.skill.transform/reload and Context.rpc.register. Keep isolated config/project/filewatcher/update/deny settings. ConfigPluginSource drops configured files, resolves directory entrypoints using Host.resolve and checks containment. Module.load's absolute-local branch does not invoke npm; never supply package targets. Reject enabling project discovery (loads untrusted settings), invented SDK setters (not present), AGENTS substitution (different semantics), or a second application-only Skill registry masquerading as Native state. Reuse existing production Native startup/owner fence, event-host resource staging and Main v2 admission. This is one narrow trusted extension, not a public plugin platform.

Package only fixed server entrypoint, package metadata and closed RPC/pure helper dependencies under a known event-host resource directory. Parent and child verify the complete manifest before startup. Construct config content in child from fixed verified path plus per-runtime private authority; never from renderer paths or saved user plugin text. Local module cannot launch processes, read arbitrary files or make network calls as part of these handlers. No external packages installed. Native startup route probe must precede downstream API consumers; source declarations alone are not proof. Stop and review approach if exact directory setup/RPC fails.

## Authority and Native data
Main uses original app runtimeEpoch/workspace/session mappings and private per-child nonce; nonce is never returned to renderer, journal or reports. Closed private RPC binds method/version/nonce/original operation identity/workspace canonical path. Context.location.directory must equal verified workspace root; reject cross-location calls. Methods are observe, registerDisabled, removeOwned. Handler state belongs to this plugin instance, with a serialized bounded request/result cache and immutable transform snapshot. Hook is synchronous; do not hold a lock that reload callbacks require. Session application uses real public SDK session.skill outside a generic arbitrary-method bridge, always resume:false.

Native Skill.Info fields are id,name,description?,autoinvoke?,path,content. There is NO generic metadata property. Allocate nativeId as omoc-skill- plus SHA256 of original epoch/workspace/sourceName/registration operation key. Parse only current supported safe SKILL.md grammar; preserve exact BOM/LF/CRLF body semantics against actual pinned parser. Always override Native autoinvoke:false. Native pathname is exact verified SKILL.md; no file read is delegated to plugin. Main passes the bounded immutable parsed record and original canonical request digest. Plugin ownership map retains exact original registration identity and record digest. Observation checks both plugin-held identity and public Native list record; prefix or matching file content alone never establishes ownership. Foreign rows remain read-only. Colliding IDs reject before change. Reload/partial verification failure remains unknown; do not restore uncertain state silently.

App registry persists identity/digests/Native IDs only, not content. Reopen does not repopulate the Native map. Prior-epoch registered metadata is historical; current explicit read must distinguish absent/current/unowned/unverified. Pending original operation gates startup and mutation exactly as existing durable rules. Re-registration is an explicit new generation/nativeId. No automatic read/register/apply after file save, startup/poll/refocus/selection, trust change or restart.

## Public operation contract
Add distinct closed configuration.skill.runtime.read {workspaceId,sessionId?}, configuration.skill.register {workspaceId,sourceName,observationId,version,directoryVersion,digest}, configuration.skill.remove {workspaceId,nativeId,observationId}, configuration.skill.apply {workspaceId,sessionId,nativeId,observationId}. Existing configuration.skill.list/read/save and instructions/MCP are unchanged. Runtime read uses files lane and returns a closed snapshot with workspace/root/epoch, observationId, owned rows (sourceName/nativeId/registration key/file and Native digests/autoinvoke:false), unowned readonly rows, and optional selected-session Skill-message facts. No credentials, raw configuration or arbitrary Native function is exposed. Exact DTO fields frozen by Main before consumers; any shape change must be coordinated, not guessed by workers.

Main stores bounded immutable observation authority tied to epoch/root/trustRevision/resource generation/revision floor and optional session mapping. Register additionally requires the unchanged exact loaded file version/directoryVersion/full-byte digest and fresh runtime observation made against that file baseline. Re-read file and Native registry before and after explicit confirmation; compare complete target/text/forced inactive state. Remove needs no file but exact owned current row and confirmed removal. Apply needs exact selected session mapping, trust, idle/inbox and current owned row; show full target and name/body scope before confirming. Read-only untrusted requests fail closed. Confirmation cancellation is zero-effect.

All mutation entry uses existing v2 envelope, sender, candidates, canonical digest, admission and receipt transport. Add configuration_skill_runtime_v1 feature before durable admission/checkpoint. New dispatch steps native.skill.register, native.skill.remove, native.skill.apply are flushed before each actual RPC/reload or SDK effect, and original key/type/workspace/session/source/registration scope must match. Exactly one RPC register/remove effect bundle is represented; internal reload is part of that bounded handler, not a second unjournalled host operation. Completion is zero resource topology delta and records only verified result identity/proofs. Older parser refusal must preserve full bytes for journal tail and zero-retained checkpoint. Unknown/orphan/late ACK preserves original operation key and no replay; selection changes never relabel an old completion as current.

## Application and proof limits
Use client.message.list with type:skill, bounded pagination (max16pages of64records, at most1024 Skill messages), validated nonrepeating cursors, exact session/root mapping and complete terminal cursor. Truncation means unavailable, not absent. Before native.skill.apply intent require no message for this registration's unique nativeId. Already present is observed history, not new application, and must not call SDK. After session.skill({sessionID,id:nativeId,resume:false}), require exactly one new message of type:skill with unique new messageID, expected nativeId/name/body digest and correct selected native session. Save messageID in confirmed receipt; no arbitrary Native metadata assumed. Missing/multiple/changed records or timeout after dispatch gives unknown with no result fabrication or replay. On reopen original confirmed receipt remains historical; fresh history can show present/absent/unverified, but absence today cannot prove an uncertain original call had no effect. Fork inherited Skill messages are not relabelled as direct application.

Registration removal changes Native registry availability only. Existing session Skill messages and model context history remain; there is no proven public undo API. Applying with resume:false proves appended Skill content and no requested model start, not model consumption or successful task execution. Future ordinary send keeps both existing baseline policy stages and honors unknown holds; no new auto execution.

## Renderer and UX
Add Native controls within current Skills editor beside the separate file workflow. Explicit Native status read, inactive registration from the exact loaded/saved unchanged file, owned row removal, and selected-session application. Selected-file draft stays sole-window owned; snapshot and action identities include epoch/workspace/root/trust/floor/generation/draft reference and selected session where applicable. Workspace operations have no fabricated session scope. Validate closed responses and original-key receipts; retire observation after mutation, await confirmed revision floor then require explicit reread. No auto Native read or cloned executable retained payloads. Draft remains editable/selectable during holds.

Show file observation/save, Native registered autoinvoke-disabled state, and selected-session recorded Skill separately. Explain forced autoinvoke:false even when file says true. Apply label is '선택한 세션에 적용'; adjacent text says it adds Native Skill record and does not start a model. Removal explains old session content remains. Current evidence only labels ownership; prior receipts are historical. Untrusted guidance uses existing new-session trust path and its actual creation side effect; no invented trust API. Missing file/unsafe/unsupported/dirty/stale/collision/foreign/changed/denied/pending/unknown/history-truncated/untrusted/restart states are explicit and recoverable. Reuse approved controls/tokens/focus/wrapping/selection, keyboard and760px/200%, no broad redesign.
