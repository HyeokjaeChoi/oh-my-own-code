# Skill file design v2
Status: proposed major-entry contract. Existing module/state/build/component ownership follows ADR-0001 without change.

## API and source
Public operations: configuration.skill.list {workspaceId}; configuration.skill.read {workspaceId,sourceName}; configuration.skill.save {workspaceId,sourceName,requestId,text,directoryVersion,expectation:"missing"|"version",version?}. No sessionId, arbitrary path, Native call or executable payload. Existing v2 envelope, sender, operationId, revision and original retained-key rules remain mandatory. List returns {workspaceId,workspacePath,path,status:"available",entries:[{sourceName,path}],truncated:boolean} or status unavailable/missing with closed reason. Read returns {workspaceId,workspacePath,sourceName,path,status:"available",content,version,directoryVersion} or missing with directoryVersion/reason:missing_file, or unavailable/unsupported with closed reason. UTF-8 grammar rejection is draft validation, not byte loss. Save returns existing saved/unknown shape; terminal result `skill_file_saved` includes workspaceId/sourceName/version/backupId? only. No Native origin/status is inferred from filesystem success.

## Target resolution and IO
One pure target descriptor fixes workspace/.opencode/skills/sourceName/SKILL.md. Existing directories only, canonical absolute metadata root, safe sourceName. List examines at most64 directory entries and returns at most16 safe canonical directories; truncation true if budget/row limit reached. Ancestors and child must be real directories on workspace device, no symlinks; retain handles where needed and revalidate canonical named/held dev+ino around each await. Read file nofollow/nonblock, regular single link, <=32768 bytes, fatal UTF8 and no NUL. Missing means confirmed leaf absence with every ancestor still verified; missing ancestor is unavailable/path_missing. Closed reasons: missing_file (missing leaf only), path_missing (missing ancestor), path_denied, file_changed, unsupported_content, too_large. Missing list root uses path_missing with no entries; unavailable never claims empty successful list. List is metadata-only and never reads contents.

directoryVersion is a 64-hex SHA256 of [workspaceId,workspacePath,sourceName, ordered [canonical path,dev,ino] for workspace and each ancestor]. Every save, including missing expectation, requires the exact read directoryVersion. Service rechecks it before/after confirmation; kernel compares held chain before any stage. An ancestor disappearing is unavailable; replacement is FILE_CHANGED.

Version hashes existing workspace/target/root/file/bytes identity plus ordered ancestor dev+ino and canonical paths for Skill only; preserve legacy root-leaf version semantics. Existing Darwin arm64/Bun1.4.2 kernel walks openat nofollow directories and holds every ancestor FD. Stage, backup and rename are relative to verified leaf-parent FD. Verify whole named/held chain before/after prepare and publication. No mkdir, follow, arbitrary target, replacement writer or cleanup of foreign files. Backup IDs retain existing operation-key hash with .skill.backup suffix in verified parent. Existing xattr/ACL/metadata/fsync/rollback behavior remains; no stronger power-loss or hostile same-UID atomicity claim.

## Admission and durable compatibility
New feature configuration_skill_files_v1 appended before any admitted Skill save, persisted in checkpoints. Private sourceName admitted with exact operation identity, defensive lookup identity and duplicate comparison; public retained snapshot remains original immutable type/scope only, no source/payload recovery execution. stage then publish only for configuration.skill.save or legacy configuration.save; result/type/target/sourceName/effect/delta/dispatch relationships closed. Old parser must refuse marker with byte preservation on journal/checkpoint, including no retained operations. Save rejects before effect where possible, timeout after effect unknown, no success/result leaked through unknown receipt. Confirmation and async rechecks bind canonical chain, exact draft text/digest and baseline version/missing. Final successful reread verifies content/version; no Native registration is performed.

## Validation
Pure browser-safe helper shared by request, kernel and UI. sourceName regex above, closed Markdown subset from actual pinned SkillFile/ConfigMarkdown source: optional first --- block, JSON string scalars name/description, optional metadata with only boolean opencode/autoinvoke. No duplicate keys or generic YAML evaluation. Read exact safe bytes even unsupported grammar. Validation explains supported form and full file difference before save. name/display metadata does not redefine folder sourceName/Native ID. autoinvoke text is file data only; it is not enabled in runtime. Plain nonblank Markdown allowed. Native content excludes frontmatter when someday loaded; current runtime disables project discovery.

## UI and state
Use existing configuration editor kind option Skills with explicit list and file selector plus read button. Empty, missing, denied, changed, unsupported, truncated, dirty, pending, unknown and confirmed states have plain Korean text and stable data attributes. Selectable actual full path; clear existing-directory limitation and inert save status. Native registry remains separately observed through existing catalog, never auto-read by Skills UI. Save button requires loaded exact baseline, valid changed draft, trusted/current/idle/nonheld scope and floor. Confirmation shows target, text/diff and backup semantics. Success retires read authority; new explicit read required after snapshot floor. Unknown holds draft and original operation key; current envelope lookup only, no replay. Do not insert received file text into execution or auto-load it into a session.

Single window Zustand owner; no second persisted store or local authoritative duplicate. Per-file keys, immutable generation+draft identity and cleanup follow current instructions/MCP patterns. Workspace/session/root/trust/epoch switches retire observations, preserve only intentional scoped drafts, prevent late action attribution. No automatic read or list on start/poll/refocus. Existing tokens, focus rings, 32px desktop/44px coarse controls, wrapped layout and selectable text; inspect desktop,760px,200%, keyboard and long names.

## Alternatives, costs and reversal
Extending legacy configuration.save kind was rejected: a distinct operation cleanly gates storage compatibility and safe per-file target metadata. Generic YAML and arbitrary path/folder creation rejected to bound parser and traversal semantics. Second writer rejected to preserve audited metadata/rollback. Native plugin registration deferred because public skill namespace is read-only and trusted-plugin startup is a separate major boundary. New narrow helpers/tests are owned by current modules, no package/framework change. Once feature is durable, old versions must hold rather than silently consume. Existing Skills files remain inert portable bytes.

## Verification
Meaningful synthetic ancestor rename/symlink/device/denial, file replacement/hardlink/oversize/encoding, scan budget, exact baseline/confirm race, backup and unknown tests; actual Bun kernel publication and exit; legacy parser journal/checkpoint refusal; renderer ABA/late ACK/unknown and no auto reads; coherent build/bundle/type/boundary; actual hidden UI and independent code/render. Provider/private stores/production Main are not invoked.
