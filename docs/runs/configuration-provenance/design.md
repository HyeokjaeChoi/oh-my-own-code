# Configuration metadata and UX contract

Version: 2 | Date: 2026-10-08

## Boundary and wire shape

Keep catalog.list as an existing v2 bounded read with selected workspace and optional session. Add optional configuration metadata to WorkbenchCatalog for compatibility with unchanged old fixtures; production new service supplies it. Absence renders unavailable, not empty/success. No new request type, persistent store, Native dispatch step, preload capability, dependency or filesystem path-opening action. Snapshot/recovery/retained schema is unchanged.

Configuration metadata: runtimeStatus fixed not_reported; status available|partial|unavailable; optional closed reason untrusted_workspace|runtime_unavailable|path_denied|limit_reached; entries bounded to40. Entry is a closed allowlist: id (host-generated stable digest), kind instructions|skills|agents|hooks|tools|mcp|plugins|configuration, source workspace|runtime, optional path (max4096, no controls), scope workspace|external|runtime, state discovered|reported|unavailable, optional count (safe bounded integer) and optional closed reason path_denied|unsupported_format|not_reported. No arbitrary config keys or values, command/template, endpoint/auth URL, headers, environment, content or errors are exposed.

Do not issue config.get. Existing running process/trust is insufficient proof that a selected Native location is initialized: middleware may create its layer and Config load/watch before returning entries. The first increment therefore has runtimeStatus:not_reported for configuration documents/directories/category counts; it cannot claim config loaded/active or native no-side-effect proof. ConfigEntry document/directory union remains a source fact for later implementation, not a DTO source now. No commands count is labelled tools. Hooks/tools or unknown declarations are not inferred absent. Skill catalog entry may add allowlisted source:runtime, path and scope from the already-required trusted skill.list result only; content remains excluded. MCP current status remains its existing observed connection state. No new SDK method, location creation, activation, config reload or watcher is introduced. App mock counters prove explicit app calls and secret projection only, not all Native internals.

Filesystem metadata discovers a fixed bounded selected-workspace set only: root AGENTS.md, CLAUDE.md, opencode.json/jsonc and .opencode/.agents/.claude directories; optional known foreign marker .codex/config.toml is discovered with support unverified, never treated executable or automatically converted. No recursion, home/global scan, raw file reads, JSON evaluation or arbitrary supplied path. Check canonical root before/after and each intermediate component with lstat; no symbolic links. Missing is not an error; denied/malformed/link/root change is unavailable/partial and cannot erase the last known identity or claim success. A discovery file is not a runtime-loaded source. Trust gates existing SDK skill/mcp calls; no SDK config method is called; inert workspace metadata may be shown for untrusted imports. Existing execution-safe startup preflight stays intact, including configured extension rejection where required.

## Alternatives and risks

Extending existing catalog is smaller than adding a generic configuration RPC/state owner; keeping optional fields allows prior fixtures without misrepresenting support. Provenance intentionally omits raw configuration values to prevent credential disclosure. A generic editor/filesystem bridge and shell-only SDK update are rejected for this increment. Later configuration activation is a separate reviewed side-effect boundary and must not bypass preflight. Inert path discovery cannot prove loaded/active configuration; Existing SDK list reports cannot prove safe execution or effective policy. Future config.get must verify its initialization boundary before use, or remain unavailable. Lexical scope does not prove native global ownership or resistance to all external filesystem races. These limits remain visible.

Revision2 resolves initial planfinding with the smallest safe choice: no new config.get, no Native setup, no inferred counts. Pure metadata discovery and existing skill path/MCP status are the useful delivered boundary. Raw ConfigEntry union projection and activation are deferred to their future verified boundary, not silently complete.
