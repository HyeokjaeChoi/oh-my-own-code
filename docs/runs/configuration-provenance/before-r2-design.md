# Configuration metadata and UX contract

Version: 1 | Date: 2026-10-08

## Boundary and wire shape

Keep catalog.list as an existing v2 bounded read with selected workspace and optional session. Add optional configuration metadata to WorkbenchCatalog for compatibility with unchanged old fixtures; production new service supplies it. Absence renders unavailable, not empty/success. No new request type, persistent store, Native dispatch step, preload capability, dependency or filesystem path-opening action. Snapshot/recovery/retained schema is unchanged.

Configuration metadata: status available|partial|unavailable; optional closed reason untrusted_workspace|runtime_unavailable|path_denied|limit_reached; entries bounded to40. Entry is a closed allowlist: id (host-generated stable digest), kind instructions|skills|agents|hooks|tools|mcp|plugins|configuration, source workspace|runtime, optional path (max4096, no controls), scope workspace|external|runtime, state discovered|reported|unavailable, optional count (safe bounded integer) and optional closed reason path_denied|unsupported_format|not_reported. No arbitrary config keys or values, command/template, endpoint/auth URL, headers, environment, content or errors are exposed.

Runtime ConfigEntry document projection reads only type/path and fixed-category structural counts: instructions/skills arrays, agents/commands own-map sizes, mcp.servers own-map size and plugins array. A document itself is a configuration row; directory is metadata only, not a document with empty info. Unsupported hooks/tools or unknown declarations are not inferred as absent. No arbitrary keys are copied. Malformed payloads yield unavailable/partial without reflecting raw input. Arrays/maps have explicit maximum; truncation is marked rather than presented complete. Accessors/nonplain objects are rejected. Paths are reported locations, not openable authorities or evidence of canonical ownership. Workspace scope only for lexically contained absolute paths under the rechecked canonical workspace; external does not mean trusted global ownership. Missing path has runtime scope. Skill catalog entry may add allowlisted source/runtime, path and scope only; content remains excluded. MCP current status remains independent observed connection state; configured counts are not connected count.

Filesystem metadata discovers a fixed bounded selected-workspace set only: root AGENTS.md, CLAUDE.md, opencode.json/jsonc and .opencode/.agents/.claude directories; optional known foreign marker .codex/config.toml is discovered with support unverified, never treated executable or automatically converted. No recursion, home/global scan, raw file reads, JSON evaluation or arbitrary supplied path. Check canonical root before/after and each intermediate component with lstat; no symbolic links. Missing is not an error; denied/malformed/link/root change is unavailable/partial and cannot erase the last known identity or claim success. A discovery file is not a runtime-loaded source. Trust gates every SDK config/skill/mcp call; inert workspace metadata may be shown for untrusted imports. Existing execution-safe startup preflight stays intact, including configured extension rejection where required.

## UI

Use existing extension panel, shared catalog store/controller identity, native buttons and CSS Modules. Add section aria-label="설정 출처". Intro: "파일 발견과 실제 적용 상태는 다릅니다." Rows show type, source, selectable full path, scope and state. Labels: discovered="파일 발견 · 적용 여부 미확인"; reported="런타임 보고 · 실행 여부 미확인"; unavailable="확인할 수 없음"; unsupported format="변환 미지원" only when the host has actual verified reason, never guessed from vendor prefix. No path guessing, activation switch or executable affordance in this increment.

Untrusted label: "신뢰하지 않은 작업 공간입니다. 파일 위치만 확인하며 구성을 실행하지 않습니다." Partial label explains some sources could not be verified; missing optional metadata: "설정 출처 정보를 제공하지 않습니다." MCP labels: connected="연결됨 · 런타임 관측", needs_auth="외부 인증 설정 필요", disabled="비활성 · 런타임 관측", pending="확인 중", failed="연결 실패". Preserve names/descriptions from existing safe catalog and clear boundary: "이 단계에서는 읽기만 제공합니다. 편집·적용과 연결 변경은 아직 제공하지 않습니다." Do not label F-14 complete.

Keyboard refresh stays native; content is readable/selectable. Current desktop32/coarse44 tokens, focus ring and narrow scroll behavior remain. Hidden proof covers normal provenance, untrusted/partial, long selectable path at200%, refresh and stale workspace response. No entire state Cartesian expansion or replacement of approved visual layout.

## Alternatives and risks

Extending existing catalog is smaller than adding a generic configuration RPC/state owner; keeping optional fields allows prior fixtures without misrepresenting support. Counts and provenance intentionally omit raw configuration values to prevent credential disclosure. A generic editor/filesystem bridge and shell-only SDK update are rejected for this increment. Later configuration activation is a separate reviewed side-effect boundary and must not bypass preflight. Inert path discovery cannot prove loaded/active configuration; SDK report cannot prove safe execution or effective policy. Lexical scope does not prove native global ownership or resistance to all external filesystem races. These limits remain visible.
