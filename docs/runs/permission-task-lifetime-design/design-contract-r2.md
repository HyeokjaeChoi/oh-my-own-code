# Original-operation task lifetime and private handoff
Revision: 2 — candidate for independent design-spec review; not an active API or permission grant.

## 1. Problem and retained decisions
Main currently validates Native's genuine inbox receipt, records accepted/confirmed, and releases the attachment acquisition when the original prompt call returns. Actual coordinator, promoted inputs, title Fiber and tool/IO/process work can remain. Registry retention currently means only `!operation.terminal`. Changing that expression alone would conflate a confirmed admission with uncertain execution, block ordinary steer/queue, and misrepresent original receipts.

Use the existing journal, registry and graph-owned Control. Add a separate bounded task lifetime inside the same durable state. Preserve the original operation key/digest, immutable ACK receipt, both baseline policy stages and no-replay rule. A terminal operation cannot receive another ordinary dispatch or have confirmed downgraded/unknown upgraded. New task records address a separate task root and never mutate that receipt. No second database, writer, executable replay queue or renderer authority.

Accepted DS02/03, authenticated upper deny, trusted inventory, location registration, actual leases and sole writer/root broker remain prerequisites. This supplement never enables positive execution by itself. Missing compiler/inventory/bootstrap/recovery evidence continues to hold the relevant scope.

## 2. Selected ownership and alternatives
Main's existing host admission owns the original operation and sole journal. The existing EventHost supervisor owns the authenticated child channel and lifetime. Graph Control owns concrete Native scope/Fiber/IO/child reservations. The renderer displays one host projection and cannot create or settle tasks.

Rejected: a second task journal; using terminal=false after ACK; using the first HTTP request to claim an origin; a nonce alone as flush evidence; raw attachment IPC; Session.active/idle or a scope callback as settlement; reopening and replaying pending originals; assigning all tasks to a single global blocking flag. These either duplicate state, lose original identity, exceed bounds or break live interactions.

Selected: Main issues an operation-stage handoff only AFTER its existing original intent append flush succeeds. Child reserves genuine Native identifiers without execution, Main persists a detached task root, and the child consumes an exact one-use handoff before the earliest Native effect. The long task root survives the HTTP ACK. Current-process verified liveness is volatile authority, distinct from persistent uncertainty. A restart cannot reconstruct live authority from disk.

Trust statement: Main is the trusted sole journal writer. The child verifies the authenticated private parent delivery and exact detached origin/stage/target against its current graph; it does not independently read Main's journal. Transport authentication proves delivery from that trusted writer, not flush by itself. The Main issuer is factory-owned and callable only after the actual successful registry dispatch; accepting arbitrary caller booleans or proof objects is forbidden. Custom plugin code is not a trusted issuer. Existing fixed-source and inventory gates must precede callbacks.

## 3. Private identity and bounds
A durable task root belongs to exactly `[originalRuntimeEpoch, operationId]`; at most one root per original operation. `taskScopeId` and every handoff ID are fresh UUIDs, never reused. The original canonical operation digest includes expectedRevision exactly as admission persists it. Raw input digest remains separate.

Closed task identity:
`{taskScopeId, origin:{runtimeEpoch,operationId,type,digest}, workspaceId, appSessionId, nativeSessionId, projectId, locationId, modeGeneration, inventoryGeneration, originKind}`.
All fields are required except appSessionId/nativeSessionId in the explicit pre-session bootstrap variant. Bootstrap carries the exact existing reservation instead; binding the created Native session is a separate one-time record. LocationId is the actual opaque registered location UUID, not a caller path or numeric incarnation converted into authority. Positive safe generations and current graph identity must match. Bootstrap uses the checked reserved workspace/project candidate and remains boot-held until post-create binding verifies the actual Native result. Any unresolved project/owner mismatch blocks bootstrap; it cannot borrow another session's identity.

OriginKind is `prompt|command|bootstrap|mutation`. The existing origin-scopes inputDigest-only admission must become a closed typed union in the coordinated implementation; do not fill its required inputDigest with a dummy value. Prompt-origin constraints retain their current exact digest; nonprompt operation scopes carry their own bindingDigest and no promoted input until an actual task.input record binds it. Existing lease kind names remain unchanged; bootstrap/mutation work that needs a lease uses its actual supported effect category, never invents an uncoordinated kind. Each origin kind uses its own closed binding, never a fabricated prompt:

- prompt: exact existing permissionPromptInputDigest of detached sessionID/text/delivery/files; child-generated Native inbox ID before reconcile/prepare/revert/admit/wake.
- command: canonical original command operation and actual command callback lease before expansion. Each resulting prompt gets its own genuine inbox ID and exact expanded prompt digest, durably attached before that prompt's first effect. Expansion is not pre-authorized merely by the original command name. If a callback can execute untracked effects, refuse it.
- bootstrap: exact existing original reservation, create/fork/import stage and parent identity where applicable. No prompt digest. Creation/fork/import cannot execute tools or auto-resume under bootstrap authority. Verify exact actual Native metadata/location/ID before installing the permanent binding.
- mutation: exact existing original operation type, its admitted closed target, actual method-stage argument digest and affected session/project set. Policy, selection, cancellation, interrupt and configuration effects use this stage authority. It does not confer prompt or tool authority.

Maximum2048 durable task roots, additionally bounded by the existing2048 operation keys; maximum256 unsettled roots; maximum1024 input bindings/root, maximum256 original origins/promoted scope and maximum32 direct child leases per existing lease. Each serialized private message must fit16KiB and each journal record the existing4MiB bound before allocation/append. Represent large promoted/child sets with bounded individual original-key records and monotonic sequences, never an oversized single proof message. Counters must be safe integers; overflow/capacity fails before effects and never evicts unknown keys. Settled roots remain attached to retained original operation history and obey the existing compaction/retention policy; no independent eviction that permits key reuse.

## 4. One-journal state machine
Append feature marker `native_task_lifetime_v1` before the first new task record. Extend strict parser, checkpoint validator, replay and feature refusal together. Existing journal sequence/checksum/append poison/owner fencing remain authoritative. Older actual parsers must refuse both journal and checkpoint with unsupported_version and preserve all bytes; retain the actual complete old parser dependency closure for that test.

New records are closed variants in the same journal:

1. `task.prepare`: original key/digest + full detached identity + taskScopeId + binding variant. Original admission must exist and match. Before any Native effect.
2. `task.input`: exact existing taskScopeId + monotonic input sequence + genuine inbox ID + nativeSessionId + inputDigest + source (`prompt|command_expansion|synthetic_child`). Each Native inbox key is unique. The initial prompt input is part of prepare; subsequent records cannot alter it or claim a previously consumed input. Synthetic input requires an actual child lease/original lineage; no unsolicited Native synthetic origin.
3. `task.observe`: exact taskScopeId + monotonic observation sequence + phase `bound|running|cancelling|unverified`, current child launch identity and detached opaque lease/scope identifiers. Only the private current-child verifier can issue it after correlating the stored task and actual graph observation. This is not an ordinary caller request or permission grant. Disk replay never restores volatile verifier capability.
4. `task.settle`: exact taskScopeId + final observation sequence + bounded proof digest + outcome `settled|no_effect`. Requires the current private verifier to have observed complete actual task/IO/process/child settlement, or proven no effect plus complete outstanding-call settlement. Parser validates structural/history consistency; live authority is required before the writer admits the record. Receipt is unchanged.

Every new record has common own data fields `{kind,revision,runtimeEpoch,operationId,taskScopeId,sequence}`. revision is EXACT previous registry revision+1 and is checked by the existing journal history validator. The original key resolves one existing task root; origin/resource fields cannot be overridden. The task handler runs before ordinary operation dispatch validation, so terminal ACK does not accidentally grant dispatch. Each root starts sequence=0 at prepare; EVERY subsequent task record, including input, binding, handoff state, observation and settlement, uses previous task sequence+1. Journal sequence remains independent. A retransmitted identical record is acknowledged without another append only if its full detached canonical payload equals the stored record at that sequence; changed payload or gaps conflict. All payloads are closed, own enumerable data fields; undefined, accessors, symbols and extras are rejected before copy.

Specific fields after the common fields are: prepare `{identity,binding}`; input `{nativeSessionId,inboxId,inputDigest,source,parentLeaseId,state:'pending'}`; input-transition is `{inboxId,from:'pending',to:'promoted',scopeId,scopeVersion,proofDigest}`, `{inboxId,from:'pending',to:'cancelled',proofDigest}`, or `{inboxId,from:'promoted',to:'settled',scopeId,scopeVersion,proofDigest}`; no other transition; bootstrap-binding `{appSessionId,nativeSessionId,metadataDigest}`; handoff `{handoffId,step,stageArgumentDigest,state:'armed'|'consumed'|'revoked'|'completed',proofDigest}`; observation is a discriminated variant `{phase:'bound',launchId}` with NO lease/scope fields, or `{phase:'running'|'cancelling',launchId,scopeId,scopeVersion,leaseId}`, or `{phase:'unverified',launchId,reason}` with no invented identifiers; proof `{proofDigest,outcome:'settled'|'no_effect',lastActivitySequence}`; settlement `{proofDigest,outcome:'settled'|'no_effect'}`. Proof kind is task_proof; it is a durable complete-proof checkpoint before final settlement, never an authority release by itself. lastActivitySequence equals the immediate prior task sequence. After proof, new activity is forbidden; only matching settlement or uncertainty/reconciliation may follow. Settlement uses the exact prior flushed proof; its own sequence is still previous+1. The existing journal envelope is unchanged. Bootstrap binding is one-time, exact actual metadata correlation, never arbitrary rebind. Origin binding variants are prompt `{kind:'prompt',nativeSessionId,inboxId,inputDigest}`; command `{kind:'command',commandDigest}`; bootstrap `{kind:'bootstrap',step,reservationDigest,parentIdentityDigest}` (null only for parentless create); mutation `{kind:'mutation',step,targetDigest,stageArgumentDigest}`. bindingDigest is SHA256 over `omoc.permission.task.binding.v1\n` plus existing permissionCanonicalJSON of the detached binding. Raw inputDigest retains its existing algorithm. A synthetic child always names its actual parent lease.

Closed phase transitions: prepare creates prepared; prepared→bound only after exact actual target correlation; bound→running only with actual admitted lease/Fiber; running→cancelling is optional upon actual cancellation initiation; running OR cancelling→settled requires complete proof. prepared OR bound→settled with outcome no_effect is allowed ONLY when all original RPCs have actually returned/settled, all handoffs are durably revoked or consumed with proven no effect, and zero pending/promoted inputs, reserved expansions, children or IO remain. No fabricated lease/scope is needed for this pre-effect case. Running cannot use no_effect. Any nonsettled phase may become unverified on lost authority; ordinary records cannot leave unverified. Only exact reconciliation below can settle it. Settled roots accept no new input, promotion, expansion, handoff or lease. A duplicate settlement is identical-only; no success upgrade of an unknown original receipt.

Atomicity: validate detached candidate state before append, flush, then publish without await/caller callback/fallible work. Failed marker/prepare/input/observe/settle flush keeps store poison/hold and prevents dependent effects or hold release. Completion flush never proves tasks ended. A settled proof received before HTTP ACK may be durably recorded first; later ACK still completes its original receipt independently. A late ACK after task uncertainty cannot clear the task hold.

## 5. Handoff and effect ordering
Private prepare is read-only with respect to Native execution: resolve actual stored session/project/current location, reserve genuine Native inbox ID via its actual generator, and compute/compare exact input digest. No prepare2, revert commit, inbox reconcile/write, wake, callback or plugin execution is allowed yet. Return bounded metadata only. Main checks it against current registry identity, original operation and generation, then flushes task.prepare. Lost prepare response is uncertainty, never permission to reuse an ID. Armed→consumed→completed and armed→revoked are the only handoff transitions; completed requires original call completion and tracked effect/child ownership settlement, revoked requires actual nonconsumption and no outstanding call. All outstanding reservations are owned by the same existing lease/input owner; private verifier may produce task_proof only after every reservation has ended. Parser rejects proof with any pending/promoted input or armed/consumed handoff still outstanding.

For every actual policy/selection/prompt/cancel/create stage, Main preserves the existing intent append and only then arms a private handoff carrying `{handoffId, taskScopeId, originalKey, originalDigest, step, stageArgumentDigest, targetIdentity, currentLaunchIdentity, expiresAt}` plus the applicable inbox/input binding. expiresAt is monotonic/current-process only, never restored authority. At most32 armed handoffs/current child, lifetime5s; expiry/reuse/mismatch fails closed. Stage names remain the existing exact names, including native.policy.before_selection and native.policy.after_selection. No new ordinal or stage name is consumed until the coordinated implementation freeze includes parser/admission/host/child together.

At the Native final entry, consume the exact handoff against stored actual session/project/location/generations and the detached actual argument body BEFORE any callbacks or Native mutations. Consume once; body digest, session ID, stage and input ID cannot be supplied by first HTTP ownership. The public HTTP body's explicit inbox ID must equal the private reserved genuine ID. An unsolicited request, guessed ID, substituted body, reordered stage, duplicate ticket or a request from a different scope has no authority. Failed consumption cannot fall back to legacy Native allow.

Reordering attachments: acquire and pin the existing checked cached bytes before any stage that needs the prompt digest. Do not reopen original paths. Preserve early validation, exact BOM/CRLF, model support checks, authority rechecks and finally release on every failure. Releasing the original HTTP attachment acquisition proves only that cache pin's own use ended. Any Native task that retains bytes must own a tracked detached copy/lease before the pin is released; no borrowed buffer lifetime after ACK.

The current generic IPC cap stays16KiB. Private messages carry only bounded digests/IDs/small immutable targets. Existing HTTP continues to carry bounded prompt data; raw content is never duplicated in journal/proof logs. If the actual SDK cannot pass the reserved ID intact, use an explicit private invocation adapter with the SAME actual Native prompt function after coordinated review. Never drop the ID, silently alter public schema or widen IPC to16MiB.

## 6. Actual task lineage and settlement
At real coordinator start, under the existing current-generation project transaction, consume the original input binding, create the origin scope and admit/capture its actual Fiber before first work. Do not hold graph/project gates across long Native work. The task observer captures concrete pinned Fiber provenance and reserves owned IO/child slots before effects. Unknown child ownership promotes hold. Forked direct/raw/nested tools, shell/background/move/configuration effects each need the existing child lease and final current-generation gate.

The existing origin-scopes input owner is the SINGLE owner of pending/consumed state; extend it rather than add a parallel pending map. Initial prompt preparation creates one pending input as part of prepare. Each queued, steer, command expansion or synthetic child input must be attached before any inbox effect. Every pending input, reserved expansion, armed/consumed unsettled handoff and outstanding original RPC blocks root settlement even when no execution lease exists. A coordinator finishing a steer drain while another queue item remains is not root completion.

Actual inbox promotion must expose exact promoted IDs, not only a count. Under the existing project-before-session-lock order, atomically validate pending ownership, attach every original to the execution scope/current version, and change pending→promoted before callbacks. Cancellation races under the SAME lock: pending→cancelled requires actual Native inbox removal proof, OR exact current-child proof that the reserved input never reached reconcile/admit and every original call/handoff ended with no effect; it cannot cancel an already promoted input. Promotion and cancellation cannot both win. Promoted inputs remain outstanding until all carrying leases and IO actually settle, then promoted→settled is durably recorded; no second input owner or last-input-wins lineage. Reserve command/child expansion before its first callback, attach resulting exact input or prove no effect and release reservation. Failure during a durable transition leaves uncertainty and prevents dependent execution. Both the live verifier and strict journal/checkpoint history validator enforce these transitions and reject any activity after settlement.

The actual title.generate FiberMap child is part of the promoted input's lineage. Admit its child lease before FiberMap.run, capture the actual child Fiber, and reserve owned IO before the parent can return. onlyIfMissing must identify an existing tracked child or prove no new task; it cannot return an untracked completion. Coordinator pendingWake, stopping restart and background handoff must acquire fresh current-generation admission and preserve original ancestry.

A root settles only after every lease carrying that original origin is settled: actual Fiber exit, complete reserved IO closure, owned child-process exit/close, children/background/title tasks and original RPC task all accounted for. Observe before effects; lost pre-binding events remain unverified. A completed Fiber alone, scope callback, interrupt ACK, deadline, UI cancellation, process absence or Native idle is insufficient. Closing Control revokes authority synchronously and retains unfinished roots; it does not settle them.

## 7. Live projection, loss and recovery
Persisted nonsettled roots are conservative startup holds, including pending inputs with terminal ACK receipts. Production freshNativePreflight considers them. Nonfresh startup remains denied unless an exact accepted private recovery ticket proves eligibility BEFORE any Native spawn. Disk state never restores handoff or live verifier authority.

The accepted schema-contract-r3 RecoveryTicket remains PERMISSION-ONLY. Preserve its exact key set, dual Main/preflight binding verification and `authorityHold:false` semantics. It cannot inspect or clear message.send, command, bootstrap or pending-inbox task roots. This supplement defines a separate factory-owned TaskRecoveryTicket, not a renderer/caller object: `{version:1,runtimeEpoch,ownerNonce,registryRevision,registryViewDigest,priorSettlementDigest,nativeCopyDigest,taskKeys:[{originalRuntimeEpoch,operationId,taskScopeId,taskSequence,proofDigest}],ticketId}`. IDs/digests and bounded keys use existing validators; taskKeys is the exact full set of task holds being released, never a subset selected by a caller. ticketId is an opaque in-process capability, never serialized to the renderer. Both Main and preflight verify all fields against the current owner, complete registry view and checked copy manifest before graph construction. Ticket creation requires authoritative prior owned app/child exit settlement, a previously flushed task_proof complete settlement/no-effect record for EVERY named task (including the crash window after task_proof but before task_settlement), zero outstanding pending/promoted inputs, expansions, handoffs and IO in that proof, exact current Native session mapping, and complete read-only copied Native inbox/history showing no unresolved corresponding input. Copy absence, idle, missing PID and a clean marker alone are insufficient. No Native pending store is reopened or drained. No raw data enters the ticket.

TaskRecoveryTicket is intentionally unavailable for a task that crashed before durable complete proof, an unconfirmed tail, incomplete Native copy or unproved process exit. Such originals remain held; this is a stated safety limitation, not completed restart acceptance. After both verifiers accept, append one closed `task_reconciled` record per key with the common fields, `ticketDigest,proofDigest,outcome:'settled'|'no_effect'`; exact original durable proof must match and the receipt is unchanged. Flush every reconciliation before releasing authority or starting normal work. Failure leaves the remaining holds. This record only reconciles a prior proven settlement, never turns an unfinished crashed task into success. A future mechanism to resume unfinished work would need a new reviewed boundary; no promised automatic recovery is hidden here.

Current-process verified live roots are privately correlated to the exact owned child/graph/generation and may allow current permitted steer/queue/reply/interrupt. They are not exposed as unknown retained keys merely because they are running. This volatile distinction expires immediately on IPC loss, owner loss, unexpected sequence, timeout with unresolved original call, child uncertainty or mismatched graph. A timeout never settles a root.

Unverified/recovered roots project ORIGINAL metadata in retainedOperations, deduplicated with ordinary retained operations, plus resource unresolved_operation. Preserve the accepted required `authorityHold:boolean` on EVERY retained row. Permission-only `authorityHold:false` remains valid solely after its exact durable permission_reconciled record. A row with an unfinished task always has authorityHold:true even if another permission hold is released; combine reasons conservatively. A task whose original receipt remains unknown stays lookup-only/retained; task_reconciled can release its task authority component only by the exact TaskRecoveryTicket above, without upgrading that receipt. An ordinary unknown-operation hold cannot be cleared by task reconciliation. False requires every applicable authority component released durably. Missing field is invalid, not false.

Original lookup may truthfully return confirmed ACK while task authorityHold remains true. Missing/idle/absent key, confirmed lookup and ordinary polling never clear that hold. Renderer accepts release only from atomic validated host projection carrying authorityHold:false, or exact host removal of a fully settled terminal row with no remaining hold. Existing actual-call IO holds remain stronger until the original call finally settles. Implement DTO validator, host projection, renderer selectors/controller and fixtures coherently; current renderer is not claimed adequate. Recovery-safe read/lookup remains possible; mutations stay held without a separately proven narrow authority, never blanket interrupt/reply bypass.

Keep global poison/unknown owner separate from resource-specific tasks. If identity cannot be decoded, hold the runtime. Live verified tasks in another workspace must not block unrelated baseline reads or disjoint allowed work. Scope identity and observation sequence must be atomic with the host snapshot clocks.

## 8. Integration and acceptance
Implement together in one routine integration wave after this supplement passes: actual parser/checkpoint/registry task root + admission/stage issuer, existing EventHost protocol/supervisor/child verifier, actual pinned Native prompt/inbox/coordinator/promotion/title/tool lease boundaries, Main cached-byte ordering and renderer uncertainty reconciliation. Freeze exact APIs and source hashes before consumers. Keep unrelated families held until their real origin-kind path is implemented; do not pretend prompt digest authorizes command/bootstrap/import. Full F09/full18 remain unfinished until all accepted families are complete.

Meaningful RED then GREEN must cover: ACK before long task end; task end before ACK; both policy stages flush before actual call; substituted HTTP body/ID/target/epoch/generation/step; earliest prepare/revert/admit/wake refusal; duplicate/no replay; live steer/queue distinct from recovered uncertainty; multi-origin promotion; title/background child still live; actual-call timeout after ACK; original cache release vs detached Native bytes; marker/each task flush paused/fails; completion immutable after task record; partial tail/reopen no execution; old actual parser journal/checkpoint refusal with complete byte preservation; IPC loss/late observation/foreign child/counter overflow/limits; unrelated workspace progress; no public forged proof.

Evidence ladder: Node real pinned Effect + extracted actual functions and strict producer parsers first; final fresh independent CODE on coherent source; then exact saved contained auth-free Native probe with owned namespaces and pre-execution review, including real child/IO/task lifetime. Existing invalid-args Node child guard is not Native acceptance. Native/server/provider/private originals/production Main/GUI/Windows/power-loss remain unrun in this design phase. Final feature enablement additionally requires the accepted complete trusted inventory, effective mode compiler, root broker and bootstrap/recovery gates; no partial-source test can self-approve those.
