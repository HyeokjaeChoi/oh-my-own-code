# Packaged official event host integration — design1
2026-10-05. Initial runtime/package integration; full PRD v0.6 F01–18 and parent P7 storage-contract v5 unchanged. Capability experiment completed with independent code PASS: ../opencode-event-host-feasibility/execution/code-review.json. This design introduces a packaged adapter, not a provider-safe/nonfresh restart guarantee.

## Decision and alternatives
Criteria: actual persisted event payloads, original SDK compatibility, scoped owned lifetime, immutable local packaging, preserve existing startup/receipt safety, support current macOS arm64 acceptance without inventing Windows evidence. Stock CLI2.0.18/inspected2.0.22 omit event persistence option; upgrading alone does not solve required history. Patching/forking native CLI adds maintained upstream divergence. Embedded Promise server automatically resumes suspended sessions and violates the current preflight uncertainty boundary. Select official @opencode/server/process2.0.18 + effect4.0.0-rc.112 in fixed Bun1.4.2 child; no lifecycle or transform argument. Actual isolated HTTP persistence/normal/idle SIGKILL proof exists; the explicit managed continuity hook is skipped in pinned source when lifecycle absent. Neither fact proves nonfresh startup safe, so freshNativePreflight remains mandatory.

Full pinned closure is the first packaging form, accepting measured prototype416MiB dependencies plus59MiB engine cost. Bundling/pruning can lose dynamic native/WASM/migration resources; defer optimization until its own asset resolution proof. The desktop remains pnpm-managed. A separate non-workspace runtime resource package uses the exact verified standalone npm lock because it executes under Bun, not Electron's Node; it is never imported into desktop or renderer. This deliberately isolated resource build has a package-lock authority, not a second app workspace/manager. Copy the completed prototype package/lock as initial pinned input, retain version/integrity; no imports into docs/runs or scratch at runtime. No root server/effect dependency and no floating/global Bun.

## Host and parent protocol
Add trusted src/event-host-supervisor.mjs and src/event-host-child.mjs; isolated server/effect imports only in child after init validation. Export eventHostForResources(resources,platform,arch) descriptor for exact packaged paths. Existing startSidecar accepts additive eventHost option and delegates to new adapter when explicitly selected; old no-eventHost ephemeral CLI compatibility stays testable. Main and durable probe explicitly select descriptor. workbenchContext returns {client,session:undefined} in durable lane; service bootstrap creates the first native/app mapped session only after flushed registry reservation. Existing client/service/DTO/receipt/factory API stays unchanged.

Order: validate port/abort; owner.assertOwned nonce; require explicit preflight true before any setup/spawn; verify resources; allocate disposable profile disjoint from durable namespace; write owned config; recheck owner and preflight immediately before owner.markSpawnIntent/spawn; attach exit/error/IPC observers immediately; capture exact OS identity and recordChild BEFORE sending init or making API; only then send init. Spawn-gap/identity failure cannot start server through delayed IPC; retain owner uncertainty. Init closed object contains nonce, private random64hex password, canonical existing namespace paths/config and database, fixed app/runtime/server identity. Single init; malformed/wrong nonce/type/size fails. No secret stdout/stderr collection; ignore raw outputs. Ready IPC only port/PID/fixed versions/nonce, bounded timeout. Validate loopback0/assigned port and identity, authenticated server.info before connected. Caller uses timeout and redirect rejection. Existing durable path is used for database, profiles/cache/tmp stay disposable. namespace directories/manifest remain exclusively owned. Guard path setup with containment/symlink/hardlink checks; these are caller guards, not OS confinement.

Child uses official scoped Effect.start events.persist=true; password loopback127.0.0.1 port configured, explicit owned config/directory/database, config.project=false, models.fetch=false, update/share disabled and empty plugin/MCP/providers/instructions default with deny permissions. No pairing/PTY automatic handoff, lifecycle or managed startup replay. Existing host applies both baseline policy stages before/after agent/model selection; do not remove them. Product configuration/provider enablement is later full-product work, not automatically enabled by this runtime swap. Test APIs never invoke provider/tools/PTY/prompt.

## Stop and uncertainty
Parent retains exact ChildProcess exit Promise from spawn. Stop requests private nonce-scoped scope close, interrupts startup fiber and closes scope; bounded scope stop followed by forced owned handle SIGKILL only if needed, never arbitrary PID. Child observes direct JS ChildProcess/Bun handles before server imports. Any observation gap/live direct handle prevents clean stop/idle SIGKILL eligibility and reuse. Poll direct exact exit evidence within existing bounded deadline; no PID absence or delay-as-proof. Direct JS observation does not enumerate arbitrary OS/native descendants. Stop result existing {exited,forced,cleanup,recoveryPath?}; an engine exit alone must not authorize complete cleanup or owner clean release when child scope/descendant proof is uncertain. Retain disposable path plus durable namespace on uncertainty. Child error/IPC loss/request timeout/startup abort is recovery hold; rejection cannot silently become connected/clean. Drain service before engine stop, owner checkpoint/release only after required exact settled proof. SIGKILL acceptance is idle synthetic test only, not permission for queued operation replay or power-loss claim.

## Storage and migration
Keep openDurableManifest existing paths/version/storage generation; no implicit original CLI database migration/cutover. First deployment only fresh namespace, so explicit new server database location is admitted in fresh durable manifest before launch and bound consistently; incompatible existing native manifest must hold without touching bytes. Native metadata {operationId,originalRuntimeEpoch,appSessionId,workspaceId,digest} and lookupIdentity comparison remain exact. No DTO, registry/journal/checkpoint changes. Pending retained operations and nonfresh namespace always block native start, even zero retained. Synthetic controlled reopen can inject explicitly trusted preflight and exact parent-observed exit proof only in fixtures; report as synthetic, never production startup acceptance. Historical same-boot absent owner PID remains unverified. This increment cannot complete real normal restart requirements; next owner/startup work remains explicit.

## Acceptance and rollback
Host unit negatives exercise preflight zero setup/spawn, corrupt/target/version/resource drift, malformed/late/duplicate IPC, identity recording fence, wrong server PID/version, abort/IPC loss/timeouts, failed scope stop/descendant uncertainty, no duplicate bootstrap. Meaningful runtime probe consumes actual production helpers and actual packaged resources, fresh bootstrap then actual nonempty event history, exact transcript/mapping/digest before/after controlled normal/idleSIGKILL reopen, existing blocked pending/nonfresh preservation. Update captureProvenance and P7 scripts to identify whole actual host/resource closure; preserve stock CLI historical failure. Type/boundaries/lint/storage/renderer/build/bundle/macOSpackage/inspect and hidden UI refreshed at coherent new source. Separate independent code review and rendered judgement; no self approval. Rollback changes resource selection only for fresh stores; no reuse/migration of existing namespaces or fallback after uncertain new startup. No visible production Main, private stores/Documents/credentials, provider, external publication/signing/notarization. Windows and power loss unverified.
