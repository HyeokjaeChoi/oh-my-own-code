# Private prompt input digest supplement
Version: focused-input-r1
Status: proposed focused addition to accepted original OriginBinding.inputDigest; no implementation/activation until entry review.

Existing original operation digest, admission expectedRevision, policy/grant/saved/scope/preview domains and 1MiB permission canonical metadata limit remain unchanged. Existing OriginBinding already binds original key+digest, app/Native session, project/location and mode/inventory generations. This helper computes actual payload identity only, not original Main journal proof or authority. No public DTO/RPC/protocol changes in this phase.

Private pure export permissionPromptInputDigest(input) -> Digest. Exact input {sessionID:ID,text:string,delivery?:steer|queue,files?:{uri:string,name:string}[]}. sessionID uses existing validWireId. Text is well-formed Unicode, NUL-free, nonempty after trim, max32000 UTF-16 code units (current Main message.send bound), preserved without normalization/BOM/CRLF changes. A lone surrogate is refused consistently with accepted permission strings and current Native inbox safe projection, never silently replaced during hashing. No caller id/resume/model/Agent/prompt-extra or arbitrary inherited/accessor/Proxy/sparse/symbol/custom-prototype fields. Inspect descriptors and detach all fields synchronously before hashing.

Files when present contain 1..8 exact entries in original order; repeated names/content permitted, no sort/dedup. name is one nonempty checked filename segment, wellformed/NUL-free, <=2048 UTF-8 bytes and matches current workspace-file single-segment path grammar. uri is exact canonical ASCII data:<mime>;base64,<payload>. Allowed MIME text/plain,application/pdf,image/png,image/jpeg,image/gif,image/webp (current supported context list). Base64 must round-trip canonically, no whitespace, URI/path/URL fallback or reopening original path. Decoded text bytes <=65536, each other file <=8388608, aggregate decoded files <=16777216; empty file bytes permitted. Reject overbudget before decoding/allocating an unbounded Buffer, encoded payload <=ceil(per-file-limit/3)*4. Processing is synchronous and bounded by existing context limits, and never persists or logs raw URI/text. It is NOT image signature/renderer/Native prepared-output validation; checked host cache already owns original bytes.

Compute compact exact metadata body:
{version:1,kind:'prompt',sessionID,text:{bytes:UTF8Length(text),digest:SHA256(UTF8(text))},delivery:{present:hasOwn(input,'delivery'),value:input.delivery??'steer'},files:{present:hasOwn(input,'files'),items:[{name,mime,bytes:decodedLength,uriDigest:SHA256(ASCII(exact uri))}]}}. Original file order and explicit field presence are bound. text/uri are hashed exactly; no content normalization or substitution.
inputDigest = SHA256(UTF8('omoc.permission.input.v1\n' + permissionCanonicalJSON(metadataBody))). Use existing canonical JSON only for compact metadata body; never raise its 1MiB limit or feed full data URI through it. Implement the new domain locally in this dedicated helper; do not broaden existing domain allowlist or change original digest functions. Export only digest, no raw/metadata result or reusable authority handle. Filename metadata stays in memory; only resulting inputDigest belongs in existing OriginBinding.

Alternatives: raw prompt canonicalization would exceed existing1MiB with supported attachments and is rejected; increasing global canonical limit broadens control/journal budget and is rejected; hashing only decoded file bytes would miss exact MIME/URI/presence/order/name changes and is rejected. Compact leaf hashes keep current control bound and all actual submission fields without retaining content.

Future consumer (NOT this phase): authenticated trusted Main submit adapter must verify durable original native.send intent before request; fixed Native entry recomputes this digest against same detached actual payload and exact admitted session/mode/inventory; generate genuine Native messageID and bind before reconcile/preparation/revert/admission/wake. Original raw public SDK sends stay denied without private scope. Main and Native must consume exact helper bytes in coherent resource closure. Native may transform images during preparation, so stored/prepared output is not used to reconstruct raw inputDigest; genuine generated inbox ID and immutable original binding carry correlation. A digest cannot establish current Agent/model/inventory/root/settlement, and this helper cannot enable execution. No guessed native IDs, firstHTTP/origincreation metadata or nonce-as-proof.

Tests require meaningful missing-helper RED, independent known digest vector/domain formula, optional presence changes, ordered files, BOM/CRLF/Unicode, each field mutation, hostile structures without getter/Proxy invocation, exact boundary text/file/count/aggregate, canonicalbase64 including empty bytes and malformed padding, nativeFileURI versus arbitrary URL refusal, original input unchanged. Node only; no Native/Bun/Electron/build/provider.
