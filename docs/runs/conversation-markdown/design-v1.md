# F05 Markdown/code/copy design
Version: 1 · 2026-10-09

## Existing boundary and alternatives
The existing external assistant-ui runtime consumes mapMessages from the window store. It caps one text part per message at65536 characters and300messages, and displays tool parts through validated Tool UI or an escaped generic fallback. This remains the only message projection/authority. Current Text renderer prints literal divs. The approved workbench UX already requires assistant-ui Markdown/code; the ADR prohibits second stores/styling engines and incidental stack upgrades.
Options: (A) extend official assistant-ui MarkdownTextPrimitive, reusing active part context, memoization and code-header hooks; (B) direct react-markdown with a separate text adapter, duplicating integration; (C) write a Markdown parser, adding unnecessary parser/security maintenance; (D) copy latest registry component, importing Tailwind/shadcn/current-stack assumptions. Choose A with app-owned token CSS and native buttons. Do not install a registry template or syntax highlighter.

## Content, streaming and privacy
Only assistant text becomes Markdown; user input remains literal. Use MarkdownTextPrimitive in MessagePrimitive.Parts Text context, stable smooth=false (no fabricated reveal) and defer=true. Memoized components/remark plugins stay stable. Do not preprocess/rewrite canonical text. Support ordinary headings, emphasis, quote, list, table, disabled task list, inline/fenced code. Fences show plain selectable code and a language label; no evaluation, Mermaid, remote highlighter, interactive embedded component or automatic run.
Use react-markdown's default escaped raw-HTML behavior; no rehype-raw, unsafe HTML renderer, URL override or raw DOM injection. Ordinary Markdown links render inert label plus full selectable destination. Images render an inert alt label without src/href/network loading. Link/image callbacks accept semantic data only and never spread untrusted node props onto DOM. No Markdown anchor navigation, shell.openExternal, credential/provider request or new bridge API. Raw HTML such as <script> must remain visible as escaped text, preserving the existing security regression. GFM checkbox inputs are disabled and never mutate app state. Browser resource monitoring plus DOM assertions must prove no remote requests/images/frames/unsafe hrefs for malicious input.

## Copy semantics and lifecycle
Native buttons: '코드 복사' per fence and '표시된 메시지 복사' per text part (mapMessages currently produces exactly one). The latter copies displayed projected Markdown source, including any explicit truncation marker, not unbounded Native history. Code copy uses the primitive's displayed code value after Markdown newline handling, not a byte-exact original file. No automatic copy/read clipboard. Copy available even when mutation authority is held, because it only exports already visible text on an explicit click.
Before calling navigator.clipboard.writeText capture the clicked immutable text; block repeated pending clicks. Pending -> success only after resolved promise; absent API/synchronous throw/rejection -> visible error. Status region role=status, concise Korean pending/success/error. Text change, message/scope replacement and unmount invalidate pending status ownership; an already started clipboard write cannot be cancelled and must not be described as cancelled. Conversation is already keyed by workspace/session; message-part copy state is local and resets when its source text changes. Late promises cannot mark a different message copied. Prefer no success timers; reset on next text/copy. No history/persistence of copied content.

## Layout and accessibility
Existing tokens/CSS Modules and visible native button focus/hit targets. Preserve text selection, composer/permissions/tool controls. Markdown prose wraps; code and wide tables have their own labelled horizontal scroll surfaces and do not widen the workbench. Buttons wrap beside labels; hover is not required. Language is plain escaped text; unknown language has a generic code label. Both themes, Korean/Latin/unbroken paths, narrow320/760 and200% zoom get native captures. Keyboard Enter/Space, Tab/ShiftTab and scrollable code remain usable. Streaming text is not an aria-live token stream; only copy status announces changes. No optimistic execution statuses.

## Validation and reversibility
Meaningful SSR RED on the actual Conversation, then GREEN for formatting, exact code text, escaped HTML, inert links/images, disabled task input, literal usertext and unchanged safe tool fallback. Hidden Electron uses the production renderer/preload and existing synthetic main, controlled navigator.clipboard promises (does not touch user's OS clipboard), all clipboard lifecycle cases and session/text replacement. Track any network request and actual mutation/effect counters, native PNG/fullviewport/visibility/focus/exit provenance. Existing Node projection/store regressions preserved. Remove the new Markdown component/dependencies to return literal display without data migration; no journal/store schema changes.
