The strongest conclusion is structural: smaller glyphs and metadata can coexist with normal input text and real target area. The current128px composer can lose reserved blank height, inner visual separation and stretched selectors before any aggressive text reduction. A complete compact design must specify where the agent/model context goes when width is scarce.

The second conclusion is semantic. A completed tool disclosure and a pending permission request should have different visual weight. Permission scope, the consequences of rejection, stale authority and unknown effects remain explicit. Reference demos are examples of presentation, not authority to alter the product's actions.

The third conclusion is provenance. Dark logged-out ChatGPT, historical companion imagery, native Claude onboarding, guide recommendations, an owned Figma file, public component demos and authenticated product screens are different kinds of evidence. Only the first six were available here. The three candidates are original proposals using these lessons; none is described as a faithful Claude/ChatGPT desktop reproduction.

The proposed source hierarchy is one common Primitive → Semantic → Component graph plus independent candidate overrides. Code preserves its system-first stack and white/neutral identity. The later actual Figma draft uses explicit Noto Sans KR/IBM Plex Mono representation mapping and verified available font styles; this is not a claim of glyph parity or bidirectional synchronization. Recommendation and migration details are in [design-plan.md](design-plan.md).
