## Bounded lessons for synthesis (inference from observed geometry)

- Candidate density can start from 13–14px navigation labels,16px glyphs,32px rows/toolbar targets,6–8px gaps. These references support smaller glyphs without discarding target area; coordinator decides exact product targets/accessibility.
- Composer should be one shared surface: conditional attachment strip, flexible input, aligned action row; model/context controls use small neutral labels and disclose detail. Separate input borders inside another enclosing composer produce more visual chrome than observed reference.
- Distinguish routine tool activity from consequential approval. Routine completed tool calls can be compact disclosure rows/chips; permission needs explicit scope/actions and a stable readable card. Retain product permission contract regardless of this illustrative card's labels.
- Sidebar grouping, modest row height, fine edges and selective hover/active backgrounds can carry hierarchy without large icons, repeated boxed sections or universal shadows.
- Preserve assistant-ui runtime/state primitives and existing Tool UI + CSS Modules architecture. Canonical composer docs explicitly allow custom restyling using ComposerPrimitive.Root/Input/AddAttachment/Send/Cancel and compact mode for one-line inputs with no attachments/quote/queue/dictation. No source copying or kit installation needed to adopt measured rhythm; token translation would be future authorized implementation.
- Treat broad shadcn examples as source evidence, not a wholesale replacement foundation. Current variant mismatch and source-copy maintenance remain architecture considerations.
