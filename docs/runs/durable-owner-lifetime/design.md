# Exact lifetime witness — design2

## Requirement and evidence boundary

Storage-contract v5 requires the exact prior app and recorded child to have exited before takeover; cleanShutdown does not bypass that condition. The current OS adapter captures birth/boot identities but cannot infer historical same-boot exit from PID absence. Existing controlled Native reopens inject parent-observed exits and are not standalone production proof. This design supplies an actual kernel event observed while the exact process is registered. Supplemental prior research at durable-workbench-storage/execution/p7-kqueue-lifetime-research.py established the local NOTE_EXIT primitive only.

The helper observes processes. It cannot execute Native work, kill processes, acquire/release the store singleton, write journal/owner/native/project files or migrate data. Keep Native startup and lifetime verification separate. Main still denies nonfresh Native startup through freshNativePreflight, even if lifetime witness succeeds.

## Closed identities and context

Keep owner.json v5 and the public owner handle unchanged. Add optional `lifetimeWitness` to `createStorageOwner` injection only. Context passed to that dependency is closed: `{root, rootIdentity, ownerNonce, role:'app'|'child', identity:{pid,platform,bootId,startToken}}`. Canonical paths and device/inode belong to the host; nonce binds the owner generation and is not an OS identity. The existing startToken algorithm must match the helper's libproc start seconds/microseconds computation exactly; freeze it before implementation. A helper-reported PID/birth is never accepted without host equality before/after registration.

Dependency methods: `register(context)` returns a closed `ready` or `recovery_required` result after a durable attach acknowledgement; `verify({...context,expectedRegistrations:{app,child:null|identity}})` returns `exited`, `unverified` or `identity_conflict`; `closeRegistration(ownerNonce)` seals admission of new registrations but is not process exit proof. Only verify has the additional required full owner-registration set. Owner passes both exact identities from the SAME previously validated owner record snapshot, never from helper discovery or separate role results. Context app must equal expectedRegistrations.app; selected role identity must equal its corresponding expected registration. Terminal membership and both registration/exit identities must exactly equal this full set, including child absence. Each verify reads/validates the entire set; owner rechecks the same old record and kernel before grant. No role-result cache can combine different file snapshots. No call may search arbitrary generations solely by PID. Preserve the existing processVerifier for live identity and direct in-process owned exits; a historical unverified result may be supplemented only with a fully validated context-matched witness exit.

## Registration and owner linearization

App: acquire same canonical kernel singleton, validate old record and proofs, capture new app identity and fresh nonce, attach/verify/flush app registration, then persist new owner candidate and publish ready. Registration failure cannot publish ready. An app crash before new owner publication leaves no granted write authority.

Child: flushed spawn intent, owned spawn, exact identity capture, attach/verify/flush child registration, then recordChild publication, then init/server API. No server init while attach is pending. If capture, registration or recordChild fails, stop only the exact owned child handle and preserve uncertainty. A historical spawnIntent with child=null remains blocked even if a helper directory contains a candidate identity.

Exit: helper reads a matching NOTE_EXIT event from its registered kqueue and publishes the exit fact for that identity. EOF, IPC disconnect, registration ACK, owner release or absence/replacement PID are not exit events. Exit before acknowledged registration must fail closed. App exit closes further registrations; finalize only after all actually registered lifetimes exit and their immutable proofs have been flushed. A registered child still alive keeps its own proof missing; do not kill it or seal a success. If deadline expires, preserve incomplete evidence and exit helper with failure.

New acquisition: kernel held, valid unchanged owner record/root, complete context-matched registration+exit+terminal evidence for each required app/child, then reuse existing owner acquisition logic. Keep live/unverified identity results dominant over contradictory files. Never amend missing owner fields or silently recreate the owner record.

## Files and integrity

Evidence lives under private canonical durable root in a separate `lifetime-witness-v1/<ownerNonce>/` generation. It is never an app journal variant. A manifest binds schema, root/rootIdentity, nonce and exact app/child registrations; immutable exit records bind role and exact identity. A terminal record binds all registered identities and their record hashes. Final schema/checksum algorithm and filename set must be frozen before writes.

Require owned directories mode0700 and regular owned single-link files mode0600, bounded size, no symlink/hardlink or path escapes, same opened descriptor/path identity during reads. Use exclusive creation, file flush and directory flush before ACK or helper publication. Reject unknown fields, unknown version, duplicates, extra generations selected by PID, malformed content, missing required exit/terminal and current verification flush uncertainty. Checksums detect corruption, not hostile same-user authenticity. Failed bytes remain preserved. Helper may open only the descriptor for its own generation and must not read/write owner.json or Native database.

Historical proof acceptance does NOT infer the previous helper's fsync success or a registration ACK from surviving bytes. These files describe immutable kernel lifetime facts, never app/native effects or journal success. Under the currently held store kernel, verifier may accept complete exact context-matched registration/exit/terminal bytes only after opening the same checked single-link files for sync (O_RDWR|O_NOFOLLOW), successfully fsyncing each file and generation directory, then rereading the full identical file/inode/path set and the unchanged owner snapshot. It writes no content, checksum or success marker, never repairs partial records. A terminal fully written before prior file/directory flush failure or helper death can be accepted by this present verification; missing/partial terminal and any current file/directory sync or second-snapshot drift remain unverified. This explicit lifetime-fact policy is independent of journal unconfirmed-tail/effect rules and does not adopt any app operation or authorize Native startup. A new process repeats this policy without prior witness memory.

At most 64 retained generation directories and 4MiB total witness records per store. A full bound blocks new ownership instead of deleting unresolved evidence. Do not add automatic garbage collection in this increment. Parent verifies exact packaged executable identity before helper spawn; helper self-checks protocol/target and context, captures current boot/birth via OS APIs, and rejects unsupported targets.

## Lifetime, failure and packaging

The helper must outlive the observed app without acquiring executor authority. Avoid inherited Electron/Native/config secrets: minimal explicit environment, no shell and no stdout of raw errors/paths. Use a bounded private IPC channel. Parent attaches exact helper ChildProcess listeners immediately. Registration deadlines are bounded; any IPC loss/invalid payload retains owner uncertainty. Parent may stop its own helper before granting authority on startup failure; after successful app attachment the helper needs to observe app exit and finalize its generation independently. Helper termination alone cannot release store data for cleanup.

Build the tiny C helper locally for the native macOS architecture using the available platform toolchain; no runtime compiler/system Python dependency and no download/installer hooks. Record source/compiler target and exact executable SHA in a closed resource manifest and coherent build/package provenance. Production loads only packaged bytes. Unsupported OS/architecture remains explicit owner_unverified/unsupported capability, never macOS substitution. The helper's own historical exit proof is not recursively required to take over: it has only old-generation evidence authority, not store mutation or singleton authority. Actual helper exit and leak behavior are separately verified in saved probes.

## Frozen implementation protocol v1

The initial implementation owns `native/owner-lifetime/witness.c`, `scripts/stage-owner-lifetime.mjs`, `src/host/owner-lifetime.mjs` and their matching tests. Main integrates existing build/provenance/resource/Main and saved-probe consumers after their bytes are frozen. No DTO, registry, journal format or owner record change.

Context file `context.json` is one UTF-8 JSON line in this exact key order: `{version:1,root,rootIdentity,ownerNonce,app}`. `app` has the existing ordered identity keys pid/platform/bootId/startToken. SHA256 covers the entire file including its final newline. Root is canonical absolute; rootIdentity is decimal device:inode; nonce is a UUID. The helper never parses arbitrary JSON or paths: host creates this closed file, passes its SHA plus inherited generation directory fd3 and canonical store directory fd4. Helper checks both descriptors, uid/modes, directory inode, context regular single-link file and exact SHA. fd4 is used only for fstat, never file access. Host checks descriptor/path identity on every verification. Generation directory name must equal nonce; only context and the fixed proof filenames below are allowed (no runtime socket).

Helper command arguments are fixed `--v1 <appPid> <bootHash> <startHash> <contextSHA> <rootDev> <rootIno>`. All hashes are lowercase SHA256 hex. It samples `kern.bootsessionuuid` via sysctlbyname and libproc PROC_PIDTBSDINFO start seconds:microseconds. The text is exactly the current OS adapter's unmodified boot UUID and decimal `seconds:microseconds`; SHA256 must equal both supplied hashes. It attaches NOTE_EXIT with EV_RECEIPT: success requires the matching receipt with EV_ERROR and data==0; nonzero data, absent/wrong receipt or syscall failure reject registration. Repeat the full sample and poll for an early exit before committing registration. A pending exit during registration causes conservative attach failure. Identity drift never retries attachment at that PID.

Private stdin control is ASCII LF lines of at most 256 bytes: `CHILD\t<pid>\t<bootHash>\t<startHash>\n` once, or `SEAL\n` once. At most one child, no equal app PID, no second child or control after seal. Both helpers and adapter reject invalid/oversized frames; no generated secret, model text or raw errors pass through these pipes. stdout is only `READY\tapp|child\t<registrationSHA>\n` or `FAILED\n`; each ACK follows durable proof file and directory flush. Parent validates exact expected record and ACK hash, plus exact helper identity before/after. stderr is discarded. Private inherited pipes are not a public network endpoint. EOF seals registrations but is never exit proof; app NOTE_EXIT also seals. Ignore SIGPIPE so lost parent output cannot prevent observation.

Proof files `app.registration`, `child.registration`, `app.exit`, `child.exit` each contain exactly one ASCII line: `V1\t<registration|exit>\t<app|child>\t<pid>\t<bootHash>\t<startHash>\t<contextSHA>\n`. Only a matching kevent for the attached identity can write exit. Helper stores registration identity in memory; it never samples/rebinds an exited PID. `terminal` is exactly `V1\tterminal\t<contextSHA>\t<appRegistrationSHA>\t<appExitSHA>\t<childRegistrationSHA|->\t<childExitSHA|->\n`. It is written only after app exit, sealed admissions and every accepted registration's exit. A registered child still alive 15 seconds after app exit causes failure without terminal; the deadline uses monotonic time. While app lives the observer remains live. No extra files/fields accepted; each file has a 4096-byte maximum. Exclusive creation, fsync(file), fsync(generation) precede ACK or terminal acceptance. Partial publication keeps bytes and rejects verification.

Host API is `createLifetimeWitness({resourcesPath,platform?,arch?,processIdentity?,spawn?,io?,deadlineMs?})`. Only Main/test setup constructs it; default platform/arch actual, deadline capped to bounded registration time. `register(context)` returns the existing ready/recovery_required result, not identities or paths. App registration creates exactly one helper and generation, child registration uses that same helper after full contextual equality. `verify({...context,expectedRegistrations})` performs the full-set/context/current-sync/double-snapshot policy above and returns `exited` only for exact complete terminal proof, otherwise `unverified` or `identity_conflict`. `closeRegistration(ownerNonce)` sends SEAL and returns ready/recovery; it cannot write an exit fact. Adapter owns no journal/owner content writes. Supported production target is darwin-arm64; other targets return recovery_required owner_unverified before helper spawn. Injected adapters/IO are unit-only, never selected by persisted data.

Owner acquisition first obtains live verifier result. `exited` is already authoritative; `alive` or `identity_conflict` never uses supplemental proofs. Only `unverified` may use `lifetimeWitness.verify` with old root/rootIdentity/nonce/role/identity and expectedRegistrations from the same unchanged old record. Fresh app `register` must return ready before candidate persist. Child `register` must return ready before recordChild persist; later host init continues to wait for recordChild. Both call sites recheck kernel/root/record authority after the awaited registration before publication, because registration is asynchronous. Missing child in spawnIntent never consults unrecorded helper identities. Witness omitted preserves old behavior for legacy fixtures/unsupported platforms; production macOS always supplies it. Store release seals registrations before kernel release and remains independently gated on actual child exit. Terminal verification requires optional child proof presence to match the owner record exactly.

Resource tree `owner-lifetime/darwin-arm64/{witness,manifest.json}` is separate from event-host resources. Manifest is closed `{version:1,platform:'darwin',arch:'arm64',sourceSha256,compiler,target,executableSha256}`; source/compiler/target recorded by build, no runtime download or compile. Verify executable regular single-link owned/non-writable-by-group/others, matching manifest/hash and packaged provenance before spawn. A replaced or unsupported resource yields zero spawn. Staging uses available `/usr/bin/clang` and explicit native target, with bounded output; package inspector and build provenance include both files. Test harness cannot accept globally installed binaries.

## Rejected alternatives and rollback

PID absence, lock age, heartbeat expiry and replacement process checks violate the exact lifetime contract. Clean-marker bypass cannot establish app exit. A hidden inspector that reads owner.json inside `inspect(expected)` loses nonce/generation binding. A launch broker would add executor/descendant ownership and is unnecessary for this bounded observer; registration gaps remain conservative holds. Storing proofs in the journal gives a released helper writer authority and is rejected.

Rollback disables witness consumption and preserves all original records/evidence. Old stores with no witness remain held. Never rewrite owner.json version5, Native tables or app journal to make rollback launch. No automatic Native replay or migration is introduced.

## Acceptance probes

Unit negatives cover context drift, concurrent registers, wrong/duplicate roles, pre/post attach identity drift, note errors, IPC tampering/timeouts, registration/exit/terminal flush failure, proof corruption/partial files, unsupported versions/targets, live child, spawn gap, replay from another generation, max bounds and failed helper startup. Owner assertions show zero journal/native effects before acknowledged app/child registration and no adoption of partial proof.

Design2 closes independent findings D1/D2: full expected app/child input and one complete snapshot per verify; surviving complete terminal reflush policy with current flush/double-read failure hold. Tests include absent/extra/replaced child, a fresh adapter for app-only and app+child proofs, role calls across changed files, complete terminal followed by failed prior file/directory sync or helper exit, and failed present sync or snapshot recheck. This is a refinement of the accepted plan1 W1-W5, not additional product/runtime scope.

Saved zero-window Native test launches one real owner app, verifies actual ACK, exits normally or by its owned SIGKILL, waits for the independent witness to finalize, then launches a separate app with production verifier and no injected `ownedExited`. Exact app/child evidence must be consumed. Also test missing/incomplete witness and live child denial with byte preservation. This is real OS lifetime/reacquisition evidence only; all Native nonfresh startup remains blocked and no provider or private-store access occurs.
