# Read and mutation interoperability amendment
Version: 3 | Date: 2026-10-03
Extends frontend-architecture-redesign architecture-and-ui v4 without changing platform or product scope.

## Closed wire and authority
Use one closed v2 envelope at desktop:v2:workbench: `{version:2, runtimeEpoch?, readId?, operationId?, expectedRevision?, operation}`. `operation` is the existing exact typed WorkbenchRequest plus read-only operation.lookup. All reads require bounded opaque readId; bootstrap snapshot alone may omit runtimeEpoch to discover it. Every mutation requires operationId and the current host runtimeEpoch, with no readId. expectedRevision is optional nonnegative safe integer and rejects a stale mutation before dispatch. IDs are 1–128 ASCII word/dot/colon/hyphen characters; envelope and operation reject unknown fields, invalid prototypes and nested values outside the operation DTO. Native permission requestId and legacy send/lifecycle requestId stay explicitly distinct; renderer creates operationId once per intent. Snapshots carry runtimeEpoch and trustRevision on workspaces. Bootstrap cannot authorize a mutation until identity arrives.
Main validates approved sender AND frame before parsing/admission; supplies sender scope into service. Renderer cannot set sender. Cancel uses closed v2 `{version:2,runtimeEpoch,readId}` on desktop:v2:cancel-read; cancellation applies only to an admitted read with matching sender, ID and epoch. Sender close cancels its reads; service close invalidates the namespace and aborts owned work. Remove production v1 wire admission atomically; trusted service-only legacy adapters for existing unit fixtures cannot remain a renderer bypass.

## Bounded reads and actual SDK work
10,000ms whole-read deadline starts at admission and covers ready, validation, aggregate reads and SDK calls. Four logical classes each admit one underlying logical identity: snapshot (includes diagnostics), catalog, files, reserved local receipt lookup. Identical sender+epoch+operation scope coalesces with independent read subscribers/deadlines; each logical class has at most8 admitted subscribers (32 across all four classes, with lookup8 reserved). Exceeding subscriber capacity returns READ_BUSY with no queue. Active `(sender,epoch,readId)` has immutable scope: same ID/same scope returns the same subscriber promise without allocation, changed scope rejects INVALID_REQUEST. Underlying task deadline is10s from its first admission and never extends on joins; subscriber deadline cannot outlive it. A cancelled/expired subscriber detaches only itself; abort the shared underlying signal only when the last subscriber detaches, the original task deadline expires or the service/sender tears down. Quarantined/aborted/expired tasks accept no new subscribers until actual completion/proven teardown; any different identity in an occupied class fails READ_BUSY without a queue. Each class has at most one actual nested SDK call in flight; rewrite existing five-way refresh/catalog fan-out into sequential deadline-aware calls. Actual SDK capacity is service-wide maximum4: one sequential call each for snapshot/catalog/files plus one shared startup-or-mutation SDK lane. Every nested SDK call passes this limiter; no pending SDK queue. Startup holds the shared lane only while its actual call runs. A separate service-wide mutation admission slot (capacity1) bounds the entire mutation intent, including ready/dialog waits, without holding an SDK slot while awaiting startup. Mutation validation/admission refusal before any effect is definitive; refusal after an earlier effect is unknown unless exact evidence proves otherwise.
Subscriber cancellation or deadline settles its renderer-facing wait and detaches it under the preceding shared-task rules. Shared-task termination aborts its own signal. If underlying SDK/files/ready ignores abort, quarantine occupied class/lane until actual promise completion or proven process teardown. Promise.race alone never releases real capacity. Track logical subscriber lifetime separately from actual task lifetime; drop late responses and prevent late host projection changes after expiry. Aggregate failures do not spawn leftover siblings. Ready is one service-owned startup task, never owned/cancelled by read subscribers. Its bounded SDK calls share the startup/mutation lane and its own10s startup budget. Cancelling/expiring a read detaches only that read; startup may finish its own authoritative initialization independently. Expired read aggregates cannot commit their projections; service-owned startup commits are distinct and require its live scope. A never-settling ready allows at most one admitted mutation waiter. A mutation has10s ready-wait budget: if it expires before effect, mark receipt effect:none and forbid late dispatch when ready eventually settles. No unregistered mutation waits for ready. After effects start, logical timeout does not release mutation admission/SDK actual capacity; quarantine until actual completion/proven teardown. Lookup reads host-local ledger, independent of ready/runtime/SDK lane, available under exhausted snapshot/catalog/files. No generic resource cache or hidden unbounded queue.

## All mutation admission and receipts
Order is validate sender/envelope/epoch → check immutable identity/digest → synchronously reserve ledger record and service-wide mutation admission slot → await ready within budget → revalidate live identity/revision/scope → dispatch. An exact duplicate/conflict is answered immediately even while ready is pending. A occupied mutation admission slot rejects another identity without queuing. Before any dialog/files/native/metadata effect, register `(runtimeEpoch,operationId)` with immutable operation type, workspace/session scope, canonical sorted input digest and admission. Check existing identity before dispatch; exact match returns stored receipt/result, changed digest returns DUPLICATE_CONFLICT without effect. Maximum 2,048 records; do not evict records/tombstones to admit new work. Existing 256 per-session send limit remains. Store no prompts, arguments, paths or credentials in exposed receipts; digest is private host metadata.
Receipt fields: `{runtimeEpoch,operationId,type,workspaceId?,sessionId?,admission:'rejected'|'admitted'|'dispatched',delivery:'pending'|'accepted'|'unknown',effect:'none'|'pending'|'confirmed'|'failed'|'unknown',revision,evidence:[{kind,id?}],result?}`. Receipt result is a CLOSED evidence-only union: `{kind:'created',workspaceId,sessionId?,nativeSessionId?}`, `{kind:'forked',workspaceId,sessionId,nativeSessionId}`, `{kind:'removed',workspaceId,removedSessionIds?:string[],workspaceRemoved:boolean}`, `{kind:'metadata',workspaceId,sessionId}`, `{kind:'delivery',nativeInboxId?:string,nativeRequestId?:string,status:'accepted'|'stopping'|'decided'}`, or `{kind:'rejected',code:fixedErrorCode}`. Limit arrays to200 and evidence to8 bounded IDs. No snapshot, title, transcript, permission detail, tool input/output, prompt, path, argument or raw error is stored/exposed in a receipt. Normal first mutation responses preserve their existing allowlisted value DTO and add a SEPARATE receipt field. Duplicate returns only `{ok:true,value:{status:'duplicate'},receipt}`; refresh uses separate bounded snapshot. Lookup returns redacted receipt only; renderer reconciles created/removed/delivery evidence by ID and separately refreshes view. A host late result projects into the same closed evidence union, never stores the original snapshot. Exact lookup request is a READ envelope with current host runtimeEpoch/readId and `operation:{type:"operation.lookup",runtimeEpoch:targetReceiptEpoch,operationId:targetOperationId}`; envelope has no mutation operationId. The nested runtimeEpoch selects the immutable receipt key, distinct from the current transport epoch. Closed lookup value union is `{status:"found",runtimeEpoch:targetReceiptEpoch,operationId:targetOperationId,receipt:RedactedReceipt}` or `{status:"missing"|"wrong_epoch",runtimeEpoch:targetReceiptEpoch,operationId:targetOperationId,effect:"unknown"}`. No type/admission/evidence is fabricated for absent records. P4 returns wrong_epoch for a target epoch it does not own; P7 may return found only after validating that exact retained journal key. Neither missing nor wrong_epoch establishes no effect. Receipt response accompanies normal mutation result; duplicate does not run operation. Pre-dispatch validation/refusal may prove none; an error after a dispatched effect is conservatively unknown unless operation-specific evidence proves failed/confirmed.
Host metadata result/revision and exact target removal establish their effects. Native create/fork result ID, send/command inbox ID, interrupt acknowledgement, permission reply bound to native request establish acceptance only where applicable. Accepted request or interrupt/reply never claims execution/tool completion. Existing idle/title/absence/time observations cannot resolve unknown dispatch. A late renderer response cannot apply to an expired renderer generation. A still-live host epoch and original operation scope may finish that SAME admitted mutation’s authoritative registry/effect commit and redacted receipt with correlated evidence, even after the renderer stops waiting. This is required for delayed native create/fork registration and subsequent bounded snapshots. A retired host scope/removed identity cannot be resurrected, and no new mutation is dispatched as recovery. Late read projections remain forbidden; host mutation finalization is distinct from read/renderer projection acceptance. Runtime-lifetime receipts remain explicitly temporary until P7 journal recovery lands. New epoch alone does not clear unknown intent.

## Renderer ownership and lifecycle
shared transport owns bounded waits, envelope generation, read cancellation/coalescing and late-response drop; it holds no file/catalog payload cache. Controller only schedules and writes explicit events to window Zustand vanilla store in entities/workbench/model with public root API. Store owns canonical runtime/lists/catalog/resources/operations/drafts/selection/layout; Context injects stable window API and Zustand React selectors subscribe. Pure transitions validate epoch, selection generation and revision before atomic snapshot+health commit. Receipt reconciliation is operation-scoped, independent of navigation. No process singleton, broad persist middleware, unrestricted feature setState or duplicated hook/ref canonical owner. assistant-ui derives transcript and composer from the same store; local menu/search/rename may remain React state.
Mutation intent is retained before send. Timeout/disconnect marks unknown and does bounded operation.lookup only, never automatic mutation retry. Preserve original draft and later edits. Clear only matching submitted draft revision after correlated authoritative acceptance; confirmed session/workspace removal clears only target drafts and reconciles current selection even A-B-A. Unknown operations stay blocked across epoch change until host-controlled recovery; unrelated successful reads cannot clear them.
Resource identity is epoch/workspace/trustRevision/path/kind/generation. Reopen always reads; selecting another file clears old preview first; manual refresh covers listing and current preview. Known mutation effects invalidate visible resources; refocus and visible connected five-second single-flight timer revalidate with the same bounded transport. Stop timer hidden/disconnected/disposed. Retained text is labelled checking/last-observed; failed/deleted reads become stale or clear content. Generation changes reject late A-B-A replies. Sole store owns bounded visible payloads, with no reopen history cache. This is observation freshness, not file-write conflict safety.
