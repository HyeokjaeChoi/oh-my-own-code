# Safe-start API analysis, not runtime acceptance

2026-10-07, Main static inspection of exact installed packaged @opencode/core/server2.0.18. No production preflight change or Native process invocation in this analysis. Current original/nonfresh store remains held. Registry idleness is not Native inbox/execution authority.

## Actual useful public surfaces

- server/process.js start(options,lifecycle?,transform?) installs SessionRestart.resumeSuspendedSessions only when lifecycle is supplied. Current event-host-child passes only options. This is insufficient by itself: createRoutes builds transitive service layers and starts V1Migration.layer.
- core/database/database configured/ configuredClient always uses databaseLayer, which changes PRAGMAs/checkpoints and applies migrations. Do not label that layer read-only or run it as the preflight.
- core/database/sqlite.bun public sqliteLayer accepts readonly, readwrite, create, disableWAL. Its nativeLayer opens Bun SQLite with those flags and omits journal_mode when disableWAL=true.
- core/database/drizzle public EffectDrizzleSqlite.makeWithDefaults accepts generic SqlClient. It can build the official query object without Database.layer's migration/tuning effects. Database.Service is public; a separately reviewed read-only provider can supply this query object without table introspection or handwritten Native SQL.
- core/session/store exposes SessionStore.node/Service.list/get/listSuspended. listSuspended explicitly covers top-level surviving execution claims; jobs are separate.
- core/session/inbox publicly exports list(db,sessionID), an actual official pending inbox read. Use its public API and bounded global SessionStore listing, not transcript/idle heuristics. Do not construct the executor or call promote/admit/cancel/delivered APIs.
- core/job public Job.make/pendingBackground reads durable recoverable jobs through KV; inspect dependencies before using. All markers, not only running jobs, matter because restart can deliver completed results. These APIs do not establish orphan session/inbox absence without complete bounded enumeration.

## Unresolved next proof

A preflight-only packaged process could instantiate ONLY readonly SqlClient+official Drizzle+SessionStore/KV/Job read providers and official Inbox.list. No ServerProcess, provider/client credentials, permissions, executor, migration, event publication, model fetch or shell. It must verify complete global bounded enumeration, no suspended claims, inbox entries or background markers and exact session mappings. Freshness/owner/resource/source hashes must bind decision to the subsequent startup; existing lifecycle omission remains required. Before/after original DB/WAL/SHM identities/bytes must prove current bounded read did not write or create auxiliary state; SQLite readonly WAL behavior and malformed/unsupported schema fail closed. No app-written SQL/table introspection/adoption.

This is a candidate architecture, not an approved implementation or safe-start claim. Verify actual official layer dependencies, readonly behavior and production-compatible pending state with saved contained tests before final judgment. The existing contract explicitly allows an honest dependency hold if safe capability/provider compatibility cannot be proved without unauthorized private/authentication access. Never promote the current authentication-free synthetic reopen override into production authority.

## Further static closure findings

- Public SessionStore.node is a LayerNode.Provider, not a bare exported layer. Public LayerNode.compile supports replacements resolved before acquisition; Database.node.replace(closed readonly Database.Service layer) can replace its entire default dependency graph. Do not access private symbols or construct Database.layer. Compose only SessionStore.node and KV.node and replace Database.node using the official utility API. Job.make has Scope/KV only, but pendingBackground filters malformed entries; an empty returned list is not complete malformed-marker absence. Conservatively require KV.scan({prefix:"",limit:1}) to have zero entries, otherwise hold without exposing contents.
- SessionStore.list({limit:201}) covers all locations. Public listSuspended filters only parent_id null; Info intentionally omits time_suspended. Background subagent children have parentID, whereas official Session.fork projector sets parent_id null and fork_session_id to its parent. A conservative candidate can reject ANY parentID session, then listSuspended covers every remaining global session. This reduces supported clean stores rather than treating missing child claims as safe. Exact bounded global session mapping is still required, and any extra/unmapped session remains held.
- V1Migration.status is a public read effect on Database.Service; unlike V1Migration.layer or run, it does not perform migration. It can reject required/running/error status on a readonly copy. This alone is not a DB schema-version claim or permission to start arbitrary provider/plugin config.
- Official server.start installs SessionRestart only with a lifecycle argument; actual event-host passes none. Transitive route layers still create migration and other services. Pending inbox and environment/plugin/provider startup behavior must be independently assessed. A production bootstrap decision cannot be inferred from authentication-free clean synthetic reopen results.

No new startup implementation, original DB read process, Native SQL, provider or credential operation was performed for these findings. Current production nonfresh hold remains unchanged. A copied-state inspector would be a new runtime/security boundary and needs one initial focused plan/design review before implementation, then routine fixes/checks/independent code review.
