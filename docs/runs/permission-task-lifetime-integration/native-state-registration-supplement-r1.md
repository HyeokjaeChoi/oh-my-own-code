# Verified direct State registration
Version:1. Focused changed-concern design candidate; no dependent production change or runtime enablement.

## Problem and selected option
Original ConfigWorktree and ConfigMCP invoke returned Native service.transform directly, bypassing the Host ctx decorator. Current unknown-factory refusal is correct and remains until the exact producer's setup prerequisites are verified. Existing original State accepts sibling/late registration and may replay a callback while its owner Scope is already Closed but before its LIFO dispose; inherited CurrentGroup is not source/Fiber authority.

Select graph-layer adapters around the exact original returned domain transform function. Control keeps the existing sole inventory; Native State keeps the existing sole callback set, replay/group/batch logic and original disposal. The graph already owns fixed node overrides. This uses its deep module boundary and avoids per-plugin callback rewriting. Preserve every existing Tool/Host/SDK private publisher/result check and existing Task/lease owner.

Alternatives: editing shared State.create would require a new native Control import and an independent identity proof for its caller/options.name; a new callback registry would duplicate ownership; branding every remaining plugin callback separately scales repeated overlays but still misses direct State routes. Rejected: options.name/source ID/hash/void result alone, inherited context alone, source audit alone as execution permission, or invoking callbacks to test purity.

## Initial scope and compatibility
Initial production consumer is ONLY original opencode.config.worktree and original WorktreeStrategies Service17 state.transform. Closed table: one expected worktree transform, undefined transform options, original factory successful void completion. Do not open ConfigMCP, core MCP->Integration acquisition, other State domains or unknown factories as a side effect. They need their own exact source/dependency review under this same design before binding.

Worktree metadata changes only the original editor directory/strategy configuration. Original Git create/remove/list callbacks remain untouched and unavailable. Config.entries is cached only AFTER Config layer load; fixed project:false/global:false/content plus ConfigDiscovery empty fastpath do not by themselves prove all Config/Watcher/Credential startup isolation. Gate constructor release on the accepted exact setup dependency proof; otherwise refuse before original factory construction. No new positive Task/compiler/inventory grant. Existing full trusted inventory, upper deny, mode/readback, bootstrap and runtime gates remain.

## Fixed graph source binding
Before activation, resource verification pins original producer/service/dependency sources and actual staged Loader/Control bytes. The graph binds the exact original plugin object and effect function. Native define returns its mutable argument: inspect plain own data descriptors, then freeze the ACTUAL object once before exposure. Repeated ID, copied object, copied effect transplant, alternate Source, proxy/accessor or public digest cannot mint a source. Use the existing Control producer table with a closed setup variant; no accept-any-result publisher.

The domain graph mapLayer gets the actual original returned Service17 value and transform function in the original location build. Control binds that exact function, same private location handle/incarnation and domain. Capture the original registration activation Scope at registration, not at domain acquisition. Use an opaque handle. The graph returns the original service fields with a transform adapter closing over this handle and original function. No caller supplies the original function, domain handle or source table. No State.name inference. Other Native fields/methods stay unchanged. Graph wrapper Scope is not claimed to be every service's internal owner: initial Worktree has no distinct internal root; any future service with a nested owner needs its genuine owner proof before binding.

## Actual activation context
The ORIGINAL Plugin.load invocation site brackets its original Effect with Control's private setup activation context. Its placement is INSIDE the original Effect.updateContext boundary, which otherwise removes arbitrary services. Capture actual running Fiber, exact descriptor already privately resolved/copied, original activation Scope, parent inventory token and current location. Context value is a frozen opaque key backed by the SAME Control. No arbitrary factory replacement or caller-created proof object. Original effect/options/storage invocation, grouping, logging and failure cleanup remain.

State registration must use the identical currently running Fiber, not merely inherited context or CurrentGroup. Sibling/forked/ended/cancelled/foreign-location context, closed/closing Scope, disposed parent and stale generation refuse before original transform is called. Invalidate activation context when original factory completes; late new registration cannot borrow a still-live parent Scope. Existing registered callbacks may replay later only through their own current source/Scope guard.

A setup result must be exactly the original successful void result AND expected publications all registered with matching source/domain/count. Do not put undefined into a WeakSet or loosen Tool/Hook result checks. Unexpected, duplicate, missing or wrong-domain registration poisons/holds that parent; successful original effect alone is insufficient.

## Publication and replay lifetime
Reserve the existing inventory row under Control's existing metadata permit before original State.transform. Pass a wrapper that checks exact row/source/parent/location and both owner scopes synchronously BEFORE each original callback, including first changed/get replay and closing finalizers. Use existing checked synchronous generation invalidation semantics, not a second lock or a claim that synchronous get can await a permit. A live execution snapshot cannot survive a generation change unnoticed. The first callback replay may use the validated registering row and live parent, before factory completion; requiring factory success before this replay would be circular. Later replay checks current source/row/parent/registration Scope/location incarnation, not the ended factory Fiber or an immutable first inventory generation. New registrations still require the exact activation Fiber.

The ORIGINAL State transform set stores the wrapper; Control does not store a second executable callback inventory. Original State Scope.addFinalizer, returned dispose, group failure, version checks, batches and shutdown remain. Post-registration check confirms current scope and row before publication. If original registration fails or publication loses authority, await ORIGINAL returned dispose where available, mark failure and retain uncertainty when complete cleanup cannot be proved. Control terminal cleanup is joinable on the existing token and cannot be skipped by ordinary queue capacity. Run original cleanup even when Control terminalization fails: preserve both Exits with ensuring/collection, never an andThen chain that skips dispose on failure. If registration fails before returning dispose, the original Loader activation Scope owns the original finalizer.

Scope can close between inventory reservation, original State.add and original Scope.addFinalizer. The replay guard must refuse before callback; original registration/dispose must settle before claiming no remaining registration. Closing a parent/plugin may notify other State callbacks: each needs its own active owner guard. Callback source provenance does not settle already-constructed notifications, background Fibers or IO. Original task lifetime holds remain separate.

## Bounds, reversibility and migration
Source/domain bindings are private provenance in existing Control, bounded by fixed source table/32 locations/256 registrations and released on actual location disposal. No second pending owner. No public DTO, saved authority, parser, Task identity or request body change. Restart cannot restore activation context. Removing graph adapter/source binding returns to conservative unknown-factory refusal.

Current recipe is65files254edits after ConfigDiscovery correction. This approach adds no shared State overlay. Extending the existing logical Loader invocation edit honestly is permitted; never combine unrelated rows or raise256 solely to fit. Source and recipe changes invalidate dependent resource/staging hashes naturally.
