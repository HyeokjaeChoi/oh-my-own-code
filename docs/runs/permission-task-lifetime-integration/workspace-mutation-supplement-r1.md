# Explicit workspace mutation task target
Revision: 1. Candidate only. Dependent workspace mutation code remains held pending independent design-spec review.

## Concrete defect and retained boundary
The accepted task-lifetime design requires a session in every non-bootstrap task identity. Actual configuration.mcp/configuration.agent and other workspace-only admitted operations have no sessionId. Storage correctly compares the admitted original identity, so inserting a selected or invented session would fail or misrepresent workspace-wide authority. The Native typed mutation currently also requires a nonempty affected-session set. Keep both refusals until this correction is accepted.

This correction preserves the existing workspace-wide operation scope and does not grant prompt/tool authority, add public methods, weaken trusted inventory or enable Control. Main remains the sole journal writer; Native graph remains the actual-effect owner. Both policy stages, exact original operation digest, final method/stage argument verification, original-key lifecycle, immutable ACK, and conservative startup/recovery remain required. Finished parent design records are historical and are not rewritten.

## Closed variants
Add required targetKind:'session'|'workspace' ONLY to mutation task identities and mutation origin admissions. Prompt, command and bootstrap shapes are unchanged.

A session mutation identity retains required appSessionId/nativeSessionId and requires targetKind:'session'. Its original admitted operation must have the same sessionId. A workspace mutation identity requires targetKind:'workspace' and forbids both session fields. Its original operation must have a workspaceId and must have NO sessionId. The registered project/location and actual trusted generations are still required, with workspaceId matching the exact admitted original. Target kind never derives from whichever session the UI currently selects.

The closed durable mutation binding becomes {kind:'mutation',targetKind,step,targetDigest,stageArgumentDigest,affectedSessionIds,affectedProjectIds}. All fields are required. targetDigest binds the complete actual admitted target, and stageArgumentDigest binds the complete detached actual method arguments. Their canonical algorithms remain shared producer functions and cannot be filled with dummy values. Both arrays are detached, unique identifiers with at most256 entries; affectedProjectIds must be nonempty and include the exact registered projectId. affectedSessionIds may be empty ONLY for targetKind:'workspace'; session target requires its exact nativeSessionId in this set. Oversized or incomplete sets fail before effects, without truncation.

Native mutation origin admission uses the same targetKind and exact detached arrays, plus its existing method and bindingDigest. The bindingDigest is the actual shared taskBindingDigest of this closed persisted binding. Workspace variant forbids appSessionId/nativeSessionId; session variant requires both. No fake inputDigest, inbox, prompt or coordinator scope is created for either mutation variant.

## Completeness and actual effect verification
Main derives the target kind from its immutable admitted operation, not a caller-supplied flag. The factory-owned verifier correlates every Native stage to that exact identity and persisted binding. Native independently checks the actual current registered location/project, method arguments and generation before consuming a handoff and before the effect. For workspace mutation, affected sessions are the complete current scope affected by that actual workspace method, including an empty workspace. A stale enumeration, concurrent session membership change or unverified mapping holds/refuses the stage; an empty array is never evidence that a mutation has no effects. Method semantics may narrow a checked complete set but cannot use a selected session as a replacement for workspace-wide scope.

Mutations do not promote inputs. Their actual RPC/Fiber/IO reservations and child effects still block settlement. A workspace mutation cannot create an execution lease that requires a nativeSessionId; such effect categories remain unavailable until a real session-bound path exists. Workspace changes that can run untracked callbacks remain refused. None of this permits effects before inventory/compiler/mode/upper-deny prerequisites pass.

## Persistence, compatibility and migration
Update the same task helper, strict journal/checkpoint validation, replay, registry correlation and Native typed origin validation coherently. New mutation records require targetKind and the complete sets. Current task feature is unshipped; there is no accepted external task store to migrate. Existing pre-feature parser refusal/byte preservation remains mandatory. Malformed or earlier development mutation records fail closed; do not infer missing target kind from optional fields or change raw saved records in place. Original receipt/lookup envelope and required authorityHold projection are unchanged.

Meaningful tests first reproduce rejection of a genuine workspace-only operation with an empty workspace. Then verify both variants, exact original identity/digest, wrong-kind/session substitution, absent/extra session fields, empty/duplicate/oversized/project-mismatched sets, detached snapshots, stale membership refusal, both flushed policy stages, no prompt/lease fabrication and same-journal reopen holds. Run coherent affected Node checks and final separate CODE. Actual Native execution remains unrun until separate contained pre-execution review and complete prerequisites. This supplement does not approve feature enablement or full F09/full18 completion.
