# Design research

Use the supplied run ID and the question in `docs/runs/<run-id>/plan.md`. Check the run status, then read only the linked product context and prior decisions. Do not begin or finish a run here.

Research the actual flow, audience, platform, and constraint named by the plan. Use accessible first-party products, official documentation, supplied Figma or Refero references, and dated captures. Read [references/research-method.md](references/research-method.md) for evidence fields and synthesis rules.

Separate what was directly observed from an inference. Identify recurring interaction patterns, meaningful differences, state coverage, accessibility implications, and constraints that transfer to this product. Do not copy another product's brand, composition, wording, or proprietary assets. A popularity signal is not proof that a pattern fits this user.

If access, authentication, or a browser limitation prevents inspection, record the missing evidence and continue with what is available. Never describe an unvisited screen or unavailable Figma node as observed.

Return a concise cited brief and source pointers to the planner. When a writable actor persists the requested research document, use `docs/design/research-template.md` or the project's convention and return its path to the coordinator for harness registration.
