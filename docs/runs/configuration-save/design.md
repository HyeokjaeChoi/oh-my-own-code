## Two-phase effect and descriptor kernel
Host observes/validates existing supported content and metadata/version, awaits confirmation, rechecks. Kernel prepare retains root/source FDs. Before any stage effect Main flushes filesystem.configuration.stage; child openat EXCL stage0600, bounded exact write, bounded XATTR copy, ordinary mode, metadata/body verification, fsync stage/directory. Source canonical singly linked regular file current uid/gid, non-executable ordinary mode, no BSD flags/extended ACL; xattr names32/aggregate32KiB, opaque comparison without projection. Stage ACL/flags must also fit. Unknown metadata refuses before publication, dispatched failure leaves stage retained.

Before publication verify original held/named inode/content/mode/xattrs and canonical root; Main flushes filesystem.configuration.publish and sends correlated publish(token). Existing target RENAME_SWAP retains displacement. Missing target RENAME_EXCL stage-to-target creates a complete file atomically and refuses collision, no partially visible target. Only one active token binds nonce/original key/root/digest; duplicate/replayed publication never executes again. Abort/timeout closes descriptors, keeps stage and unknown after dispatch. Never release a busy lane before actual task settlement.

After effect inspect new held inode/body/metadata, displaced inode/body/mtime/mode/xattrs and canonical root, fsync directory. Rename changes ctime; do not compare post-swap ctime equality as CAS. Stage creation changes directory times; compare expected version before staging and root identity afterward. Any mismatch/sync/IPC/completion failure is unknown, no rollback. Concurrent symlink becomes retained displaced link; it is never followed. Root rename writes held original directory only but canonical mismatch is unknown. Post-observation proves current bytes, not future stability or filesystem isolation. Final version uses the same reader raw-byte/version algorithm after actual publication and directory sync.
