# Branch/restore design v3 — initial proposal, independent gate pending

## Selected boundary / alternatives
Extend existing paired snapshot owner and typed descriptor metadata core with closed branch-create, branch-select and worktree-restore policies. Keep index/commit facades and one active kind-bound token/lifetime lane. Rejected: original-path Git/launcher (breaks checked-copy boundary), duplicated generic worktree writer (duplicates authority/recovery), UI-only branch label (does not checkout). Worktree replacement/create/delete/mode and finite parent effects are new authority; consumers wait for initial independent DESIGN_SPEC. Private known-byte probes inform behavior, not approval.

## Product actions and support
Create a new local branch at current verified non-unborn HEAD without switching/overwriting. Explicit branch name and user name/email; current commit identity lexical rules and exact UTC timestamp apply to branch reflogs. Never infer personal identity. Select an existing local branch only, explicitly requiring no tracked staged/unstaged changes; preserve every ignored/untracked byte and empty directory, refuse any destination collision including ignored. No force/stash/reset/clean/remote guessing or arbitrary start ref. Detached current HEAD can select existing branch; unborn selection/create refuses until a concrete nonempty source exists. Restore explicit selected tracked paths from INDEX or HEAD to WORKTREE ONLY, including creation of currently missing tracked files and deletion when selected HEAD source is absent but index tracks the path. Index/HEAD/refs/logs remain byte-exact for restore. Restore has no reflog identity field/effect.

Existing repository lexical/object/index/config/attribute restrictions remain. Refuse symlink/hardlink/nonregular/submodule/sparse/split unsupported repositories and protected configuration/credentials/harness path changes (existence/content/mode) under shared workspaceFilePathReason. Unchanged protected files may be copied privately under existing privacy policy and must stay byte/mode-exact. No activation bypass. Ordinary binary contents can remain private artifact bytes with digest/size preview; no raw export.

All THREE new actions (create/select/restore) require absence in the SELECTED gitDirectory of the existing finite commit-state marker set: MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, REBASE_HEAD, rebase-apply, rebase-merge, sequencer, MERGE_MSG, MERGE_MODE, SQUASH_MSG, AUTO_MERGE. Bind each absent path in source.missing and verify at preview, apply recomputation, kernel admission and immediately before EVERY original effect, including lock/parent creation. Never read/delete a marker or silently substitute a clean private checkout for this proof. A marker's appearance refuses before effects, or yields unknown after an earlier effect. Clean tracked state alone is insufficient. Other linked worktrees' operation markers are not selected-worktree markers and do not widen this check; target occupancy remains independently conservative. Existing reader/index support and commit marker policy stay unchanged. UI reports unsupported_branch_restore_state. Tests include clean tracked + each marker, preview/apply and effect-time insertion, and selected linked-worktree separation.

## Immutable computation / previews
Extend existing Git read observation, selected workspace/sender/epoch/root/trustRevision/revision/source digest and60s expiring preview cache. New closed public preview/apply DTOs and private target API are frozen as actual files after acceptance, before consumers. Target discriminates action and contains exact current/target HEAD/ref/tree/index facts; affected relative paths with old/new existence,size,rawdigest,Gitmode and actual mode; source selection; index/HEAD/ref/log proposal digests; occupancy digest; deterministic original-key backup roles/null. Never transport original raw file/config body in target/journal/receipt. Native author/message from commit is not reused implicitly; explicit visible user identity only for branch actions.

Native fixed Git computes only on complete checked private copies with hooks/filter/helpers/network/signing disabled and exact preflight before rawconfig stdin. Clean selection uses explicit --no-overwrite-ignore; no fallback. Recheck COMPLETE original manifest before native computation and after ALL commands. Verify private original branch/index tree, target branch OID, target tree graph and whole proposed canonical index/worktree manifest; no omitted unchanged paths. Proposed files come from exact private native checkout, not raw blobs. Native worktree-only restore refreshes index stat cache; NEVER publish it for restore. Branch selection canonical index entries must match target tree; original staged/unstaged clean check and post-native clean check required. A normalized checkout that cannot be independently correlated refuses before original effects.

Normalization boundary is EXACT predecessor policy: original core.autocrlf must remain false, core.eol only lf|native, attributes eol only lf; private minimal config autocrlf=false/eol=lf. Do not enable eol=crlf, input/true autocrlf, encoding/filter/macros to make a proposal pass. Ordinary CRLF blob bytes may remain unchanged; preparatory eol=crlf experiment is outside production support. Closed effective output policy is raw bytes or ident-only expansion. For ident=false output equals raw desired blob. For ident=true canonical literal $Id$ becomes $Id: <desired blobOID> $; reject any pre-expanded $Id: form rather than guess its special semantics. Preserve every other byte including BOM/CRLF. Shared pure bounded proof independently hashes blob header+bytes to desiredOID, expands only supported exact tokens and validates output length/digest. Main compares fixed native checkout bytes to this pure result BEFORE preview/admission; kernel independently repeats pure proof and immutable admitted output digest. No arbitrary private output accepted because native exit0.

Private binary object proof is distinct from public text-diff blob(), which retains its text/size gates unchanged. Add only a closed bounded private object-byte read kind to existing fixed executor, no caller arbitrary argv or new source path. Public preview reports binary/existence/size/hash/mode, never raw binary body. Changed original config, current/cached/target attributes or any native/pure mismatch refuses before effects. Target branch tree raw object graph and commit hash chain are independently verified: raw commitOID equals exact original target ref; its first tree header names root; all complete raw tree nodes hash to their OIDs and selected desired blobs hash to tree/index entries. Packed source objects can be supplied as private raw proofs and verified cryptographically; no original object mutation/decompression shortcut.

Restore INDEX requires path present in original index. Restore HEAD requires path present in original HEAD or index; absent HEAD with index-tracked path explicitly previews deletion. HEAD-present/index-deleted path may explicitly restore selected current target after full content-loss confirmation; preserve all OTHER untracked bytes. Never pretend an absent index path is a valid INDEX restore source. Worktree-only original index/HEAD/ref/log bytes stay exact even when private native restore refreshes stat cache.

## Occupancy and branch naming
Complete bounded common/worktrees registry listing plus common HEAD (primary worktree when selected worktree is linked) and every child HEAD/gitdir/backlink/locked presence is read and fingerprinted. Current selected entry is distinguished by exact canonical gitDirectory, not display name. Any foreign symbolic HEAD naming the requested target blocks, including stale/unverified/unborn entries; no arbitrary foreign filesystem path opening to clear a hold. Invalid/ambiguous registry refuses. Recheck listing and exact records before every effect. Detached foreign HEAD names no branch. Name must satisfy current strict local branch lexical rules, native private check-ref-format, physical exact directory names/case, ref-prefix collisions and packed/loose logical identity. Create also refuses a foreign unborn HEAD name even if ref absent. Cooperative checks are not an atomic occupancy reservation against uncooperative processes.

## Typed original effects / locks
No new Git object writes are needed: branch targets and restore sources already exist and complete tree/blob proofs are verified. Worktree effects derive ONLY from immutable selected relative paths and actual source layout, never caller arbitrary absolute path.
After durable stage intent: acquire current index.lock and HEAD.lock, then relevant old/target branch locks. For new branch creation only, finite missing ref parents may be created after index/HEAD locks and before the new branch lock, matching accepted commit ordering. ALL required locks must exist before worktree/log/index/HEAD stage/backups or new worktree/log parent creation. Each finite created directory uses checked held parent/exclusive mkdir0700 and exact owned inode/listing delta; no recursive cleanup or original empty-directory deletion. Restore source branch ref lock is included when HEAD-derived. Foreign locks fail fast without retry/deletion.

Backups/proposals are deterministic original-key kind/path roles under checked git/common metadata roots, NEVER refs/logs or ordinary worktree. All target devices must match the chosen backup root before effects; unsupported cross-device refuses. Existing files require source/parent named+held identity, positive no-write writable probe, ownership/flags/ACL/xattr/metadata guards and exact backup preservation. Replacement uses cross-parent FD SWAP with staged desired bytes, leaving exact old inode at backup. Creation uses EXCL, backup:null. Deletion uses same-device FD rename EXCL to absent deterministic backup; verify old inode at backup and original absence. No arbitrary unlink/rollback. Original mode preservation plus exact Git executable transition must be explicit: selected policy preserves original rw permission bits and sets exec bits only where corresponding original read bits exist when Gitmode100755, removes all exec bits for Gitmode100644; new files0600/0700. Formula existing nextMode=(oldMode & 0666) | (executable ? ((oldMode & 0444) >> 2) : 0). Preserve all other accepted metadata; special mode/flags already refused. Private native mode is checked for desired Git executable class, not adopted blindly as permission authority. Exact old/new actual modes are immutable in preview and artifact, including core.filemode=false cases. Test full permission transitions before final acceptance. Refuse unsupported metadata; never weaken original configuration kernel rules.

Publish intent flush before first target replacement/removal. Selection publishes finite worktree targets in canonical byte path order, then canonical index, required HEAD log, and symbolic HEAD LAST. Existing branch refs and branch logs stay unchanged. Creation publishes required branch log then new branch ref LAST; HEAD/index/worktree unchanged. Restore publishes only selected worktree targets. No global atomicity: partial worktree/index/log/HEAD failures retain unknown, exact backups/artifacts and original-key lookup-only hold. Do not restore old files or upgrade unknown to confirmed on reopen. After every effect, exact source allowed delta and immutable unaffected state are rechecked; no global source recapture hiding external writes. Owned locks clean only by exact named identity after actual settlement.

Reflog proof is closed and independently repeated by Main and kernel, not merely an admitted digest match. Reuse exact accepted logAllRefUpdates parsing/default-true behavior (true/yes/on/1/always; false/no/off/0/empty; other values refuse), with log creation required when existing log is present OR policy is enabled. Create affects ONLY commonDirectory/logs/refs/heads/<new branch>; select affects ONLY selected gitDirectory/logs/HEAD; restore affects NO log. Each absent relevant log is bound in source.missing, including when omitted by policy. Preserve original log prefix byte-exact; require empty or final LF and refuse unsupported prefix/boundary. Build exactly one appended UTF-8 line: `<oldOID> <newOID> <name> <<email>> <timestamp> +0000\t<reason>\n` (angle brackets surround the email once; `<<email>>` here denotes the placeholder with Git delimiters). Create uses all-zero format-width oldOID, verified current HEAD newOID, fixed reason `branch: Created from HEAD`, computed with private `branch -- <shortName> HEAD`. Select uses verified old HEAD and verified target OID, reason `checkout: moving from <old> to <targetShortName>`, where old is original symbolic short branch or exact original detached HEAD OID; private switch has no custom reflog action environment. Both use explicit validated visible identity and immutable timestamp, never inferred Git config. Compare the ENTIRE native proposal to original prefix plus this exact line before preview and again in kernel using raw private author proof/identityDigest; correlate proposal digest/bytes in target and receipt. Existing branch logs stay unchanged on select; HEAD log stays unchanged on create. If actual fixed native output/policy differs, refuse before original effects rather than accepting alternate reason/prefix. Future tests cover policy false with log present/absent, forged prefix/OID/name/email/time/reason, primary/linked/detached paths and log-at-preview races.
