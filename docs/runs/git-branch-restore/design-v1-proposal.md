# Branch/restore design v1 — initial proposal, independent gate pending

## Selected boundary / alternatives
Extend existing paired snapshot owner and typed descriptor metadata core with closed branch-create, branch-select and worktree-restore policies. Keep index/commit facades and one active kind-bound token/lifetime lane. Rejected: original-path Git/launcher (breaks checked-copy boundary), duplicated generic worktree writer (duplicates authority/recovery), UI-only branch label (does not checkout). Worktree replacement/create/delete/mode and finite parent effects are new authority; consumers wait for initial independent DESIGN_SPEC. Private known-byte probes inform behavior, not approval.

## Product actions and support
Create a new local branch at current verified non-unborn HEAD without switching/overwriting. Explicit branch name and user name/email; current commit identity lexical rules and exact UTC timestamp apply to branch reflogs. Never infer personal identity. Select an existing local branch only, explicitly requiring no tracked staged/unstaged changes; preserve every ignored/untracked byte and empty directory, refuse any destination collision including ignored. No force/stash/reset/clean/remote guessing or arbitrary start ref. Detached current HEAD can select existing branch; unborn selection/create refuses until a concrete nonempty source exists. Restore explicit selected tracked paths from INDEX or HEAD to WORKTREE ONLY, including creation of currently missing tracked files and deletion when selected HEAD source is absent but index tracks the path. Index/HEAD/refs/logs remain byte-exact for restore. Restore has no reflog identity field/effect.

Existing repository lexical/object/index/config/attribute restrictions remain. Refuse symlink/hardlink/nonregular/submodule/sparse/split unsupported repositories and protected configuration/credentials/harness path changes (existence/content/mode) under shared workspaceFilePathReason. Unchanged protected files may be copied privately under existing privacy policy and must stay byte/mode-exact. No activation bypass. Ordinary binary contents can remain private artifact bytes with digest/size preview; no raw export.

## Occupancy and branch naming
Complete bounded common/worktrees registry listing plus common HEAD (primary worktree when selected worktree is linked) and every child HEAD/gitdir/backlink/locked presence is read and fingerprinted. Current selected entry is distinguished by exact canonical gitDirectory, not display name. Any foreign symbolic HEAD naming the requested target blocks, including stale/unverified/unborn entries; no arbitrary foreign filesystem path opening to clear a hold. Invalid/ambiguous registry refuses. Recheck listing and exact records before every effect. Detached foreign HEAD names no branch. Name must satisfy current strict local branch lexical rules, native private check-ref-format, physical exact directory names/case, ref-prefix collisions and packed/loose logical identity. Create also refuses a foreign unborn HEAD name even if ref absent. Cooperative checks are not an atomic occupancy reservation against uncooperative processes.

## Typed original effects / locks
No new Git object writes are needed: branch targets and restore sources already exist and complete tree/blob proofs are verified. Worktree effects derive ONLY from immutable selected relative paths and actual source layout, never caller arbitrary absolute path.
After durable stage intent: acquire current index.lock and HEAD.lock, then relevant old/target branch locks. For new branch creation only, finite missing ref parents may be created after index/HEAD locks and before the new branch lock, matching accepted commit ordering. ALL required locks must exist before worktree/log/index/HEAD stage/backups or new worktree/log parent creation. Each finite created directory uses checked held parent/exclusive mkdir0700 and exact owned inode/listing delta; no recursive cleanup or original empty-directory deletion. Restore source branch ref lock is included when HEAD-derived. Foreign locks fail fast without retry/deletion.

Backups/proposals are deterministic original-key kind/path roles under checked git/common metadata roots, NEVER refs/logs or ordinary worktree. All target devices must match the chosen backup root before effects; unsupported cross-device refuses. Existing files require source/parent named+held identity, positive no-write writable probe, ownership/flags/ACL/xattr/metadata guards and exact backup preservation. Replacement uses cross-parent FD SWAP with staged desired bytes, leaving exact old inode at backup. Creation uses EXCL, backup:null. Deletion uses same-device FD rename EXCL to absent deterministic backup; verify old inode at backup and original absence. No arbitrary unlink/rollback. Original mode preservation plus exact Git executable transition must be explicit: proposed policy preserves rw bits and sets execution only for existing read permissions when executable, removes execute bits for nonexecutable; new files0600/0700. Freeze actual mode values in preview and test before adoption. Refuse unsupported metadata; never weaken original configuration kernel rules.

Publish intent flush before first target replacement/removal. Selection publishes finite worktree targets in canonical byte path order, then canonical index, required HEAD log, and symbolic HEAD LAST. Existing branch refs and branch logs stay unchanged. Creation publishes required branch log then new branch ref LAST; HEAD/index/worktree unchanged. Restore publishes only selected worktree targets. No global atomicity: partial worktree/index/log/HEAD failures retain unknown, exact backups/artifacts and original-key lookup-only hold. Do not restore old files or upgrade unknown to confirmed on reopen. After every effect, exact source allowed delta and immutable unaffected state are rechecked; no global source recapture hiding external writes. Owned locks clean only by exact named identity after actual settlement.
