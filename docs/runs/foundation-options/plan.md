# Foundation options — task plan

Revision: 1. Date: 2026-09-26. Coordinator: /root.

## Confirmed request
Research ChatGPT, Claude, OpenCode and Grok design foundations using appropriately routed specialists. Deliver several foundation preset previews for the user to compare and select. User selection is required before adopting any candidate. This task ends with reviewable alternatives, not adoption.

## Scope and decisions
- Research official public product pages, public app surfaces and available first-party source. Distinguish brand/marketing observations from actual app and internal system facts. Date/source every observation; no invented proprietary fonts, exact tokens or inaccessible UI claims.
- Use designlang for available public extraction and/or analysis; report heuristic and accessibility limitations. No credentials, private chats or LLM smart fallback.
- Four differentiated product-specific candidates, each light/dark, with identical Korean workbench content and foundation/component specimens. Include primitive/semantic/component alias data, palette, typography/fallback, density, radius, borders/elevation, motion, focus and status meanings. Exact candidate numbers are proposed values, not vendor copies.
- Deliver standalone local HTML/CSS/JS with preset and mode selection, side-by-side overview, workbench preview, responsive layout and export/copy selection text. Clearly label all content synthetic and actions demonstrative. No backend, vendor auth or production workspace changes. Prefer system Korean fonts and no remote font dependency.
- Preserve frozen paths in baseline.json byte-for-byte. No Figma mutation, AGENTS edit, canonical token update or library publish. Current architecture remains unchanged.

## Artifacts and ownership
Coordinator owns integration and ledger. Research child owns no files, returns sources. Main gathers complementary sources and synthesizes. Preview files only in docs/design/explorations/foundation-options/: index.html, styles.css, app.js, presets.json, research.md. Run evidence/checks/screenshots only in docs/runs/foundation-options/.

## Assignments / routing
User delegated model and effort decisions. Factual research Luna/high; plan review Sol/medium; preview author Sol/high or coordinator if child capacity unavailable; final independent code/design review Sol/high. Fresh role contexts with file-based handoffs, no transcript forks. Native child cap may include old completed agents; a fresh read-only Codex CLI invocation is an alternative, no history resume, no raised concurrency ceiling. At most four live workers including coordinator. Requested settings are not runtime identity attestations.

## Acceptance
AC-1: Four named vendors have cited, qualified evidence and a comparative synthesis.
AC-2: Four materially distinct light/dark candidates show the same Korean workbench and meaningful foundation/component states; selection remains pending.
AC-3: Preset/mode switching, comparison, selection export, keyboard focus and narrow layout are verified in the rendered preview. Proposed text/status pairs meet 4.5:1 and focus indicators 3:1 against relevant surfaces.
AC-4: Existing canonical files remain unchanged; honest scope/evidence and independent review.

## Verification and holds
Contracted structural/token check validates aliases/cycles/types, color pairs, all four two-mode sets, file references, and preserved hashes. Browser check uses synthetic local preview only at desktop and narrow sizes, switches every preset/mode, checks overflow, console/page errors and selection control. Screenshots feed independent visual judgment; no vendor fidelity or complete WCAG claim. No existing product tests are in scope. Final code and rendered design gates. Candidate prose is exploratory guidance, not a binding implementation design spec; no production implementation consumes it until user selects and a subsequent adoption design_spec passes.
