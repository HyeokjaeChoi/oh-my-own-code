# Permission policy observation design — v1

First bounded B06 product increment, not full AC09. Authority: user requests continued functional implementation after completed design foundation; PRD F09 and section5; accepted Workbench ADR. Actual prerequisite native-r1 once/reject/configured-deny passed independent final CODE. This increment reads session rules; it does not apply a preset or grant/revoke a permission.

## Ownership and alternatives
Use the current workbench service and v2 read envelope, existing files read lane, one Zustand projection and adjacent task surface. Alternatives rejected: deriving effective permission from a menu label (false authority), extending every snapshot with automatic rules reads (unneeded IO and stale authority), or a separate policy store/service (duplicate lifecycle). Reversible additive explicit read; no journal/schema/store migration or new runtime target. No dependencies or tokens introduced.

## Closed protocol
New request permission.policy.read {workspaceId,sessionId}, existing outer v2 read envelope {version:2,runtimeEpoch,readId,operation:{type:'permission.policy.read',workspaceId,sessionId}}. Cancellation uses the same runtimeEpoch/readId; no outer requestId is added. Public observation has runtimeEpoch/revision, workspaceId/workspacePath/sessionId, status available|unavailable. Available contains exact observed Native session rule presence (absent|present), ordered sessionRules [{action,resource,effect:ask|allow|deny}], requiredBaselineRules (current app BASELINE), baselineMatches:boolean and evaluation:'not_evaluated'. No native session ID, raw config, secret/error messages, invented desired preset, saved grant, hook outcome or OS sandbox claim. Absent rules stay distinguishable from present empty rules. Bounded 128 rules, action128/resource2048, no duplicate erasure/order sorting. Invalid Native data gives unavailable reason native_policy_unverified, never partial rules. Closed DTO validator lives in a shared browser-safe module with matching declaration/public barrel; producer and consumer use the same helper.

The service checks ready/trusted/nonheld selected scope and obtains actual native session.get. Correlate exact native ID + canonical location before projecting rules. Use current registry mapping checks/authority callback and read atomic clock semantics. Recheck current generation/root/trust/native mapping after await; ignore/reject late replies. Reading does NOT call session.update, policy(), permission.reply, save/revoke, discovery or any effect method. Recovery/untrusted/unknown/mismatched mapping does zero Native policy IO and returns the existing authority error. Native identity/rules invalid yields closed unavailable. No raw Native response exported.

## Renderer behavior
Explicit action observePermissionPolicy / cancelPermissionPolicyObservation, selector currentPermissionPolicyObservation. Observation identity includes epoch,wid,sid,root,generation,trustRevision,floor and request identity. No auto read on start/poll/selection/refocus/send/decision. Retire on scope/epoch/root/trust/generation/floor change; stale result cannot relabel new selection. Draft/input remains editable. A disconnected/held/untrusted scope has no read authority.

Adjacent task surface title 권한 규칙; button Native 세션 규칙 확인; cancel 확인 취소 while read pending; status not_observed/checking/observed/unavailable/stale/error. Always show: 세션에 저장된 규칙입니다. Agent 규칙·저장된 허용·hook을 합친 최종 실행 판단은 아닙니다. Also: 도구 수준 규칙이며 OS sandbox가 아닙니다. Ordered rule rows show original action/resource/effect with selectable full values and wrapping. Distinguish required app baseline from observed session rules and show mismatch visibly. No new preset selector or remembered-grant controls. Existing permission card and Composer + unchanged. Keyboard Enter/Tab/Escape cancel/focus, light/dark760 and200% full values/no overflow verified using original hidden renderer captures. Use established task-surface/component primitives and tokens.

## Acceptance and next boundary
P1 closed correlated real-session observation, zero mutation; P2 renderer identity/race/floor/no-auto-IO; P3 truthful accessible task surface preserving foundation; P4 current affected checks and fresh independent CODE+RENDER. Full mode compiler, active transitions, remembered grants/revoke, child propagation remain unfinished B06/B07 and need coordinated major extension before implementation. Current service baseline before/after selection remains intact. Existing nonfresh startup hold is unchanged.

Risks: session rules are incomplete effective-policy evidence (explicit label); Native optional/invalid data (closed unavailable); async selection ABA (identity guards); rule text untrusted (React text only); latency (read lane cancellation/timeouts). No provider, production Main, foreground product, private originals, real grants or release execution authorized by this increment. Hidden synthetic renderer is already authorized. Unit scripted SDK adapters prove service logic, not new Native all-tool enforcement. Reuse completed actual tool probe as narrow background evidence, never rerun it merely for this UI.
