# Git index mutation design v3 (entry proposal)

## Decision and alternatives
Reuse checked private snapshot and exact fixed CLT Git2.50.1/accepted2.54.x capability policy. All commands execute against private roots. Factor existing read-only snapshot/index/lifecycle internals into a private host engine, preserving existing reader API/public DTO. Add index preview/apply methods only through a separate private manager. Existing Sources read/hash/complete-manifest/no-symlink bounds remain. Narrow pinned Darwin Bun kernel performs original descriptor publication, following proven configuration kernel openat/renameatx_np ABI/ownership/exit model. Do not weaken generic file .git denial.

Rejected: running Git with original absolute --git-dir/worktree after realpath check (race/untrusted callback boundary); /dev/fd descendants or Node cwd (actual Darwin incompatibility already demonstrated); new native launcher (larger build/runtime and Git canonicalization uncertainty); new full Git implementation (reuse fixed plumbing/private index instead).

## Public contract proposal (Main must implement/freeze before consumer)
Read `git.index.preview.read` = {type,workspaceId,observationId,action:'stage'|'unstage',paths:string[]} with distinct sorted unique ordinary paths, 1..128, total UTF8 path bytes<=32768; no session scope. Existing accepted review observation owner/sender/epoch/root/trust/floor/source digest must be current. Response common clocks/runtimeEpoch/revision/workspaceId/workspacePath; available {previewId,previewDigest,action,paths,headOid:null|OID,indexExists:boolean,indexDigest,nextIndexDigest,objectFormat:'sha1'|'sha256',entries:[{path,before:null|{mode,oid},after:null|{mode,oid}}]}. Unavailable closed existing Git reasons plus busy/unsupported mutation as coordinated closed extension. Preview describes selected staged changes overwritten/restored; worktree content untouched. indexDigest is SHA256(exact original index bytes) when indexExists=true; for true absence only it is SHA256(UTF8("omoc-absent-git-index-v1")). nextIndexDigest is SHA256(exact complete canonical proposed index bytes), including every nonselected entry. previewDigest includes nextIndexDigest, indexExists and original indexDigest explicitly. headOid=null (unborn) does not imply indexExists=false. No backupId is minted before admission. No source bytes/commit message in DTO. Preview cache is bounded16per-workspace/64total, sender/epoch/trust immutable, lifetime60s maximum; expiry requires explicit new preview.
Mutation `git.index.apply` = {type,workspaceId,requestId,previewId,previewDigest,action,paths,headOid,indexExists,indexDigest,nextIndexDigest,objectFormat}; normal v2 envelope outer operationId=requestId, expectedRevision=preview.revision (Renderer retains the corresponding observation floor; no invented public floor field). Admission synchronously derives a closed target from exact bounded original preview metadata, and canonical operation digest covers every field. Service requires exact field-for-field equality with immutable host-held preview (sender/epoch/workspace/root/trust/floor/expiry) before any possible effect. Client-submitted values alone confer no authority; forged/missing/expired preview rejects before stage. No new asynchronous pre-admission IO or resolver callback. Lost preview/restart requires new explicit preview, never reconstitutes authority from receipt. Mutation returns status applied|unknown; confirmed receipt result {kind:'git_index_updated',workspaceId,action,paths,indexDigest,previewDigest,backupId:null|string,digest:originalRecordDigest}. Persist EXACT private gitIndexTarget={action,paths,previewDigest,headOid,indexExists,indexDigest,nextIndexDigest,objectFormat}, synchronously from the validated apply request. All fields are immutable and original canonical operation digest covers them. Layout/source fingerprint and sender/root/trust/expiry remain in the original host-held preview and are cryptographically bound by previewDigest; they are not privately invented after admission or separately persisted. No raw config/file bytes/index body/private token. Exact final fields coordinated in actual helper.

## Preview lifecycle/state
One window Zustand owns selected paths/current preview/action, workspace scope independent session. Explicit select paths -> preview -> show exact action/selected paths/old->new OIDs and staged-only loss warning -> explicit Apply -> Main native confirmation (defaultdeny injection) -> exact fresh revalidation. Initial mount/poll/refocus/selection/receipt never preview/apply automatically. Success invalidates observation/preview, raises floor; next explicit Git read required. Scope/epoch/root/trust/generation change retires preview but retains inert metadata/drafts for explanation. Pending/unknown/reopened original key disables matching workspace mutations; lookup current envelope/nested original epoch, no retry/replay. Actual call-finally hold survives logical timeout and confirmed lookup.

## Private computation
Fresh snapshot validates exact original accepted review fingerprint and complete source stability. Stage only selected ordinary files: fixed private Git normalization using preserved safe builtin attributes/autocrlf/eol/ident/filemode; filter/textconv/working-tree-encoding/external drivers refused as reader does. Explicit tracked deletion removes selected index entry; untracked ignored/protected/unmerged/symlink/sparse paths refused. Unstage replaces selected index entry with exact HEAD tree entry, or removes it for true HEAD absence/unborn HEAD. Preserve all nonselected stage0 mode/OID/path. Generate canonical v2 index with zero stat fields, no copied private inode stat cache; discard optional cache extensions only as current reader does, refuse meaningful unsupported index extensions/flags. Verify private fixed Git ls-files and expected selected/nonselected semantics. Derived preview digest includes action, sorted paths, before/after entries, complete canonical proposal bytes SHA256(nextIndexDigest), actual indexExists, object format, actual original root/git/common identities, HEAD symbolic target+resolved OID, exact original index hash/absence, safe semantics/config/attributes and complete source fingerprint. No fresh token relabels an old preview.

## Publication and locking
1. Main admitted original key/digest/immutable target, workspace mutex, trusted/current native idle identity. Recompute exact preview; obtain explicit confirmation; recheck. Journal stage intent flushed BEFORE original lock/stage creation. Stage intent means possible filesystem effects, so after dispatch any inconclusive result is unknown even before index replacement.
2. Bun kernel receives closed private request with original key, canonical workspace/git/common and full directory chain identities, expected HEAD/index/selected source manifest, a bounded artifact descriptor naming only exact app-owned private proposal root+dev/ino and manifest name/hash/length. Index/blob bytes never travel inline in IPC. No arbitrary path command. Open and hold each canonical directory with NOFOLLOW/NONBLOCK/CLOEXEC, validate named and held identity/owner/device; refuse symlink/hardlink/unsupported metadata and read-only original with no-write O_RDWR probe. Original layout may be linked worktree; its gitDirectory index is target, commonDirectory objects only. Verify linking/backpointer and no workspace/metadata alias. Current original index may be absent only for genuine initial repo; no other original file creation.
3. Acquire original `index.lock` using openat O_CREAT|EXCL|NOFOLLOW; reject existing lock, never steal or remove foreign locks. Hold exact inode+nonce ownership. Only index.lock is acquired in this slice; no ref/HEAD lock or parent directory is created. Recheck exact HEAD symbolic target+OID before publication and during post-verification; observed concurrent ref change makes outcome unknown and keeps backup. These checks do not establish OS exclusion against uncooperative ref/path writers or a durable HEAD lock; no such guarantee is claimed. Stage does not depend on HEAD content, but unstage is bound to the explicitly previewed HEAD. Any observed HEAD drift requires a fresh preview, never silently rebases the request.
4. Deterministic same-gitDirectory backup/stage name SHA256(original epoch/op key)+`.git-index.backup`; O_EXCL mode0600. Write new canonical index, fsync; preserve required original mode/xattrs or refuse unsupported ACL/metadata. Backup originally holds new bytes. Do not overwrite an existing backup from a prior op.
5. New loose objects are validated decompressed `<type> <length>\0body`, hash equals exact SHA1/SHA256 OID, accepted type blob for stage only, bounded cumulative<=existing128MiB/16384file snapshot budget. Publish under held common objects directory via descriptor-created/check-owned hex prefix and exclusive temp/rename. Existing exact OID object must verify same bytes; collision/mismatch refuses. Object effects can precede index and remain unreachable if later failure; disclose this, never claim no effect. No pack/refs/config writes.
6. Journal publish intent with EXACT admitted target flushed before index rename. Recheck held/named roots, HEAD/index/source expected state and lock ownership. Existing index uses renameatx_np RENAME_SWAP between stagebackup and index so original bytes retained at deterministic backup; absent index uses RENAME_EXCL. Fsync new index and parent. No original truncate or unchecked pathname write.
7. Verify original index bytes/digest and selected/nonselected entries equal proposal; worktree/HEAD/refs/config/source remain unchanged except allowlisted owned stage/lock/backup/object additions and index. For original absence, require exact new index creation and absence of the renamed stagebackup name; never claim an original backup. For existing index require deterministic backup exact original bytes and new index exact nextIndexDigest. Exact expected delta-aware manifest verification; never globally refresh baseline to hide external writes. Release only owned lock inode; keep original backup if and only if original index existed. Kernel settles actual task and closes all FDs. Main exact post-read semantic result before durable confirmed completion, Receipt indexDigest MUST equal admitted gitIndexTarget.nextIndexDigest, not merely valid hex. Existing index requires deterministic original-key backupId; true absence requires backupId=null. UI distinguishes absence (no original backup) from a retained original backup. Failure after any dispatched effect -> unknown/retained; partial object/index publication cannot be auto rolled back/replayed. Checkpoint/reopen never gains live publisher authority. Actual unproved kernel child exit holds workspace and retains namespace/lock evidence.

## Bounds/privacy/compatibility
Existing reader copy bounds128MiB/16384files/candidate4096/depth32/deadline8s; index paths<=128 selected. Private kernel prepare/publish10s fixed max, lower tests only. Stage writes only original index and objects, never selected file bytes; index backup persists under Git metadata and contains file names/OIDs. Private snapshot can retain ordinary source/history on crash/unproved exit as accepted reader; raw config remains stdin memory only, no credentials export. No secure erase/power-loss/full OS exclusion claim. Darwin arm64 pinned Bun1.4.2 only; other platforms unavailable. Linked worktree index/common isolation mandatory. Original packed objects permitted read, no rewrite; SHA1/SHA256 supported. Reftable, sparse/split/unmerged/indexv4, shallow/alternates and protected/special path constraints fail closed, visibly.

## Storage compatibility
Add feature marker `git_index_mutation_v1` durably before admission; archive/import actual current parser closure and prove it refuses marker without modifying bytes. Immutable admitted gitIndexTarget separate from operation identity/digest. Exactly bounded ordered stage and publish dispatch with matching target; object writes included in stage authority. New target and results closed, digest/path/action/previewDigest/index/backup correlated. Completion and redaction reject receipt.indexDigest !== admittedTarget.nextIndexDigest, wrong indexExists/absence marker or backup nullability, changed target and original canonical digest; result cannot manufacture authority. Unknown cannot be upgraded by replay, current lookup projects no raw targets/index/source. Reuse registry/journal/admission/receipts, no new persistence layer.

## Host integration and reversibility
Node private manager computes previews/proposals; Bun kernel remains inside exact owned event-host IPC alongside existing configuration kernel. New private request channel has one in-flight operation, <=262144 JSON bytes and actual child settlement; no Renderer IPC access to artifact/kernel token. Artifact manifest<=16MiB and total artifact bytes within existing128MiB bound, chunk reads<=1MiB. Kernel opens private mode0700 root with checked ancestry/owner/held+named identity; all referenced files must remain inside it, NOFOLLOW/nonregular/hardlink/escape/executable-metadata refusal, exact length/hash and closed manifest entries. Raw config is never in this artifact. Manager retains artifact/private snapshot FDs until actual kernel settlement or owned child exit; logical timeout does not authorize deletion/reuse. Unproved exit holds original workspace and retains namespace. Service public factory adds optional private gitIndexManager and confirmGitIndex injections only after actual producer freeze; default denial. Event host receives immutable admitted original key+target and owner fencing. Main stage/publish markers precede each possible phase; cancel/sender close settles preparation, cannot claim index publication canceled. Existing gitReader injection/API and read clocks remain unchanged. Refactoring private snapshot must retain actual49/51 reader regression matrix; compare old/current semantics with unchanged helper canaries. Feature can be disabled by refusing new mutations without destroying metadata; no auto rollback/migration/cutover. Retained new-marker stores are intentionally unreadable to old builds rather than silently downgraded.


## v2 design integration resolution (initial PLAN scope unchanged)
Actual source inspection identified existing event-host wire cap and pre-service admission order. Replace inline index/blob bytes with checked private artifact descriptors; apply carries exact bounded preview metadata so immutable target admission needs no new callback. Full original snapshot verification remains frozen and delta-aware: allowed path/listing changes are exact owned lock/stage/backup, expected index replacement and verified selected new blob fanout/temp entries. Every original nonselected source/metadata signature, listing and missing target still matches original frozen baseline; newly published objects independently hash-verify. No global recapture/rebase may hide external writes. Node manager waits actual publisher result before closing snapshot/deleting proposal; late result cannot release UI IO hold before original call finally. These details narrow existing proposed publisher/lifetime boundaries, not new user scope/runtime/persistence.

Supplementary feasibility: evidence/prechange/descriptor-report-r1.json + exact descriptor-probe-r1.mjs used manifest-hash verified bundledBun1.4.2 and fixedGit in fresh owned synthetic SHA1/SHA256 repos. Exclusive lock collision, atomic swap+exact original backup, unchanged worktree/HEAD and named-root-drift check passed. Not production publisher/fullmanifest/IPC/journal/linkedworktree/crash/independent acceptance. Actual archived prechange parser closure19files/111912bundlebytes; old-parser new-marker test still unrun until implementation.


## v3 initial design correction DS1/DS2
Fresh independent v2 review found missing whole-new-index digest in durable target and inaccurate unconditional backup promise for actual index absence. Add exact nextIndexDigest and indexExists across preview/apply/closedtarget, digest/host-held/kernel/journal/receipt correlation, explicit absent-index hash marker and backupId nullability. Verify target/nextdigest/receipt forgery rejection, SHA1/SHA256 original-index-absent vs unborn-with-existing-index separately. No scope/authority expansion or repeat PLAN gate. Exact fields above are required before actual producer freeze. Also refuse preview reason no_changes when selected semantic mode/OID/absence all unchanged; zero-stat canonical byte differences alone never authorize cache-only writes. Mixed selections require at least one meaningful selected delta; UI labels unchanged entries.

Private engine ownership: one createWorkbenchGitAccess factory creates the read facade and index manager over one authoritative observation/sender/epoch/trust table and snapshot executor. Existing createWorkbenchGitReader(options) remains a backwards-compatible read facade over that engine, with identical review/diff/closeSender/close and options. Production service lazy creation uses the paired access; a supplied legacy read-only gitReader alone does not implicitly grant mutation capability. Explicit private gitIndexManager injection is separately validated for tests. No duplicated observation authority or module-global cross-window cache. Manager checks original accepted review record through that same engine before fresh snapshot/proposal. Exact internal exports are actual producer checkpoint responsibilities, not new Renderer authority.
