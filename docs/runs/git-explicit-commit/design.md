# Explicit commit design v2 — initial entry proposal

## Decision / alternatives
All Git computation remains on checked app-owned copies under the existing single observation/snapshot owner. Add a commit manager and closed commit policy to shared descriptor primitives. Factor current index kernel into private git-metadata-kernel.mjs with backwards-compatible createGitIndexKernel facade and separate commit facade; production uses ONE core instance with kind-bound tokens, one active operation across configuration/index/commit. Preserve current index validation and52 actual kernel regressions. No arbitrary callback/path extension API. A separate full copy of the1320-line descriptor kernel duplicates critical checks; a new native launcher/original Git cwd path changes the accepted boundary; neither is selected. No new dependency or parallel journal.

## User/API proposal (not actual frozen code)
Explicit Git read -> enter author name/email and message -> preview ALL staged changes -> review exact branch/detached/unborn target, staged paths, parent/tree/commit OIDs, canonical message/author/time and unsigned/no-hooks behavior -> Apply -> Main native confirmation default-cancel -> revalidate -> commit or original-key unknown. No stage/read/commit on mount/poll/refocus/selection/receipt. No amend, merge commit, empty commit, signing, hooks or remote operations. An unchanged staged tree refuses no_changes; an unborn empty tree also refuses, while deleting every file from a nonempty parent remains a meaningful supported commit; unsupported paths/formats follow current reader/index rules.

New read git.commit.preview.read = {type,workspaceId,observationId,author:{name,email},message}; no session. Normal v2 envelope and current floor. Name/email explicitly user-entered, bounded256 UTF8 bytes each, nonempty, well-formed Unicode encoded as exact UTF8, no ASCII control bytes or angle brackets; email has no whitespace. No trim, Unicode normalization or punctuation removal. Reject BEFORE preview any first/last UTF8 byte that Git boundary crud would remove: ASCII0..32, comma, colon, semicolon, angle brackets, double quote, backslash or apostrophe. Interior permitted spaces/punctuation and Korean names remain byte-exact. Native author AND committer ident and actual commit-body headers must independently equal expectations built from ORIGINAL validated input name/email plus captured timestamp/+0000, never from a normalized native result. Any mismatch refuses before original effects, no silent rewrite. Message nonblank bounded65536 UTF8 bytes, no NUL, valid UTF8; exact CRLF/BOM preserved subject to explicit commit-tree final-newline behavior. Host canonicalizes by adding one LF ONLY when message lacks terminal LF, displays this exact result, and supplies one immutable Unix-second UTC timestamp. Same author/committer identity/time, no inferred real identity. Preview expires60s, max16/workspace64total, scope sender/epoch/workspace/root/trust/trustRevision/revision/source digest. At most128 staged changes and32768 aggregate path bytes; full index/tree proof can include up to4096 entries. DTO<=196608 bytes; too_large refuses rather than partial preview.

Available preview common clocks/workspace/path + previewId, target, author/time/canonicalMessage, entries of ALL staged changes (path,before/after mode/OID or null). Target = {objectFormat,previewDigest,indexDigest,headOid,treeOid,treeDigest,commitOid,commitBodyDigest,reference,logs}. treeDigest=SHA256(JSON of byte-UTF8-sorted [path,mode,oid] for complete original staged index). commitBodyDigest is SHA256 exact raw commit body, supplementing native SHA1/SHA256 OID. Reference = {kind:'branch'|'head',name:full refs/heads/name|null,exists,digest,nextDigest}; kind=head only detached, branch name strict validated original symbolic HEAD. Digest is exact physical original bytes or explicit SHA256 absence marker. Packed logical parent and physical loose absence are distinct. logs sorted closed role head_log|branch_log, each {role,exists,digest,nextDigest,nextBytes}; omitted only when actual checked log policy and physical absence mean no log effect. No raw ref/log/index/config/body/root/token in target. previewDigest covers exact original complete source/layout/config/log policy/body/author/time/tree/reference/log proposals plus target; host-held immutable preview owns bodies.

Mutation git.commit.apply = {type,workspaceId,requestId,previewId,...target}; outer operationId=requestId and required expectedRevision=preview.revision. Admission synchronously derives exact closed target and canonical original digest, no IO resolver. Service must match every target field to host-held current owner/scope/floor/expiry before and after native default-cancel confirm; submitted metadata alone confers no authority. Never recreate a live preview from restart receipt. Return status committed|unknown. Confirmed receipt result closed {kind:'git_commit_created',workspaceId,commitOid,treeOid,parentOid,referenceDigest,logDigests,previewDigest,backups,digest:originalRecordDigest}; every output correlated to immutable target and exact independently derived original-key backup roles/presence. No author/message/log content in journal/receipt. Actual helper fields must be frozen before consumers; coordinated source defect corrections only thereafter.

## Private generation / repository semantics
Extend current checked snapshot only with relevant original reflog reads/ancestors and known logAllRefUpdates semantics (unset nonbare default true, true/false/always); raw config still private stdin and minimal safe config. Current minimal config emits hooksPath=/dev/null and drops unrelated config; preserve signing suppression explicitly. Fixed commands on private roots: write-tree; commit-tree --no-gpg-sign with bounded explicit identity/date environment; update-ref -m "commit: explicit local app commit" HEAD new old with hooksPath=/dev/null and private exact original log policy/copies to generate complete proposal bytes. The reason is an EXACT constant for all inputs/formats/roles; user message stays ONLY in commit-tree stdin/body, private owned artifact and approved preview, never in argv/journal/receipt/report. For each applicable log, independently compare exact original prefix bytes followed by one expected line: oldOID (all-zero native width for unborn), new commitOID, ORIGINAL explicit committer ident/time, TAB, that exact constant reason and LF. Require old prefix empty or LF-terminated; malformed append boundary refuses before effects. Existing prefix is preserved byte-for-byte, not rebuilt from parsed history. Private command canaries prove no reference-transaction hook/signer/helper execution. Existing logs append even logAllRefUpdates=false; absent disabled logs stay absent. Private refs may be flattened copies; original layout metadata retains packed/loose state. Use actual fixed Git capability preflight for these flags and both formats before raw source/config consumption.

Proposed tree graph must resolve EXACT complete staged path/mode/OID mapping, with no extra entry and valid native hashes, including required tree bodies even when their private object is already packed. Kernel validates complete canonical tree graph against original staged index, exact commit headers(tree, zero/one original parent, explicit identical author/committer/time, no gpgsig/extra headers) and raw body digest/native OID. Only genuinely required missing immutable tree/commit objects are original write targets; existing content hash/type/bytes must match, never overwrite objects or packed files. No_changes compares tree with original HEAD tree; unborn empty index refuses. Linked worktree HEAD and index belong to gitDirectory, branch/ref/log to commonDirectory. Detached HEAD modifies only current gitDirectory HEAD and applicable HEAD log; other branches unaffected. Current bounded unsupported reftable/split/sparse/unmerged/indexv4/alternates/shallow/symlink/hardlink/nonregular and protected source behavior stays closed.

## Commit-only ordinary-state guard (DS1)
Before preview and again on apply/after confirmation/before every original effect, require absence in the CURRENT worktree gitDirectory of this finite exact list: MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, REBASE_HEAD, rebase-apply, rebase-merge, sequencer, MERGE_MSG, MERGE_MODE, SQUASH_MSG, AUTO_MERGE. Any named presence (file/directory/symlink/other type) refuses unsupported_commit_state without reading/executing that state or modifying it. Do NOT use commonDirectory marker paths for a linked worktree. Existence/absence uses checked parent/named identities and is captured in immutable source fingerprint and artifact missing authority; kernel independently requires the SAME exact missing set and repeats checks immediately before effects. Errors never count as absence. Existing ORIG_HEAD alone is ordinary persisted history and is NOT a refusal marker. Read/index operations retain their existing support, so staging to resolve a merge is not disabled by this commit-only rule. This feature never finishes/cleans merge, cherry-pick, revert, rebase, sequencer or squash state. Resolved stage0 merge is refused just like unresolved merge; marker created after preview cannot be hidden by globally rebasing the source.

## Descriptor authority / publication
Private request wire<=262144, checked artifact0700/0600 manifest<=16MiB, each index/log/proposal bounded16MiB, combined snapshot/artifact<=128MiB and16384 files, depth32, chunk1MiB. Actual read deadline8s and kernel10s, test overrides lower only. Artifact manifest includes original layout/source completeness plus exact proposal reference/log files, complete tree proof and new objects; no raw config. All artifact files checked nofollow/hardlink/owner/mode/hash/length and exact named/held identity. Current index artifact contract remains unchanged behind index facade.

Stage intent MUST be durable before original effects. Prepare FIRST verifies exact root/git/common/index/HEAD/packed/loose/log/config/source, ordinary-state absence and named descriptors; writable probes apply to intended ref/log targets and their parents, NOT unchanged readonly index bytes. AFTER durable stage intent, acquire exclusive cooperative index.lock and HEAD.lock in their existing gitDirectory parents. NEXT, for an attached branch, verify missing ref-parent absence and create only required ref parent directories ancestor-to-leaf from the held checked commonDirectory; record exact owned dev/ino/listing delta after each exclusive mkdir. THEN acquire branch.lock fail-fast in that verified existing/new parent (deduplicate paths; no wait/retry). Only AFTER ALL required locks exist may log-parent creation, immutable objects, proposal stage files or backups begin. On partial parent creation, branch-lock collision or failed recheck, preserve created effects as unknown; do not claim no effect or recursively remove directories. No object/proposal/backup effect is allowed before the last required lock. New original missing ref/log parent directories are a finite <=depth32 list derived ONLY from original canonical layout and strict existing HEAD branch name, no public arbitrary path mkdir. mkdirat exclusive0700, record exact owned dev/ino and permitted source delta; collisions/unexpected inherited ACL/cross-device layout fail closed. Ancestors/ownership/write permissions rechecked before each create. After any uncertain effect, unknown and retained evidence, no unsafe directory rollback.

Backups/proposal files use deterministic SHA256(JSON.stringify([originalEpoch,operationId,closedRole])) under gitDirectory root for current HEAD/HEAD log or commonDirectory root for branch ref/log. NEVER put backup names under refs or logs namespace: that would change repository semantics and current reader traversal. Use cross-parent-fd renameatx_np on the same checked device; cross-device ancestor layouts unsupported before effects. Positive writable probes and xattr/ACL/mode preservation for existing originals. New loose refs/logs use explicit owner-only safe metadata. Do not silently relax readonly or ownership checks.

Prepare creates exact proposed stage files/backups and any genuinely missing immutable objects, all included in frozen source allowed delta; foreign locks/backups untouched. Publish intent MUST flush before rename. Recheck exact scope/HEAD/index/log/source; publish applicable log proposals in closed order head_log then branch_log, then publish reference LAST. Existing target uses atomic SWAP leaving exact original backup; physical absence uses EXCL and backup result null. Fsync each file and affected directory, exact postchecks after each step and full verification before committed. Attached symbolic HEAD stays unchanged; detached HEAD is the exact final reference target. Index and worktree files never replaced. All owned locks removed only after verified named identity and actual settlement.

Multiple logs/ref/objects are NOT globally atomic. A failure after one log rename may leave new log entries with old reference. This is an explicit unknown partial outcome, retained backups/artifacts and matching workspace hold; no automatic rollback/retry/upgrade/reopen replay. Cooperative locks do not prove exclusion against an uncooperative writer. If actual child exit cannot be proved, retain namespace/FD authority/hold rather than cleanup/reuse. Original current source is never globally recaptured/rebased to hide external writes. Allowed delta is only exact owned lock/backup/directory/object/proposal/reference/log changes and immutable post-publication matches.

Same owned Event Host child and typed prepare/publish/abort/result channel, one active core transaction and one supervisor pending lane across all configuration/index/commit operations. ## Source references / preparatory evidence
- Official Git update-ref2.50 documentation: https://git-scm.com/docs/git-update-ref/2.50.0 . Old OID guards, per-ref atomic visibility, and existing-log creation policy support the design; they do not establish our descriptor implementation.
- Upstream Gitv2.50.1 refs/files-backend.c: https://github.com/git/git/blob/v2.50.1/refs/files-backend.c . Relevant log routing/setup/transaction finish corroborates distinct linked HEAD/common log paths and logs before ref publication; upstream source is not Apple-specific runtime attestation.
- Actual four synthetic private Git cases and exact scripts/reports in evidence/prechange prove explicit identity/date/CRLF body, old-OID refusal, linked log routing, disabled-existing vs disabled-absent logs, no signing/reference hooks. No original descriptor publisher/journal/crash proof yet.

Reversibility: feature can be disabled before new admissions without deleting metadata. Already-written commits/refs/logs are normal Git data and are never automatically rolled back. New marker stores intentionally refuse old builds. Commit does not authorize branch create/switch or worktree restore; those remain required later bounded changes.

DS2 exact stage -> existing index/HEAD locks -> finite ref-parent creation -> branch lock -> log parents/objects/stages/backups, partial creation remains unknown. Also clarify that deleting every tracked file is a valid changed empty tree; only semantic no_changes/unborn-empty refuses. Original readonly index remains readable and untouched, not subjected to target O_RDWR probes. New tests must cover all four concerns plus complete staged deletion. No new user scope/authority or repeated PLAN gate; fresh changed DESIGN_SPEC review before implementation.
