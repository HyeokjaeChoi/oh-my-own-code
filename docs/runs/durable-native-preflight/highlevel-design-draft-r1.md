# Durable Native preflight — design1 draft

This draft does not authorize implementation. It supplements plan revision1 for one initial independent review of the new runtime boundary. Existing production nonfresh startup remains held. Parent P7 v5 DTO, owner record, journal and registry shapes stay unchanged.

## Authority and decision

Main constructs `createNativePreflight({namespace,owner,registry,eventHost,processIdentity,signal?})` from trusted local objects. Its proposed result is one async callback returning a boolean; it accepts no renderer, stored executable, environment or path options. Fresh admission uses the existing fresh proof. Nonfresh admission requires the exact active owner and no unresolved registry or resource authority, then a complete copied-state proof. An unknown, unsupported or failed condition returns false. Detailed causes are bounded host diagnostics, not executable recovery requests.

The inspector has no executor authority. It is a separately owned contained process that imports only the reviewed public readonly dependencies. It cannot construct ServerProcess or Native execution, provider, plugins, credential, permission, migration or event-publication services. The inspector process is not recorded as the executor child in owner.json. Main retains its exact ChildProcess handle and confirms exit directly; no PID-based stop, exit from absence or historical injected proof.

## Snapshot and physical binding

Require actual canonical owned mode0700 namespace directories, the currently held kernel/nonce and ready registry. Snapshot registry runtimeEpoch, revision, exact sorted active app/native/workspace/location mappings and retained keys; reject resource holds, missing native identity, duplicate native IDs and more than 200 mapped sessions. Defensive identity correlation and receipt/fork lineage remain host verification responsibilities; preflight cannot promote a reservation, receipt or mapping.

The original file set is fixed by the verified manifest database path: event-host.sqlite and its optional -wal, -shm and -journal companions. Reject missing main DB, symlink, non-regular, hardlink, foreign ownership, group/other access, or oversized input. Proposed finite bounds: main DB 256MiB, WAL 64MiB, SHM 4MiB, rollback journal 64MiB, aggregate 388MiB. Open with O_RDONLY|O_NOFOLLOW. Capture descriptor/path device, inode, mode, uid, link count, size and nanosecond timestamps plus full SHA256. Check descriptor and path before and after each streamed read, then recheck the entire set and absence of optional files. Do not reopen an arbitrary discovered path.

Create an exclusive canonical private temporary root disjoint from namespace, app Documents and runtime resources. Copy all present files with their exact names into one private directory, then flush copied files and directory. Preserve all WAL/SHM bytes together. Never checkpoint, rename, repair or open original SQLite through a Native library. A copy mismatch or original set/content/metadata drift invalidates the proof. Inspect all copied files again after inspector exit to distinguish copied-state changes; original unchanged proof is mandatory even when the inspector fails. Hash equality does not claim hostile same-user isolation or absence of change-and-restore.

Inspect durable configuration separately with the same physical rules. Current supervisor-created config directory must contain only the reviewed empty opencode.json; reject nonempty/unknown configuration rather than load it. Bind the exact EVENT_HOST_CONFIG deny policy, initialization options, runtime resource inventory and inspector bytes. Original state outside the finite inspected closure must be rejected or explicitly demonstrated irrelevant by the official dependency graph before acceptance. In particular, legacy migration storage must not be assumed absent from DB-only evidence.

## Closed read program and messages

The proposed packaged read entry receives a private bounded request through stdin, not command interpolation: version1, random invocation nonce, private copied database path and the sorted expected native IDs. The path is supplied by Main and must lie inside its copied-state root; no environment inheritance. Maximum request 64KiB. Environment HOME/cache/temp/config/state point only into the private copy root; PATH is explicit system-only. Bun and entry paths come from the validated event-host resource tree, never a global executable. stderr is discarded. stdout is capped at 16KiB and contains only a closed decision frame with matching nonce, version and counts; no session text, metadata payload, KV values, path, credential or generated password.

Readonly construction must use public sqliteLayer with readonly:true, readwrite:false, create:false, disableWAL:true, and official Drizzle. Before acquisition replace Database.node with a closed readonly Database.Service through public LayerNode.compile replacement. The default Database provider performs migration/tuning and must never be acquired by the inspector. Exact exported modules, provider composition and final response schema remain subject to the factual API checkpoint and independent review; do not implement a guessed equivalent graph.

Bounded read rules use only public operations: SessionStore.list(limit:201) must return at most 200 sessions and exactly equal expected native IDs. Reject any parentID to exclude background children; official root forks require the host's exact lineage correlation. SessionStore.listSuspended must return empty. For every enumerated session, Inbox.list must be empty. KV.scan(prefix:"",limit:1) must be empty, including malformed or completed markers; filtered Job lists cannot establish absence. Public V1Migration.status must establish completed/inert state. Never call any write, admission, cancellation, migration, resume or job API. A malformed/unsupported schema, pagination ambiguity or inconclusive result denies launch.

## Startup ordering and freshness

Each callback invocation must independently reassert owner/kernel/root, capture the current registry and original/config/resource closure, inspect the copy, confirm inspector exit and recheck all bindings. Do not cache a boolean across awaited startup mutations. Main calls the callback before recordOwnerIntent(startup); the existing supervisor calls it again before setup and immediately before markSpawnIntent. The startup owner journal append changes registry revision, so a proof for the earlier revision cannot be reused for the later revision. Existing sequential callback call sites may perform bounded repeated inspections; optimize only after an explicit equivalent binding proof.

All pending or uncertainty holds must stop before executor spawn or init. The inspector cannot be an alternative owner or Native service. The source review must establish the exact pinned server initialization does not resume claims, drain inbox, deliver background jobs or migrate unknown legacy state under the accepted policy. Omitting SessionRestart lifecycle alone is insufficient because route-layer acquisition has independent effects. If official graph review cannot close that condition, the callback must continue to deny nonfresh launch.

## Deadlines, failure and cleanup

One inspector invocation has a 20-second monotonic deadline and bounded file/session/input/output counts. Attach error/exit listeners immediately. On timeout or invalid output, terminate only the exact owned inspector handle and wait a bounded period for its exit. If exit is unconfirmed, retain the copied root and record cleanup uncertainty; original executor remains unspawned. Remove the temporary root only after exact inspector exit and complete original recheck. No recursive removal of durable stores or failed test namespaces, no leaked raw child output, no approved-success fallback.

The read program is staged into and bound by the existing event-host resource inventory; build, package inspector and provenance must inventory its exact bytes. A source or resource replacement invalidates launch. Unsupported platform/schema/config/state remains a conservative hold. Rollback removes use of the new callback and preserves original bytes; it never converts a hold to fresh or modifies stored identities.

## Verification and independent decision

N1 and N4 require unit fault injection for every boundary and actual copied readonly inspection with original DB/WAL/SHM/journal byte/metadata preservation. N2 uses explicitly authorized synthetic public Native APIs to create persisted root claims, background children, inbox/KV/migration and unmapped/boundary states; no Native SQL or provider dispatch. Malformed states that lack a public producer require a closed copied-fixture proof or remain unclaimed. N3 requires separate zero-window owner generations with production lifetime verifier and production preflight for normal/SIGKILL reopens, exact history and actual fork lineage. A trusted synthetic preflight is never positive acceptance. N5 includes one initial plan/design review, implementation checks, coherent package, saved actual probes and fresh independent final code review; subsequent repairs inside the accepted boundary use the routine path.

The immediate next step is factual API/dependency review, not source implementation. Any limitation that prevents complete public pending absence or inert startup is recorded as an unmet dependency with the existing production hold preserved.

## Factual checkpoint — 2026-10-08, not entry-ready

The fresh independent reader report is saved at `../durable-workbench-storage/execution/native-preflight-public-api-r1.md`. It found three gaps in the high-level read-program proposal above. No implementation or initial entry review is started for an incomplete proof.

1. Include Database.node itself in LayerNode.group roots, alongside SessionStore.node and KV.node, before replacement. Otherwise direct Inbox.list/V1Migration.status effects cannot obtain the exported Database.Service from the compiled root environment.
2. SessionStore's row converter hides a non-null empty parent_id; listSuspended excludes that row. SessionInbox.list reads only an existing session's rows and cannot enumerate orphan inbox rows. These public high-level reads cannot prove complete pending absence for arbitrary damaged input. Main found the public `@opencode/core/session/sql` table exports, but using them would be a different explicitly reviewed typed-read program, not the high-level program already drafted here. No Native table queries or mutations were executed.
3. V1Migration.status concerns legacy v1 data and may report completed when its legacy session table is absent. It is not a readonly schema-migration status. The public schema migration module exposes apply/applyOnly, both with mutation paths, and ordinary server Database acquisition always invokes it. Do not run those methods on the original or silently substitute them for a readonly status.

The current draft therefore cannot satisfy N2/N3/N5. The existing nonfresh hold remains. A complete design needs an official global pending/raw-state and readonly schema-compatibility capability, or a separately reviewed provenance/typed-read boundary that closes ALL of these cases. A synthetic allowSyntheticStart callback and a successful authentication-free reopen close none of these gaps. Finishing the lifetime witness and current P7 renderer/host verification is independent useful work and continues.
