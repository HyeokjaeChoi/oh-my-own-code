# Main integration preparation

2026-10-08. This records inspected integration points while the independent design2 entry review runs. It is not an entry pass, API freeze or runtime acceptance. No dependent preflight source has been implemented yet.

- Resource descriptor stays unchanged: eventHostForResources returns root/enginePath/hostPath/manifestPath. Derive a fixed inspector entry within that verified root; never accept a caller/stored executable path. stage-event-host currently copies only host/protocol/resource local modules and checks the complete expected asset set. Add the inspector's closed local dependency set there and in required-asset validation, with hashes checked before/after exclusive staging.
- Build provenance already hashes production src recursively. Put reader/protocol/predicates under src so build identity covers them. If a new production staging script is necessary, include its exact source path in build-provenance sourceScopes; ordinary probe scripts remain separate before/after acceptance inventory inputs.
- Main currently checks freshNativePreflight before recordOwnerIntent(startup), then passes that function to startSidecar. Replace both with the same production preflight object only after accepted design and actual module API freeze. Recheck after the startup record changes revision. The existing supervisor invokes its guard before setup and twice before markSpawnIntent; do not bypass these calls or cache their previous boolean.
- Registry readView increments observationSequence on every call. A proof binding must omit that observer-only counter, and bind runtimeEpoch/revision/state/recovery/retainedOperations/workspaces/sessions/tombstones. Include exact lookupIdentity/lookupForkIdentity and original confirmed receipt verification. readView sessions use appSessionId/nativeSessionId/parentSessionId/lifecycleState; worker input translates explicitly to parentAppSessionId and canonicalPath.
- Nonfresh controlled config lives at namespace.config/opencode/opencode.json. Existing supervisor exclusively creates {} on fresh launch, but only checks permissions when it exists. Preflight must additionally require exact controlled content and closed directory entries. It must reject unknown config/state and cannot assume existing file means safe configuration.
- finishStorage currently drains workbench, records shutdown/checkpoints/closes registry, then releases owner. Join the preflight object's owned inspector shutdown before those operations. If exact inspector exit is unconfirmed, retain copy and owner and report incomplete cleanup. Abort during startup must settle the same tracked inspection task, not drop a promise and release owner.

Proposed disjoint implementation ownership after entry acceptance: Main owns copied-set host adapter, resource descriptor/staging/provenance integration, Main startup/shutdown and saved actual Native probe. One fresh worker owns readonly reader, bounded protocol/predicates and their tests. Freeze those actual exports before consumers. No renderer, DTO, checkpoint-module or owner-record changes are needed by this preparation.
