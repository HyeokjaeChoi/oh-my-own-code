# Copied readonly Native startup validation — design3

This is the proposed single initial design for a new runtime inspection boundary. Implementation waits for its independent entry reviews. Earlier high-level design is preserved in highlevel-design-draft-r1.md and is superseded here: projected SessionStore/Inbox APIs are insufficient for complete pending absence; executing migration effects on a readonly connection can still read credentials before a rejected SQL write. Production nonfresh startup remains held until actual positive evidence exists.

## Scope and authority

Keep storage-contract v5, DTO, service factory, owner record and registry/journal formats unchanged. Add a contained evidence-only Bun inspector and a host callback using existing supervisor preflight injection. Inspector reads only a private complete stopped SQLite COPY. It receives no original database path or inherited original file descriptors. It does not own the store kernel or replace the Native executor child.

Use pinned public Native table definitions with official readonly SqlClient and Drizzle. The only additional table descriptor is an explicitly version-bound readonly projection of the native migration ledger, whose id/time_completed definition is confirmed in the official DatabaseMigration source. This coupling is a design decision, not a claimed public MigrationTable API. It creates no table and changes no native schema. No handwritten SQL, custom PRAGMA, native mutation, default Database provider, migration apply/up/run, server, provider, plugin, executor, credential or bus service acquisition is permitted in the inspector.

The positive claim is bounded absence of the pinned engine's durable pending work and schema-migrator work for the exact validated file set and controlled startup configuration. It is not arbitrary SQLite integrity, hostile same-user isolation, unknown Native-version compatibility, migration cutover or an authenticated provider acceptance claim. Any unknown or unsupported state stays held. No schema or journal success marker is adopted.

## Host API and ordering

Main-only `createNativePreflight({namespace,owner,registry,eventHost,processIdentity,signal?})` returns `{check,reason,close}`. `check():Promise<boolean>` is the existing supervisor callback shape. `reason():StoreRecoveryReason` returns the latest closed pending_inbox/native_startup_unverified or underlying owner/store reason. `close():Promise<{exited:boolean,cleanup:'complete'|'incomplete',recoveryPath?:string}>` cancels active inspection, settles its owned process and retains uncertainty. Trusted unit injections may be constructor-only additions coordinated at source freeze; no renderer/stored path, executable, callback or environment selection.

Fresh namespaces continue the current fresh proof: registry ready with no retained keys. Nonfresh requires canonical owned kernel/root, ready registry with no retained or unavailable resource, validated mappings and the copied inspection. Single-flight inspection; concurrent conflicting calls fail or wait on that same task, never reuse a stale result. Every returned true belongs to that invocation's exact binding.

Main checks before recordOwnerIntent(startup), then passes check to the supervisor's existing guards before setup and spawn intent. Owner startup append changes registry revision; a prior proof cannot be reused. Repeat the bounded read inspection at the new revision. After every await, verify cancellation, exact owner nonce/kernel/root and source binding before a positive decision. Supervisor retains its resource revalidation and owner capture/record/init fences. No append/spawn/init follows a false result.

Shutdown closes inspection before owner release. A missing exact process exit leaves cleanup incomplete and the recovery path retained. App crash does not give an inspector original-store write authority: only its copied read program can continue, with parent disconnect cancelling and scoped close. No stale PID is killed and no persisted inspector identity is promoted to the owner Native-child record.

## Complete stopped file set

Bind database path to the existing verified manifest's namespace.data/event-host.sqlite. Require canonical actual uid-owned private directories mode0700, regular mode0600 single-link files and no symlink/path alias. Open originals O_RDONLY|O_NOFOLLOW and capture descriptor/path device, inode, mode, uid, nlink, size, mtime/ctime nanoseconds and full SHA256 before/after streamed reads. Access time is excluded because a normal read can change it.

Copy the main database and all present -wal/-shm/-journal companions together into an exclusive canonical private temporary directory disjoint from durable namespace/Documents/resources. Check absence of optional files before and after the entire copy. Limits: DB256MiB, WAL64MiB, SHM4MiB, journal64MiB, total388MiB. Copy exact bytes, flush copied files/directory and recheck the entire original descriptor/path/content set. No original SQLite connection, checkpoint, migration, truncate, rename, repair or recreate. A hot/unsupported copied rollback journal that readonly SQLite cannot open is held.

Config must be the supervisor-owned controlled empty opencode.json under the exact checked config directory. Reject unknown entries, nonempty/unsupported config, wrong permissions and path drift. Bind EVENT_HOST_CONFIG and current initialization feature flags. Check other namespace state relevant to the reviewed graph; unknown legacy state cannot be assumed inert. Bind registry epoch/revision, sorted active native/app/workspace/location mappings, exact retained set and resources, event-host resource inventory, Bun/server versions and inspector bytes. Repeat original/config/registry/owner/resource binding after inspector exit. Hash checks are bounded evidence, not an OS sandbox or proof against change-and-restore.

## Inspector construction and output

Stage an entry under the existing pinned event-host resource tree and include its bytes in preparation/build/package inventory. Use only that verified Bun1.4.2 and core/server2.0.18; never global Bun or installed Native. Environment is explicit and points HOME/config/data/state/cache/temp to the copied root, system PATH only, no credentials/config inheritance. Set MSGPACKR_NATIVE_ACCELERATION_DISABLED=true BEFORE importing dependencies. This disables the identified optional addon import path; it is not a claim that every transitive import is side-effect-free.

Receive a closed version1 request over private bounded stdin: invocation nonce, copied database path and expected mapping descriptions {appSessionId,nativeSessionId,workspaceId,canonicalPath,parentAppSessionId?}. The path must be inside the host-created copy; maximum request64KiB. Main writes exactly one newline-terminated request frame without ending stdin. The inspector keeps that pipe open until physical exit, rejects any later input, and treats EOF or pipe error as parent-loss cancellation. This is a lifetime signal, not an additional command channel; no IPC execution command is added. stdout is at most128KiB, one closed decision frame with matching version/nonce, boolean result, allowlisted reason, bounded counts and root correlation identities {nativeSessionId,appSessionId,workspaceId,runtimeEpoch,operationId,digest}. These are the closed admission keys/digests already stored by Main, not arbitrary metadata. No raw rows, transcript, credential/KV values, model text, native error or filesystem paths. Discard stderr; effect logging is disabled through a reviewed public logger composition. Reports/diagnostics expose counts/reasons only, not correlation identities.

Create sqliteLayer({filename:copy,readonly:true,readwrite:false,create:false,disableWAL:true}); official EffectDrizzleSqlite.makeWithDefaults produces a readonly query object. Supply Database.Service through a closed replacement or layer; NEVER acquire default Database.node dependencies. Root environment exposes only the services needed for direct read effects, not Native connection mutation APIs. V1Migration.status is an official read effect; never acquire V1Migration.layer or run it. Public schema imports and Drizzle prototype wrappers do not authorize services or effects beyond these reads.

## Raw global predicates and migration ledger

Use public @opencode/core/session/sql tables, @opencode/core/kv/sql KVTable and Drizzle explicit selection/limit. `.values()` preserves SQL NULL separately from JSON text "null" and bypasses automatic JSON mapping. Validate exact row length/order/runtime types before parsing any bounded JSON. Do not use truthiness as absence proof.

SessionTable: global, no filter/join/offset, limit201; reject more than200, duplicate/malformed IDs, any non-null parent_id including empty string, any non-null time_suspended/time_compacting, invalid/nonzero resume_attempts, malformed location/metadata/fork, or native ID set differing in either direction from committed mappings. Exact workspace canonical location and closed root metadata app/workspace identity must match input mappings. The inspector returns only the bounded root correlation identity above; Main uses registry.lookupIdentity plus the original confirmed create receipt to verify EXACT original digest/key/scope/result/native ID before check returns true. A root key must refer to the host-admitted create/import operation; no candidate identity is authority by itself.

Fork children are roots with fork_session_id and closed before/through messageID boundary. Require the exact input parent native ID, same workspace, existing valid parent boundary message and recursively inherited complete root metadata. Main additionally requires registry.lookupForkIdentity plus the exact original confirmed fork receipt/result/native ID for each child before true. This avoids needing a new registry root-enumeration API or trusting an inherited child metadata key as its own admission. Reject missing/cyclic/ambiguous lineage and JSON null/partial fork representations. Select known raw lifecycle and mapping columns; do not substitute SessionStore DTOs for those facts.

SessionPendingTable and SessionInboxTable: global id-only limit1, no session join. ANY returned row means pending, even invalid/NULL ID. KVTable: key-only limit1, any row denies; do not decode values or use filtered Job.pendingBackground. These queries cover orphan rows in the pinned known tables.

Migration compatibility: import public migration.gen definitions and inspect ONLY their id strings, never call their up functions. A closed Drizzle descriptor matching the official pinned native `migration(id TEXT PRIMARY KEY,time_completed INTEGER NOT NULL)` performs SELECT of those columns with limit49 for the exact48-entry pinned list. Require exact ID-set equality, unique expected IDs and positive safe completion timestamps; absent/extra/incomplete/unsupported ledger denies. No DDL, apply/applyOnly, legacy conversion or Global acquisition. This proves the next pinned schema migrator takes its already-completed skip branches; it does not prove arbitrary physical constraints/indexes or all stored data are intact. Missing required columns in the known read closure must fail, never become empty success.

Public V1Migration.status must return completed under the Bun condition; any legacy-required/running/error or failure denies. Its source uses official table existence reads; this is not PRAGMA user_version inference and is not a claim of zero internal Native introspection. A completed legacy marker in KV is conservatively unsupported because any KV row already denies.

## Transcript uncertainty and bounds

SessionMessageTable is globally read through public columns with limit10001, at most10000 rows; select raw id/session_id/type/data with `.values()`, reject orphan/malformed identity or duplicate per-session identifiers and invalid JSON. Each data value maximum1MiB and aggregate64MiB; exceeding the bounds denies. Like the official projector's decodeRow, reconstruct the schema input with {...parsedData,id:rowId,type:rowType}, because stored data normally omits those identity fields and fork copies use new row IDs. Decode through public @opencode/schema/session-message Info encoded schema. No transcript is returned outside this process.

Reject incomplete assistant time.completed, unfinished tool states/times, assistant retry state, running compaction, unfinished shell, malformed/unknown message types or incompatible row type/id. Do not infer completion from an app idle flag. Preserve valid historical terminal user/assistant/idle/compaction/shell messages without creating any Native event. These conservative predicates may hold otherwise legitimate older interrupted histories; do not silently normalize them.

Query construction covers the selected safety closure, not a full arbitrary schema checker. Native startup graph review must account for any additional durable work selector outside that closure before positive admission. If found, add its public bounded read or keep the hold; no success by omitting a known selector.

## Process lifecycle and failure

Attach owned ChildProcess listeners immediately, no shell; both Main and inspector enforce independent20s execution deadlines with bounded output. The child begins its own deadline and stdin EOF/error listeners before dependency imports or database acquisition. On parent loss, child deadline or malformed/extra input it aborts the same scoped read task, awaits connection finalization, then exits. Main keeps the stdin pipe open while the child lives and cancels by destroying that exact owned pipe before bounded exact-handle termination if needed; it never infers parent liveness from a reused PID. These paths require actual parent-exit/EOF/deadline tests during implementation. File/resource inspection is a tracked cancellable task; late completions cannot spawn or publish true. On timeout/crash/invalid frame/cancellation, stop only that exact child and wait bounded exit. Confirm scoped connection close and physical process exit before removing copied temporary root. Unconfirmed cleanup retains the root and blocks startup. Recheck original files on all settled failure paths; failure report has closed metadata only. No recursive cleanup of original/retained test namespaces.

## Acceptance and independent gates

N1: actual readonly copied-set inspection with original bytes/identity/permissions unchanged, exact owner/registry/resource binding and no mutation/service acquisition. N2: global root/child/empty-parent claims, pending/orphan inbox, pending rows, any malformed KV key/value, missing/extra ledger IDs, legacy-required, partial fork/transcript and bounds deny executor with preserved data. N3: actual separate zero-window normal/SIGKILL/fork reopens use production lifetime verifier AND production preflight, exact receipt/metadata/history correlation; trusted synthetic callbacks never count as positive. N4: crash/deadline/copy/config/registry/resource drift and late effects fail closed with exact cleanup evidence. N5: pinned official graph's no automatic pending recovery, schema-up, job drain, provider or credential operation during the accepted startup policy is independently reviewed; coherent source/build/package/native and final code evidence agree. Unsupported Windows/power-loss/private/provider configurations remain explicit.

Use one initial plan review and this applicable design review for the new boundary. After acceptance, ordinary source/test/provenance repairs use brief plan, edit, affected checks, a separate fresh code reviewer and integration. Main is sole ledger writer. Disjoint workers may own read-program/protocol versus host copied-set/callback after the actual API freezes; Main coordinates integration and probes. Final whole-P7 code/render judgments follow coherent source evidence. No self-approval, recursive delegation, release, signing or real private/provider invocation.
