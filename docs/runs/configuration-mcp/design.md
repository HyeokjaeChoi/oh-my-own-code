# MCP runtime controls - design v1

## Scope and ownership
MCP is workspace/location scoped. Connected tools/instructions can become available to every Native session in that directory, including future sessions. UI and immutable confirmation must name canonical workspace/path, source definition name and distinct app-reserved Native name. No selected-session isolation claim. App name is omoc-mcp- plus first40 hex of SHA256(JSON.stringify([workspaceId,sourceName])); sourceName uses existing validated file name grammar. Host derives it; renderer cannot supply arbitrary Native name.

Live ownership Map is keyed by canonical workspace identity and reserved name; contains current runtime epoch, source name, requested definition digest/sourceVersion and validated in-memory config. Only successful durable registration completion installs ownership. Journal stores no config/text/env/headers. Reopen/epoch/root/trust changes invalidate live authority. Old receipts are historical effects, not current Native config. If a current name exists without live authority, report ownership_conflict and prohibit replacement/connect/disconnect/remove. If absent after restart, user may explicitly register again from current saved file. Unknown retains resource hold and cannot be reissued with another key.

## Actual API and closed projection
Actual mcp.list returns {location:{directory},data:[{name,status,integrationID?}]}; add/remove/connect/disconnect return void. Verify exact canonical location, bounded<=300 rows, unique bounded safe names and closed statuses connected/pending/disabled/failed/needs_auth; unsupported/malformed projection becomes unavailable, no raw errors or integration IDs. New explicit read returns observation token covering current root/epoch/live ownership and bounded name/status catalogue. Do not claim digest of current Native config: SDK does not expose it. Requested definition digest is labeled as submitted data only.

Proposed public operations: configuration.mcp.read, .register, .connect, .disconnect, .remove. All carry workspaceId; actions target validated sourceName, host derives reserved name. Register also carries requestId,text,fileVersion and expectedObservationVersion; other mutations carry requestId and expectedObservationVersion but no executable payload. Exact DTO shapes frozen after initial entry. Existing v2 sender/envelope/operation ID/revision and current-read ID rules apply. Register binds exact UTF8/BOM supported loaded/saved opencode.json baseline and selected definition; no content copied into receipts. Public mutation result is a closed registered_disabled/connection_status/removed/unknown result with sourceName/nativeName and status if observed; no raw native response. A connect that finishes with observed failed/needs_auth is a confirmed attempt with that explicit status, never connected success. Receipt.effect describes whether SDK attempt/postcondition was confirmed; result status describes success/failure of connection. Timeout, malformed or mismatched post-read and completion failure remain unknown with no speculative result/ownership.

## Definition conversion and confirmation
Existing validator allows local command array/cwd and remote auth-free HTTP(S) URL, options disabled/codemode/protocol. No environment/header/credential fields. Registration always sends disabled:true; confirmation shows original desired disabled setting and explicit inactive registration. Local command is exact argv, no added shell. Resolve cwd against workspace root, require existing canonical directory inside that workspace and reject escapes/symlinks/outside-root runtime conversion; show complete argv and actual resolved directory in immutable confirmation. Remote registration requires explicitly present oauth:false; omitted oauth is supported as inert file content but unsupported runtime conversion, explained with external settings guidance. No auto rewriting of auth choice, browser/auth UI or secret fields. Native remote connections can recover/reconnect while connected; connect confirmation explains ongoing connection authority until disconnect and workspace-wide tool/instruction exposure. No real remote endpoint will be used in verification.

Host confirmation default denies. Registration, connect, disconnect and remove each require explicit confirmation of immutable target and action. Denial is no effect. Registration re-observes exact file baseline and Native catalogue before/after confirmation; other actions use current live host config/ownership and recheck catalogue. New session trust route remains existing session.create -> confirmTrust and its actual new-session effect; stored receipt does not imply trust/current Native config.

## Admission, effects and postconditions
Use existing global mutation actual-work lane and registry workspace scope. Workspace MCP mutation must refuse if any of its sessions is executing, has inbox/pending permissions, unresolved native mapping or matching resource hold; check canonical root/trust/generation/epoch and all-session baseline permissions/correlation around confirmation and SDK effects. No new send/command/fork in that workspace during pending actual mutation. Independent workspace reads remain available. All SDK mutations get exact flushed native.mcp.add/connect/disconnect/remove intent before call, bound to workspace and derived Native name. Preserve both existing send policy stages and all other feature checks.

After add require same reserved name observed disabled and no unexplained non-target catalogue change; after connect terminal connected/failed/needs_auth; after disconnect disabled; after remove absent. Re-observe policy/identity before durable completion. Own already-absent remove may close live ownership with a verified no-effect receipt and no SDK call, but never mutate foreign present state. Register duplicate current-live target is explicitly refused unless same original operation key lookup; definition replacement is remove then fresh explicit register, not silent add replacement. Native list is status observation, not full config verification/CAS. Catalogue baseline changes invalidate pending confirmations; asynchronous status drift is changed/unavailable rather than automatic retry.

## Durable compatibility
Add configuration_mcp_v1 marker before any new admission or dispatched effect. Existing journal/registry handle new closed identity/type/step/result combinations; bind workspace and Native name, allow only relevant step per operation, no session metadata or workspace configuration field. Other operation types cannot forge MCP results. Capture actual legacy parser dependency closure before implementation and verify marker/checkpoint unsupported_version without byte changes. Recovery never drains/replays pending operations. Original composite lookup survives; live authority expires on restart regardless receipt success.

## UI and state
MCP file editor retains inert edit/validate/preview/load/save behavior. Adjacent controls choose one supported source definition or current live owned registration, explicitly observe state, register inactive, connect, disconnect, remove. Show actual workspace scope, selected definition and Native name, supported/unsupported conversion reason, current Native connection status versus saved file and historical action receipt. Commands/cwd/URL shown only for explicit chosen supported definition/confirmation, never generic catalogue fields. Re-read required after confirmed action before another baseline-dependent action. No automatic registration/connect/remove on load/save/selection/refocus/start/reopen; existing read-only catalog behavior unchanged.

One renderer store owns immutable workspace/root/epoch/trust/floor/file/draft identity, generation and original operation handles. Late results update original action only, never a new workspace/draft. Unknown preserves editable draft/lookup-only original key and workspace-wide mutation hold. Buttons explain disabled reasons. Current-session unrelated content stays readable. Use current approved32desktop/44coarse/36permission/focus3:1/reflow tokens; keyboard activation/Escape and760/200% inspect all controls/status/next actions. No auth popup flow is added.

## Actual verification and limits
Node tests target real journal/registry/service/admission/controller modules; SDK mocks prove closed behavior only. Before full UI, actual pinned production owner/event-host/service probe runs contained synthetic stdio MCP with deterministic handshake and harmless tools, register-disabled zero starts, connect actual start/catalog, disconnect/remove actual exit, explicit reconnect and current-live collision/unknown/reopen behavior. Auth-free loopback remote fixture can verify failed/needs_auth projection if supported without external access. No provider/tool execution or real server credentials. Synthetic server records PID; parent attaches bounded macOS kqueue EVFILT_PROC NOTE_EXIT observer only after exact live OS birth identity verification and checks identity around attachment. Only actual kernel exit event proves this fixture child exited; no observeExit injection from polling or PID absence claim. Track exact observer parent exit separately. Test server has no spawned descendants; no arbitrary descendant or Windows exit proof. Attachment failure fails acceptance rather than weakening evidence.

Preserve synthetic namespaces and failed process evidence. Exact owned runtime/helper/observer exits before disposable cleanup. Build, hidden current states, keyboard/narrow200 and independent code/render gates follow coherent freeze. Existing owner-lifetime/native-preflight acceptance reused when bytes unchanged; no unrelated full restart matrix. Before/after hashes are not filesystem isolation. SDK status is not exact arbitrary child exit, full current config, authentication proof or model consumption. CAS/same-UID external mutation, physical devices, Windows, power-loss and real remote/provider behavior remain explicitly unverified.
