# Official source packet
Checked 2026-09-26 by coordinator using browser tool. Concise factual notes; architecture choices remain author judgment. These are documentation observations, not installed compatibility proof. Do not copy speculative version numbers from search summaries.

- Nx boundaries: https://nx.dev/docs/features/enforce-module-boundaries . Official ESLint rule @nx/enforce-module-boundaries supports tagged dependency constraints for TS/JS projects. Nx project boundaries alone do not enforce slices within a single Nx project. Avoid treating enterprise Conformance or experimental Oxlint boundary plugin as required.
- Nx Vite: https://nx.dev/docs/technologies/build-tools/vite/introduction . nx and @nx/vite must use matching versions. Plugin integration exists; exact Vite peer range needs registry/installed-manifest inspection at bootstrap.
- Nx task cache: https://nx.dev/docs/features/cache-task-results . Cacheable operations should be side-effect-free. Define exact inputs/outputs and exclude serve, models, permissions, destructive workspace commands, and stateful/live E2E from caching. This exclusion is our product decision.
- Nx cache security: https://nx.dev/docs/kb/cache-security . Local cache is trusted. Untrusted project content must never be given access to app build caches or build configuration. No cloud/remote cache subscription by default.
- Feature-Sliced layers: https://fsd.how/docs/reference/layers/ . Dependency flow is downward; distinct same-layer slices do not import each other. App/Shared have no domain-slice isolation rule. Public API: https://fsd.how/docs/reference/public-api/ . Public entrypoints encapsulate slices; deep imports bypass contracts. Apply FSD to renderer, not mechanically to bridge internals.
- TanStack Query: https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults . Cached query results are stale by default; background refetch occurs on mount/focus/reconnect. Default failed queries retry three times. Set explicit policy for this local app. Permission/mutation completion remains bridge-authoritative; never use HTTP retry defaults to replay side effects.
- Zustand: https://zustand.docs.pmnd.rs/learn/guides/initialize-state-with-props . Scoped dependency injection uses a vanilla store and React Context, consumed with useStore. Do not use removed legacy zustand/context APIs. Store lifetime and session isolation are application responsibilities.
- React: https://react.dev/learn/scaling-up-with-reducer-and-context . Reducer+Context can share state/actions through a subtree. Context is suitable for scoped ownership/injection; custom useX hooks alone do not share state between independent callers.
- Vite: https://vite.dev/guide/why.html . Current official architecture uses Rolldown/Oxc; do not describe current Vite as always esbuild+Rollup. https://v8.vite.dev/blog/announcing-vite8 confirms the v8 Rolldown transition. https://vite.dev/guide/ lists runtime constraints. Exact chosen stable version must match Nx, React plugin, tests and runtime in a pinned installation probe.
- shadcn monorepo: https://ui.shadcn.com/docs/monorepo . Workspace aliases route shared UI and package exports. Keep related components.json style/iconLibrary/baseColor aligned. Source-owned component installation is distinct from publishing a shared UI package.
- shadcn Base UI: https://ui.shadcn.com/docs/components/base/button and https://ui.shadcn.com/docs/components/base/drawer show maintained Base UI variants. Base UI: https://base-ui.com/react/overview/quick-start . Unstyled accessible primitives do not prove product keyboard/focus/a11y or assistant-ui/Tool UI compatibility.
- Existing product evidence: docs/research/sdk-ui-feasibility.md + spikes/sdk-ui/package.json. React19.2.4 / assistant-ui0.15.22 / new OpenCode SDK+client2.0.18 pinned only in isolated spike. Old assistant-ui opencode adapter uses another SDK generation. Actual tool-card dispatch, browser runtime, native host and safety remain unverified. Preserve separate assistant-ui interaction/runtime adapter and Tool UI card ownership.
