# Native multi-origin task correlation — focused DS-02 amendment r1

Status: PROPOSED. No implementation or positive execution authorization. This document changes ONLY the exact singular originalOperationKey lease/lineage boundary of accepted permission-control-design design-contract-r4 DS-02; all floor, compiler, physical broker, preflight, one-journal, actual process proof and recovery requirements remain. Existing terminal design files are immutable. Canonical helper run is terminal COMPLETE with independent CODE, but hashes are not authority.

## Actual problem and selected option
Pinned Native2.0.18 SessionInbox.promote(config-7stqpyhf.js) publishes multiple steers and can combine queued input with arrived steers. SessionRunner.drain(config-qs9wxzz9.js) repeats promotion/model steps within one existing coordinator Fiber. SessionExecution(config-y8cm73x9.js) continues same drain across moves/reloads. Current lease observer requires one actual Fiber owner and actual callback/await/process/IO proof. A first HTTP key is therefore not the origin of every consumed input. Required behavior preserves batching, steering, continuation and existing executor; it does not serialize each input into a new replacement executor.

Selected: one actual task/Fiber lease plus an opaque versioned execution scope containing EVERY admitted contributing original operation. Alternatives: refusing mixed inputs is a safe interim hold but loses required behavior; rerunning perinput changes steer/continuation semantics; multiple leases for sameFiber violate actual task ownership and doublecount settlement. No generic callback or executor injection is introduced.

## Exact private identities and limits
Origin = {runtimeEpoch,operationId,digest}; keys are ORIGINAL app epoch/op, digest is existing production admission digest INCLUDING expectedRevision. OriginalOperationKey remains canonical JSON.stringify([runtimeEpoch,operationId]) when indexing existing app records/holds. Never replace it with preview serializer or scope identity.

OriginBinding = {origin,workspaceId,appSessionId,nativeSessionId,projectId,locationIncarnation,modeGeneration,inventoryGeneration,inputDigest}. Every field required. IDs reuse existing private validation; digest fields64lowerhex; generations positive safe integers. inputDigest binds exact closed Native execution input (type/text/delivery/files or other explicitly supported method), not only prompt text. ScopeConstraint = {projectId,locationIncarnation,modeGeneration,inventoryGeneration}. Native store/app creation mapping and current generations are rechecked under project gates; record fields from renderer/session metadata alone are insufficient.

ScopeVersion = {executionScopeId,version,origins:Origin[],promotedInputs:{nativeSessionId,inboxId,originalOperationKey}[]}. ID unpredictable>=128bits graph-owned, version positive safe integer. Origin set sorted canonical original key; promoted pairs sorted [nativeSessionId,inboxId], each maps to exactly one listed original. Versions are detached/frozen, never rewritten or shrunk while actual work may exist. ScopeConstraint is immutable and privately bound to the scope. Operations sharing exact origin key but changed digest/binding are conflict, never updated.

Private lease row becomes exactly {runtimeEpoch,leaseId,executionScopeId,scopeVersion,projectId,locationIncarnation,sessionId,kind,modeGeneration,inventoryGeneration,state,parentLeaseId}. This replaces originalOperationKey ONLY in runtime lease row, not journal/receipts/boot-hold table. A parent child captures same executionScopeId and its parent's CURRENT immutable scopeVersion plus same scope constraints; changing parent version never expands existing child's snapshot. Existing kinds/states/bounds and actual handle validation remain. New children use current version; old livechildren remain tracked until actual settlement. Parent cannot settle while any child remains live/unverified.

Bounds: graph8192 original bindings, graph8192 scopes and graph8192 versions total lifetime, scope256 origins and1024 promoted input pairs,32 children/lease,8192 leases lifetime. No eviction/reuse. Overflow keeps affected project held, refuses before inbox publication/effects. Scope values must pass current1MiB detached canonical validation; no prompt/files/raw paths exported or retained in scope rows. The data-only input digest alone is retained.

## Private Main-to-Native admission and ordering
No new public renderer DTO or general RPC injection. Main alone constructs OriginBinding from actual currentScope().record after valid durable admission and flushed actual native.send/command/etc intent. Both before_selection and after_selection policy calls remain. Selected Native scope/generations/digests are authenticated and rechecked, never chosen by renderer. Fixed graph nonce authenticates transport only; request-body possession is not independently an admission proof. Main must actually validate the journal record and dispatch before its fixed client constructs this request.

Proposed fixed handler: registerAdmitted(OriginBinding) -> {admissionId}; submitPrompt({admissionId,input}) -> actual Native inbox response. admissionId unpredictable, graph-private one-use transport handle; not a bypass capability. Fixed handler creates a genuine SessionMessage.ID with existing generator, associates ID with detached admitted binding BEFORE Session.prompt({id,...}) can prepare, publish, revert, admit or wake. Input digest rechecked before consumption. Register/replay duplicate original key returns inert original status only; never another dispatchable handle. Once submit may have started, error/timeout preserves consumed/unknown hold; no retry or authority recreation. Other methods remain held until explicitly wired with their own exact inputs.

Actual graph Session/Inbox/coordinator gates require the registered binding, not only the new RPC facade. Public SDK prompt or native internal mutation with no binding stays denied. Short gate may validate/register; it is released before provider/Deferred/task wait. Actual generated inbox ID/payload/readback must match exact private binding. ACK proves admission only, not model/tool completion.

## Complete batch and actual task protocol
Coordinator cause and consumed input origins are distinct. Before coordinator started/cleanup effects, resolve its explicit admitted cause and the complete candidate pending batch under sorted project gates, then session/inbox lock, then DB transaction. Missing/foreign/stale binding refuses/holds BEFORE effects. No firstHTTP, arbitrary nextPromotable, wake nonce, last receipt or session creation metadata guess.

At EACH actual promotion, validate full chosen batch inside the same serialization region as publication. The later arrived-steer selection in promote must be checked too. Merge origins into a NEW immutable version and bind the actual task before the corresponding first effect. The batch cannot change between verification/publication; if complete atomic grouping cannot be established, hold and reject rather than publish partially as clean. Mode/inventory/project/location constraint mismatch is unverified; no automatic intersection broadening across changed generations or locations.

Execution constraints are the intersection of ALL contributing origins' admitted constraints and current authenticated floor. Because scope constraint is fixed, adding origins cannot widen it. Unknown/incomplete input, revoked generation, mixed project/location scope or unsupported input fails held. Any previously running child keeps its old snapshot; insertion of stricter/new-generation origin cannot retroactively authorize it, and is refused before promotion pending existing settlement/reconciliation. At each final tool/effect boundary, validate scope/version/current generations and existing floor/broker. No raw allow can override that gate.

Capture the ONE actual existing coordinator task inside its Fiber before effects, once; HTTP/RPC Fiber is not that task. Version advancement changes immutable attribution data, not task owner. No reuse/cloning of Fiber ownership, no new executor. Title/background/tool tasks obtain distinct real child leases before first effects. Direct shell/tool/transition tasks use the same scope model with one origin when no shared inputs exist. Move still holds both projects and follows accepted commit rules; this amendment does not authorize changing immutable scope constraint in place. A move requires explicit reviewed relocation to a new scope version/constraint protocol before activation; until then it remains held.

When same actual coordinator consumes later inputs, create another version and retain earlier contributing origins until actual task and children settle. Cancellation/revocation of any participating origin prevents NEW shared effects; do not remove that origin and continue under others. Existing Native cancellation APIs retain their actual selected inbox/request semantics; scope hold does not claim a new per-origin rollback or automatically interrupt unrelated work. Read/wait/cancel-intent stays usable, actual task/process settlement is still required. A cancellation requiring shared interruption must disclose existing scope before such an action is exposed.

Shared model/tool attribution is the exact participating origin set. Existing Native messages remain native history; no single app operation is falsely labelled sole producer of a shared result. Model input references to historical completed messages do not revive old operation authority: a new explicitly admitted execution cause authorizes current work under current constraints, while newly promoted live input contributions are tracked. Every resume/restart/pendingWake/continuation must carry exact still-live verified scope or a new explicit admitted cause; unknown historical mappings never authorize replay.

## Persistence, failures and staged implementation
Same existing app journal owns original identities/intents/receipts. Scope registry is bounded runtime bookkeeping, NOT a second durable permission DB or journal. Each contributing original must already have a flushed actual dispatch intent before Native publication. Internal scope binding cannot turn an unadmitted input into effect authority. Permission transition hold/activate continues exact permissionEffect ordinal/progress/completion contract. This amendment does not add or skip effect intents.

Original inbox ACK, app receipt, Native event or Fiber completion is not full settlement. Actual observer callback +Fiber.await +actualIO/process/children proof remains mandatory. Existing process slots remain incomplete until authoritative descendant proof is implemented; this document does not declare it solved. A shared uncertain task keeps EVERY participating original scope held; original unknown receipts never upgrade or replay. Reconciliation may release only after accepted full identity/state/actual prior-task proof and durable reconciliation generation, never from scope-table absence.

No scope/admissionId/token is restored as live authority after crash. Startup still starts boot_held only after accepted owner/exit/preflight/recovery ticket checks. Native pending inbox with missing original correlation is held, never drained. Read-only correlation uses existing original app journal receipts/nativeId and defensive identity. Scope empty/absent and missing Native mapping are not no-effect proof.

Staging: first implement private immutable origin/scope bookkeeping +adapt runtime leases/tests, with Control still alwaysheld. No Main/Native positive RPC wiring yet. Freeze actual API before consumers. Then wire fixed data-only Main/Native admission and complete real batch guards, instrument task children/lifecycle and actual source identities together. Native saved runtime invocation only after fresh preexecutionCODE, bundled with related closure tests rather than repeated micro-probes. Full modes/compiler/inventory/broker/journal/recovery/UI requirements stay unfinished; no productionMain/build/provider/private store launch.

Required evidence: original sameFiber mixedsteer/queue+steer behavior; missing binding beforeeffect; changed digest/scope duplicate; input substitution; complete atomic batch including arrivedsteers; frozen version/nooriginshrink; older child snapshot; late cancellation/generation/root changes; pendingWake/reload/move refusal; one actual capturedFiber; process/IO/child incomplete holds; flush/ACK/timeout/crash unknown no replay; independent-project isolation; preserved bothbaseline calls and legacy current request digest. PureNode bookkeeping tests do not prove Native integration. Design approval permits only scoped implementation, not execution readiness.
