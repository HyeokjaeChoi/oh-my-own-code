# oh-my-own-code — 개인 에이전트 워크벤치 PRD

**v0.6 · 2026-09-28 · macOS/Windows Electron desktop · review required**

This version preserves approved PRD scope and records the user's explicit selection of Electron for the installed macOS and Windows desktop app with an app-owned OpenCode v2 `serve` sidecar. Electron is a product decision, not evidence of packaged compatibility or runtime security. F-01–18, exclusions, and integrated scenarios remain unchanged. Earlier reviews are historical evidence; these amendments require fresh product and design-spec review. Text changes are not app implementation or verification.

## 1. 목적과 제품 경계

사용자는 본인 한 명이다. 목적은 일상적인 개발 작업을 직접 수행하면서 agent, model, instruction/skill, tool/MCP, permission, hook과 검증이 어떻게 연결되는지 이해하는 것이다. 문서나 CLI만으로도 가능한 작업을 통합 화면에서 다루고, 설정과 실제 실행의 차이를 확인한다. 시장 수요·사용성 향상·시간 절감은 아직 측정하지 않았다.

실행 엔진은 **새 OpenCode v2 세대**를 기준으로 한다. UI는 **assistant-ui + tool-ui를 함께 사용**한다. Claude/Codex/OpenCode 데스크톱의 공통 작업 흐름을 참고하되 특정 제품의 인증, 브랜드, 독점 클라우드나 벤더 전용 기능을 복제하지 않는다. 세 런타임을 모두 구동하는 멀티 백엔드 제품도 이번 범위가 아니다.

배포 형태는 **macOS와 Windows용 Electron 설치형 로컬 데스크톱 앱**이다. Electron main process가 창과 앱 소유 OpenCode v2 `serve` sidecar의 수명을 관리하며, renderer에는 임의 로컬 경로·셸·프로세스 권한이나 sidecar credential을 주지 않는다. Electron 선택은 SDK/서버 호환성, 플랫폼 패키징 또는 런타임 보안을 입증하지 않는다. 로컬 앱은 완전 오프라인을 뜻하지 않으며 기존 설정의 원격 모델·MCP를 사용할 수 있다. 개인용 unsigned 빌드는 범위에 포함하며 public distribution, store, signing/notarization, auto-update service는 별도 범위다.

출시 목표는 아래 F-01~F-18 전체다. 단계 구분은 구현 순서이며 명시된 기능을 후속 버전으로 밀어내는 MVP 축소가 아니다. 한 기능이 SDK에서 지원되지 않으면 앱 어댑터 또는 검증된 확장을 설계한다. 실행 불가능한 버튼이나 데모 데이터만으로 완료 처리하지 않는다. 범위를 바꿔야 하면 근거를 제시하고 사용자의 명시적 승인을 받는다.

## 2. 화면과 개념

기본 화면은 **왼쪽 프로젝트·작업 목록 / 중앙 대화·진행 상태 / 오른쪽 프리뷰·상세 패널**이다. 오른쪽은 브라우저, 파일, diff, 터미널, 계획, 서브에이전트, 실행 기록 탭을 제공하며 크기 변경·접기·복원과 작업별 위치 저장을 지원한다. 좁은 화면에서는 탭 전환으로 모든 필수 조작에 접근한다.

| 개념 | 사용자에게 보이는 의미 |
| --- | --- |
| 작업 루트 | 새 디렉터리를 자동 생성할 부모 경로. 최초 설정에서 선택·확인하며 앱 설치 폴더로 묵시적으로 대체하지 않는다. |
| 프로젝트 | 연결한 일반 폴더 또는 저장소. 표시 이름과 실제 절대 경로를 분리한다. |
| 워크트리 | 저장소의 별도 작업 사본. 일반 디렉터리를 Git 워크트리로 표시하지 않는다. 원본 저장소·브랜치·관리 주체를 함께 표시한다. |
| 작업/세션 | 대화, 실행, 선택한 작업 경로, 권한과 산출물의 묶음. 여러 세션이 같은 경로를 쓸 때 충돌 가능성을 표시한다. |
| 서브에이전트 | 부모가 범위와 입력을 주어 위임한 실행. 역할, 실제 컨텍스트 전달 방식, 경로, 상태, 결과를 추적한다. |
| 실행 기록 | 사용자가 한 요청에서 시작된 관측 가능한 사건. 설정 스냅샷·허용/거절·도구 결과·변경 파일과 연결한다. |

## 3. 출시 기능과 수용 기준

아래 AC는 구현 후 확인할 조건이다. 현재 통과 결과가 아니다. 상세 API·데이터 구조·테스트 케이스는 승인 후 스펙에서 정한다.

| ID | 기능 | 관찰 가능한 수용 기준 |
| --- | --- | --- |
| **F-01 / AC-01** | 프로젝트·워크트리 import | 폴더 선택 또는 경로 입력으로 기존 일반 폴더, Git 저장소, 기존 워크트리를 등록한다. 원본·브랜치·절대 경로·쓰기 가능 상태를 표시하고 중복 경로를 하나의 대상으로 식별한다. 없는 경로·깨진 worktree·접근 거절은 이유와 복구 동작을 제공한다. Import만으로 파일 이동, Git 초기화, 프로젝트 스크립트 실행을 하지 않는다. |
| **F-02 / AC-02** | 새 디렉터리·워크트리 생성 | 경로 지정 시 선택한 위치를 사용한다. 미지정 시 작업 루트 아래 새 자식 디렉터리를 자동 생성한다. 검증된 SDK 기본 네이밍을 우선하고 없으면 `yyyy-mm-dd-<uuid-v7>`을 사용한다. 일반 폴더 생성과 기존 저장소의 워크트리 생성을 구분한다. 결과 경로·브랜치를 확인하며 충돌·권한·설정 실패를 처리한다. 자세한 규칙은 4절. |
| **F-03 / AC-03** | 등록 해제·실제 삭제 | ‘목록에서 제거’, ‘대화 기록 삭제’, ‘워크트리/폴더 실제 삭제’를 별개 동작으로 제공한다. 실제 삭제는 대상 절대 경로·변경 사항·영향받는 세션을 보여주고 확인받는다. 활성 작업·터미널·dev server 또는 미커밋·untracked 변경이 있으면 일반 삭제를 막는다. 취소 시 데이터는 유지된다. 자세한 규칙은 4절. |
| **F-04 / AC-04** | 작업 관리·병렬 세션 | 생성, 이름 변경, 검색, 고정, 보관·복원, 삭제, 최근 작업 재열기와 읽지 않은 상태를 제공한다. 최소 두 세션을 다른 경로에서 동시에 실행하고 전환해도 입력·결과·승인 대상이 섞이지 않는다. 기록 분기와 빈 새 작업을 구분한다. 재시작 후 작업·경로 연결을 복원하고 사라진 경로는 명시한다. |
| **F-05 / AC-05** | 대화·컨텍스트 | assistant-ui 기반 스트리밍, Markdown/code, 첨부, 파일·선택 영역 참조, 복사, 재시도, 메시지 편집 후 분기, 실행 중 추가 지시/대기열, 중단을 제공한다. 첨부 크기·형식·경로 접근을 검증하고 전송할 컨텍스트를 확인할 수 있다. 모델 미지원 입력은 전송 전에 설명한다. 메시지 재시도가 도구 부작용을 자동 재실행하지 않는다. |
| **F-06 / AC-06** | agent·model·추론 옵션 | 현재 런타임이 제공하는 선택지와 실제 적용 값을 표시한다. 요청값·기본값·관측값이 다르면 구별한다. 모델/effort 미지원 값을 조용히 다른 값으로 바꾸지 않는다. 실행 중 변경은 적용될 다음 경계를 표시한다. 제품에 특정 모델 티어·역할별 고정 모델을 하드코딩하지 않는다. |
| **F-07 / AC-07** | 서브에이전트 호출·관찰 | 부모의 위임과 사용자 직접 위임을 지원한다. 역할·목표·입력/참조·소유 경로·검증 조건을 전달하고 부모-자식 트리에서 실행/대기/승인/실패/완료를 본다. 자식 기록 열기, 결과 회수, 개별/전체 중단, 동시성 한도와 대기열을 제공한다. 최소 두 독립 자식의 병렬 실행과 한 자식 실패를 검증한다. 기본은 필요한 자료만 주는 새 컨텍스트이며 history fork와 구분한다. 실제 격리 방식·권한 상속을 5절 기준으로 표시한다. |
| **F-08 / AC-08** | 도구 호출·Tool UI | 파일 읽기/검색/편집, 셸·테스트, 웹 조사, 연결된 MCP와 확장 도구를 같은 실행 흐름에서 지원한다. 이름·호출자·입력·진행·결과·오류·권한 상태를 볼 수 있다. tool-ui로 구조화된 결과, diff, 진행·선택·승인 카드를 렌더링하고 알 수 없는 도구는 안전한 일반 표시로 보존한다. 노출된 스키마가 있는 도구는 사용자가 인자를 확인해 직접 실행할 수 있다. 직접 호출에도 같은 권한·취소·기록 정책을 적용한다. |
| **F-09 / AC-09** | 권한 확인·모드 전환 | 기본 ‘요청마다 확인’, ‘범위 내 편집 허용’, ‘읽기/계획’, ‘사용자 정의’ 프리셋과 유효 규칙을 표시한다. 모드 변경, 요청별 허용·거절, 지원되는 제한적 기억, 저장 규칙 조회·취소를 제공한다. 단순 프롬프트가 아니라 실행 경계에서 적용되어야 한다. 5절의 실행 중 전환·자식·일괄 승인·만료·중복 응답 기준을 통과한다. |
| **F-10 / AC-10** | 우측 브라우저·산출물 프리뷰 | 로컬 dev server, URL, HTML/Markdown, 이미지/PDF 등 산출물을 탭으로 연다. 주소·로딩·실패·새로고침·앞뒤 이동·크기 조절·외부 브라우저 열기를 제공한다. 임베드 불가 사이트는 이유와 외부 열기를 제공하되 로컬 앱 프리뷰의 실제 동작을 대체하지 않는다. dev server 시작/중단·포트·로그를 작업과 연결한다. 프리뷰 콘텐츠에 로컬 실행 권한을 주지 않는다. |
| **F-11 / AC-11** | 파일·diff·Git 검토 | 파일 트리/검색, 텍스트 열기·수정·저장, 외부 변경 충돌, 변경 파일 목록, staged/unstaged/기준 브랜치 diff와 줄 단위 피드백을 지원한다. 선택 stage/unstage, 명시적 commit, branch 선택/생성, 변경 복원을 제공한다. 복원 전 대상과 손실을 확인하고 원본 저장소나 다른 worktree를 잘못 변경하지 않는다. 이 앱은 전체 IDE 언어 서버 대체를 목표로 하지 않는다. |
| **F-12 / AC-12** | 터미널·실행 액션 | 작업 디렉터리에 연결한 실제 터미널, 여러 탭, 입력·리사이즈·종료·종료 코드·출력을 지원한다. 프로젝트별 build/lint/test/dev 액션과 최근 실행을 제공한다. 사용자 직접 명령과 에이전트 명령의 주체·권한 경계를 명시한다. 탭을 닫는 것과 프로세스 중단을 구분하고 고아 프로세스를 확인한다. |
| **F-13 / AC-13** | 내장·슬래시·커맨드 팔레트 | `/` 입력으로 런타임 내장/프로젝트 커맨드·스킬과 앱 커맨드를 검색한다. 인자 도움말, 실행 대상, 출처, 사용 불가 이유를 제공한다. 런타임 목록과 실행을 실제 연동한다. 앱의 new/open/worktree/model/permissions/plan/review/compact/status/mcp/help에 해당하는 조작을 팔레트와 연결한다. 이름 충돌·인자 오류·busy·취소를 처리하며 슬래시 문자열을 임의 셸 명령으로 해석하지 않는다. |
| **F-14 / AC-14** | 하네스 구성 관리 | 프로젝트별 instructions/AGENTS, skills, agents, hooks, tools, MCP 및 플러그인의 위치·출처·활성 상태·적용 범위를 확인한다. 로컬 구성 편집·검증·미리보기·적용/재로딩과 MCP 등록·연결/해제를 제공한다. 설치/업데이트·프로세스 실행은 명시적 사용자 동작으로만 한다. 호환되지 않는 벤더 포맷은 그대로 실행하지 않고 변환 미지원으로 표시한다. 인증이 필요한 연결은 기존 외부 설정을 안내하며 인증 UI를 만들지 않는다. |
| **F-15 / AC-15** | 계획·작업 목록·리뷰 | 계획과 체크리스트를 대화 옆에서 보고 수정/승인/진행 확인한다. 승인 문서 버전과 실행을 연결한다. 구현자와 독립 리뷰어의 결과·미해결 지적을 구분하며 수정 후 재검증 상태를 표시한다. 에이전트의 ‘완료’ 주장만으로 lint/test/review 통과를 표시하지 않는다. |
| **F-16 / AC-16** | 기록·학습·사용량 | 시간순 타임라인을 세션/자식/tool/권한/검증별로 필터링하고 해당 결과로 이동한다. 제공되는 context/token/usage와 선택된 모델을 보여주되 미제공 값·추정 비용을 실제 청구로 표현하지 않는다. 설정 비교와 합성 학습 모드를 제공하며 실제 프로젝트 작업도 동일하게 관찰한다. 7절의 학습 평가와 기록 신뢰성 기준을 따른다. |
| **F-17 / AC-17** | 복구·로컬 데이터 | 연결 단절, 런타임 종료, 부분 실패, 재접속, 앱 재시작을 다룬다. 요청 중단과 실제 종료 확인을 구분한다. 새 이벤트 구독과 저장 상태 재조회를 수행하고 복구 불가능한 기록 구간을 표시한다. 세션·기록 export/import, 보존 설정과 앱 데이터 삭제를 제공한다. 삭제 범위와 외부 보존 한계를 설명한다. |
| **F-18 / AC-18** | 일상 작업 편의·로컬 자동화 | 키보드 팔레트·단축키 도움말, 테마·폰트/밀도·레이아웃 설정, 접근성, 완료/오류/승인 알림을 제공한다. 사용자가 등록한 로컬 반복 작업은 대상·주기·권한을 명시하고 일시정지·재개·기록을 제공한다. 앱/실행 서비스가 꺼진 동안의 미실행은 표시하고 임의 소급 실행하지 않는다. 민감 내용은 알림에 숨기며 OS 알림 미허용 시 앱 안에서 대기 상태를 유지한다. |

위 기능은 일반 작업 앱의 명시적 범위다. 음성·OS 전체 computer use·독점 이미지 생성 모델·모바일 리모트 제어·클라우드 작업·팀 협업·결제/마켓플레이스는 포함하지 않는다. 웹/브라우저 자동화는 연결된 범용 도구를 F-08에서 호출하고 관찰하는 범위이며, 독점 브라우저 확장 구현이나 사용자의 로그인 세션 탈취를 의미하지 않는다. 일반 Git remote 작업은 기존 환경의 CLI/도구로 가능하지만 GitHub 등의 로그인·PR 호스팅 전용 UI는 목표가 아니다.

## 4. 경로·생성·삭제 규칙

**Import:** 사용자가 지정한 폴더는 그 위치에 연결한다. 작업 루트 밖의 기존 프로젝트도 명시적으로 선택하여 등록할 수 있다. 경로 정규화와 실제 대상 확인으로 중복·심볼릭 링크·경로 이탈을 처리한다. 등록 자체는 읽기 중심 탐색이며 프로젝트의 신뢰되지 않은 plugin/setup을 자동 실행하지 않는다. SDK discovery가 실행을 수반하면 실행 없는 사전 검사와 신뢰 확인을 분리한다. 설정 파일이 있다는 사실은 실행 허가가 아니다.

**자동 생성:** 먼저 선택한 작업 루트를 사용한다. 루트가 없으면 최초 한 번 지정받는다. 새 폴더/워크트리 이름을 비워도 동작한다. 선택한 SDK 버전에 기본 생성 규칙이 있으면 그 규칙을 호출하며 구체적인 단어 조합을 앱에 추측해서 복제하지 않는다. SDK 규칙이 없는 일반 폴더 등에는 사용자 현지 날짜와 소문자 표준 UUIDv7 전체를 붙인다: `2026-09-26-<uuid-v7>`. 잘못된 UUID나 단순 임의 문자열로 대신하지 않는다. 날짜와 ID는 최초 생성 시 고정한다.

충돌 시 기존 폴더를 덮어쓰지 않는다. SDK 충돌 처리를 우선하며 fallback은 새 UUID를 생성하여 제한 횟수 내 재시도한다. 동시 생성은 배타적으로 확정한다. SDK 실행 실패·권한 거절·setup 실패는 ‘네이밍 규칙 없음’으로 간주하지 않으며 다른 전략으로 조용히 재실행하지 않는다. SDK가 다른 목적지를 반환할 수 있으므로 선택 전략의 경로 제약을 사전 검증한다. 허용 루트 밖 쓰기를 막을 수 없는 전략은 선택 불가로 표시하고 대안을 설계한다. 결과를 받은 뒤 경로만 검사하는 방식은 충분하지 않다.

워크트리는 소스 저장소, 시작 ref, 새 branch 여부를 표시하고 선택한다. ref 미지정 시 선택 소스의 HEAD에서 시작하는 제안을 생성 전에 보여준다. 기존 미커밋 내용과 ignored 파일은 기본 복사하지 않으며 별도 명시 선택과 결과 검증이 필요하다. 프로젝트 setup 명령은 실행 전 내용을 확인할 수 있어야 하고 허용 여부를 묻는다. setup 실패 시 폴더의 생성 성공과 준비 실패를 구분하며 무조건 지우지 않는다. 일반 폴더 생성은 Git 초기화 여부를 따로 선택한다.

**실제 삭제:** 저장소 원본 루트는 워크트리 삭제 대상으로 삼지 않는다. 앱에 등록한 일반 폴더도 실제 삭제할 수 있으나, import된 폴더임을 강조하고 절대 경로 재확인을 받는다. 홈·파일시스템 루트·상위 작업 루트와 중첩된 다른 프로젝트를 보호한다. 실행 중 작업/자식/터미널/server는 먼저 중단·종료 확인을 완료해야 한다. 다른 세션이 쓰는 경로는 삭제를 막는다. Git 상태는 확인 직후 바뀔 수 있으므로 실제 삭제 직전에 재검사하고 경쟁 쓰기를 차단한다.

기본은 비강제 삭제다. 미커밋/untracked 자료를 버리는 강제 삭제는 별도 경고·대상 경로 확인을 거쳐 선택하며 기본 체크하지 않는다. 선택한 전략의 제거 API를 쓰고 실패하면 임의 재귀 삭제로 바꾸지 않는다. branch 삭제는 별도 명시 동작이고 기본 유지한다. 보관이나 목록에서 제거는 디스크를 지우지 않는다. 물리 삭제 후 기록을 남긴 경우에는 ‘작업 경로 삭제됨’으로 읽기 전용 표시한다. 스냅샷/휴지통 복원이 구현·검증되지 않았다면 되돌릴 수 있다고 약속하지 않는다.

## 5. 권한·위임·도구 실행

권한 모드는 앱의 **명시적 규칙 묶음**이다. 벤더의 동명 모드를 흉내 내는 라벨만 만들지 않는다. 각 모드는 파일 읽기/쓰기, 셸, 네트워크/MCP, 허용 경로와 확인 조건을 보여준다. 기본 확인 모드에서도 인증된 시스템 정책의 거절을 사용자가 UI로 무력화하지 않는다. ‘읽기/계획’은 파일 쓰기·변경을 유발하는 셸/확장 호출을 차단해야 하며, 해당 실행 경계가 구현되지 않았다면 사용 가능으로 표시하지 않는다. OS 샌드박스와 도구 수준 정책은 따로 설명한다.

권한 요청 카드에는 호출자, 세션/자식, 작업, 대상 경로·도메인, 실행 명령/인자, 허용 지속 범위를 표시한다. 기본은 이번 요청에만 허용이다. 세션/패턴 기억은 런타임이 지원하고 범위를 정확히 표현할 때만 제공한다. 동일 요청의 중복 클릭·재접속 후 낡은 승인·이미 종료된 요청은 다시 실행하지 않는다. 결정이 저장·적용되었는지 확인한 뒤 완료 표시하며 오류 시 실패 이유를 남긴다. 일괄 승인도 각 대상과 범위를 확인하고 요청을 추가로 끼워 넣지 못하게 한다.

실행 중 모드 변경은 ‘변경 요청 → 대기/중단 확인 → 규칙 적용 확인 → 후속 실행’ 상태를 갖는다. 이미 수행된 쓰기는 소급 취소되지 않는다. 권한 축소 시 신규 호출을 보류하고, 진행 중 도구를 즉시 중단할 수 없는 경우 실제 상태와 위험을 보여준다. 기존 대기 요청은 새 정책으로 재평가하거나 취소 후 재요청하여 이전 승인으로 우회하지 못하게 한다. 권한 확대는 명시적 확인 후 적용한다. 전환 실패 시 이전 유효 정책을 유지하고 새 모드가 활성인 것처럼 표시하지 않는다.

새 자식은 위임 시점의 적용 가능한 권한·컨텍스트·모델 설정을 받는다. 부모 권한 확대가 기존 자식에게 자동 전파된다고 가정하지 않는다. 권한 축소는 활성 자식까지 범위를 선택·표시하여 보류/중단하고 각 적용 결과를 확인한다. 상위 거절과 자식 요청의 충돌은 안전하게 거절한다. 사용자나 정책이 허용하지 않은 재위임/자동 권한 확장은 금지한다. 동시성 한도는 실행 환경의 실제 용량과 사용자 설정 중 가능한 범위로 적용하고 초과 요청은 대기한다.

도구 결과·웹 페이지·저장소 텍스트는 권한 상승이나 실행 지시의 근거가 아니다. 모델이 렌더러 종류·권한·콜백을 임의 선택하지 못하도록 도구 이름과 검증된 스키마에 연결한다. UI에서 누른 action은 원래 세션·요청 ID와 묶어 실행 계층에서 재검증한다. 상태 표시용 카드, 사용자 질문, 실제 권한 승인을 구분한다. 취소가 불가능한 도구에는 그 한계를 표시하고 종료를 거짓 보고하지 않는다.

## 6. 기술 선택과 구현 전 확인

[현재 공식 문서 조사](../research/workbench-expansion.md)는 제공 API와 제한의 근거이며 구현 보증이 아니다. 패키지/commit·지원 플랫폼은 기술 스펙에서 고정한다. 오래된 조사와 충돌하면 새 고정 버전의 검증 결과로 결정한다.

| 영역 | 방향과 선행 검증 |
| --- | --- |
| 실행 엔진 | 앱이 소유하는 OpenCode v2 `serve` sidecar에 버전이 맞는 `@opencode/client`로 연결한다. 셸은 비교 후 사용자가 Electron을 선택했다(ADR-0002). 정확한 패키지 호환성과 플랫폼 런타임은 아직 검증하지 않았다. 기존 `@opencode-ai/sdk`의 `/v2`로 조용히 되돌리지 않는다. |
| assistant-ui | 대화·composer·thread·스트리밍의 표현과 상호작용을 맡긴다. 공식 OpenCode 어댑터가 새 SDK 세대에 맞는지 검증한다. 불일치하면 ExternalStoreRuntime 등으로 v2 상태 어댑터를 만든다. 중복된 실행 엔진이나 두 번째 모델 호출 루프를 만들지 않는다. |
| tool-ui | 승인/질문/진행/코드·diff/표·미디어 등 도구 결과를 실제 assistant-ui 렌더링 경로에 연결한다. 두 라이브러리의 버전·접근성·스타일·데이터 스키마·중단/재접속 상호작용을 검증한다. 설치만으로 도입 완료라고 하지 않는다. |
| 경로·worktree | SDK의 기본 이름, 부모 경로, 전략, import/discovery 부작용, setup, 제거와 dirty 상태를 실제 임시 저장소에서 확인한다. 전용 import API가 없으면 안전한 검증·등록 어댑터를 설계한다. |
| agent/tool/command | 빈 컨텍스트 위임, 자식 추적·취소, 직접 도구 호출과 권한, native command 목록·인자·실행을 검증한다. SDK API, plugin/RPC 확장, 앱 명령을 구별한다. TUI에서만 동작하는 명령은 가짜 SDK 호출로 연결하지 않는다. |
| 권한 | 실행 계층의 규칙 적용, deny, 사용자 거절, 기억 취소, 실행 중 변경, 낡은 응답, 자식 상속·축소를 부작용 관찰로 검증한다. UI 상태나 이벤트 부재만으로 차단을 증명하지 않는다. |
| 브라우저·로컬 bridge | localhost 연결 보호, origin 검증, 비밀을 노출하지 않는 로컬 접근 제어를 설계한다. 벤더 인증 UI 제외가 로컬 API 무방비 공개를 뜻하지 않는다. 프리뷰는 비신뢰 콘텐츠이며 bridge를 호출할 수 없어야 한다. |
| 기록·복구 | live-only 구독에서 누락된 이벤트를 과거 사실로 복원하지 않는다. 저장된 메시지·상태 재조회와 앱 기록으로 재동기화하되 확인 불가능한 구간은 표시한다. 중복 이벤트·부분 결과를 식별한다. |
| 운영·패키징 | 설치형 macOS/Windows 앱의 선택된 shell과 sidecar 시작/종료 책임, 알림·자동화 지속 조건, 데이터 위치·보존·마이그레이션을 확정한다. 창/업데이트/서명 요구사항은 사용자가 선택한 shell에 맞춰 승인된 플랫폼 스펙으로 구체화한다. |

SDK가 기본 지원하지 않는 필수 기능은 기술 spike에서 대안과 비용·위험을 평가한다. 미지원 상태를 보여주는 것은 개발 중의 정직한 상태 표현일 뿐 출시 수용 기준 충족이 아니다. 본 PRD에서 비용·일정을 추정 사실로 제시하지 않는다.

## 7. 검증·개인 성공 기준

**출시 판정:** AC-01~18 각각의 실제 실행 근거와 실패 경로를 확보하고 독립 제품/코드/디자인 검토에서 중대한 미해결 문제가 없어야 한다. 권한 우회·잘못된 경로 변경·데이터 유실·중복 부작용은 출시 차단 항목이다. 모든 아래 시나리오를 지원 환경에서 통과한다.

1. 이름·경로를 비운 신규 작업 → 올바른 루트와 이름 생성 → 대화 → 파일/도구 작업 → 결과 프리뷰 → 재시작 후 재열기.
2. 기존 저장소와 외부 worktree import → 새 worktree 두 개에서 병렬 세션 → 두 자식 위임 → 결과 회수 → diff/테스트/리뷰 → 명시적 commit.
3. 같은 파일 도구에 확인 후 허용, 사용자 거절, 정책 deny, 기억 취소를 각각 적용 → 실행 효과 확인. 실행 중 모드 축소·대기 승인·자식까지 검증.
4. 내장 명령 검색/인자 입력/실행과 앱 slash 명령 → 도구 rich UI/질문 응답 → 터미널/dev server → 우측 브라우저와 파일 프리뷰. 잘못된 인자·스키마도 확인.
5. dirty/untracked·활성 세션·경로 이탈·실패 전략에서 삭제 차단 → 명시적 종료/재확인 → 정상 삭제. 일반 폴더/원본 저장소/다른 세션의 자료 보존을 확인.
6. 연결 중단·프로세스 종료·앱 재시작·이중 승인 → 재연결과 상태 재조회 → 누락 표기. 이미 실행한 도구가 자동 재실행되지 않음을 확인.
7. 로컬 구성 변경과 MCP 연결/해제 → 실제 활성 상태 확인 → 계획/검증 결과 열기 → 기록 export/import·삭제 → 로컬 자동화 pause/resume·미실행 표시.

UI 통합은 실제 화면 E2E로, 정책·경로·재실행 방지는 임시 합성 저장소와 부작용 검사로 검증한다. lint/type/unit/integration/E2E와 hook 실행은 실제 명령·종료 코드·현재 소스 버전의 근거를 남긴다. 초록 체크 아이콘이나 에이전트 자기 보고는 검증 결과가 아니다. 접근성은 키보드만으로 위 핵심 흐름을 수행하고, focus 복원·스크린리더 상태 안내·대비·좁은 화면 조작을 검토한다.

**개인 활용 지표:** 사용자가 별도 CLI 조작 없이 시나리오 1~4의 정상 흐름을 완료하는 것을 목표로 한다. 소요 시간, 앱 밖으로 나간 이유, 잘못 이해한 상태, 복구 실패를 로컬에 기록한다. 아직 실측 기준선이 없으므로 시간 절감 비율을 출시 성과로 약속하지 않는다.

**학습 지표:** 합성 읽기 예제와 실제 위임 작업 각각에서 (1) 모델과 도구가 한 일, (2) 권한 적용의 실행 근거, (3) 부모·자식 컨텍스트/권한 관계, (4) 설정·요청·실제 관측의 차이를 설명한다. 각 4문항 중 3개 이상, 권한 근거 문항 필수 통과를 목표로 한다. 예측·답·근거·오답을 남기되 hidden chain-of-thought 복원이나 성능/캐시 보장을 요구하지 않는다. 실패하면 해당 설명·상태 표현을 고치며 사용자의 범위 승인 없이 제품 전체를 실험 뷰어로 축소하지 않는다.

## 8. 데이터·외부 연결·제외 사항

실제 프로젝트는 합성 자료와 다르다. 실행 전에 활성 provider/model, 선택 경로·첨부, 외부 호출 가능성을 확인할 수 있어야 한다. 원격 모델에 전송될 컨텍스트와 로컬 기록을 구분한다. API key/token·환경 변수 비밀·자격 증명 원문은 대화, 브라우저 bundle, 도구 카드, export, 로그에 넣지 않는다. 로컬 저장 위치·보존 기간·삭제 범위는 설정에서 보인다. 기록 내 민감 자료 최소화·마스킹·export 확인을 설계한다. 외부 telemetry/자동 업로드는 기본 사용하지 않는다.

로그인/OAuth·계정 관리·구독·결제·벤더별 rate-limit 대시보드·독점 클라우드 동기화·provider 전용 도구는 제외한다. 기존에 설정된 런타임/모델 자격 증명을 사용하며 없거나 만료됐으면 외부 설정 경로를 안내한다. 잘못된 자격 증명 때문에 실행 실패한 상태를 연결 성공으로 표시하지 않는다. 일반 MCP나 사용자 도구 지원은 포함하지만 모든 제3자 도구의 의미·안전·UI 전용 구현을 보장하지 않는다.

개인용 로컬 출시이며 팀/RBAC·멀티테넌트·상용 SLA·공개 호스팅을 추가하지 않는다. 공개 배포, 전송, 결제, 실제 프로젝트 삭제는 이 PRD 작성 요청으로 실행하지 않는다. 후속 제품이 그러한 동작을 지원하더라도 사용자의 구체적인 실행 의사를 따라야 한다.
